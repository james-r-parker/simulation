# Body temperature

**Status:** Implemented - body temperature is in the sim core with the tuned defaults (T10, experiments `E11` to `E18`); the bench check (T11) and the conformance review (T16) are still to do.
**Depends on:** [headless-sim-core.md](headless-sim-core.md), [evolution-evals.md](evolution-evals.md), [evolution-rework.md](evolution-rework.md)

An agent has a temperature from 0 to 100. Moving warms it, time cools it, eating warms it. An agent outside the 40 to 65
band pays up to twice the passive energy cost, and one outside the band also thrusts less; an agent past either
stress threshold cannot start a mating. A sitter cools, pays more and dies; a rusher overheats, pays more and slows; the
speed between lives. The brain senses its own temperature through four inputs.

The rules live in `js/sim/`. There is no new RNG stream and no new event. The brain layout changes, so every saved
genome, archive and champion from the earlier layout is rejected by the existing layout checks (`assertGenomeFits`,
`validateChampion` and the archive codec).

## Rules

### Temperature

`world.temperature` is a `Float32Array` with one element per slot. A new agent, whether spawned (`initial`, `floor`,
`immigrant`) or born (`mate`, `split`), starts at `temperatureStart`.

- **Gain.** `gainTemperature(world, slot, amount)` adds `amount` and caps at `temperatureMax`. `tryEat` in `feeding.js`
  calls it with `temperatureGainEat x stored / foodEnergy` for each food eaten, with `stored` the energy `addEnergy`
  returns; `applyBite` calls it with `temperatureGainEat x world.transferGained / foodEnergy` for the biter. A food of
  `foodEnergy` gives `temperatureGainEat`; a bite of `biteEnergy` 5 gives 0.1. The bitten agent gains nothing.
- **Tick.** `applyCosts` calls `stepTemperature(world, slot)` for each alive agent before it prices the tick; it reads `config.seasons[world.season[0]].temperatureModifier` directly and allocates nothing. With
  `speed = sqrt(vx x vx + vy x vy)` (the velocity left by `integrate` and `resolveContacts`) and `L` the season's loss
  multiplier `max(0, 1 - seasons[season].temperatureModifier x temperatureSeasonSlope)`: a warmer season cools an agent more slowly. At the defaults `L` is 1.15 in spring, 0.55 in summer, 0.85 in autumn and 1.45 in winter:

    `temperature += min(speed / maxVelocity, 1) x temperatureGainMove - temperatureLossPassive x L`

    then clamps to 0 to `temperatureMax`.

- **Passive cost.** `passiveMultiplier(config, t)` is 1 from `temperatureOptimalMin` to `temperatureOptimalMax`; below
  `temperatureOptimalMin` it is `1 + (temperatureOptimalMin - t) / temperatureOptimalMin x (temperaturePassiveLossFactor - 1)`,
  reaching `temperaturePassiveLossFactor` at 0; above `temperatureOptimalMax` it is
  `1 + (t - temperatureOptimalMax) / (temperatureMax - temperatureOptimalMax) x (temperaturePassiveLossFactor - 1)`,
  reaching `temperaturePassiveLossFactor` at `temperatureMax`. `tickCost` multiplies `passiveLoss + sizeEnergyLoss x size`
  by it, using the temperature after `stepTemperature`; the movement, turn and sprint terms are unchanged; the season's
  `energyDrain` multiplies the whole sum as before. The core has no resting state, so there is no resting discount.
- **Thrust.** `actAll` multiplies the thrust (sprint included) by `thrustEfficiency(config, t)`, read from the
  temperature at the end of the previous tick:

    | Temperature `t`                  | Efficiency                          |
    | -------------------------------- | ----------------------------------- |
    | below `temperatureColdStress`    | `temperatureEfficiencyColdSevere`   |
    | below `temperatureColdModerate`  | `temperatureEfficiencyColdModerate` |
    | up to `temperatureOptimalMax`    | 1                                   |
    | below `temperatureHeatStress`    | `temperatureEfficiencyHeatModerate` |
    | `temperatureHeatStress` or above | `temperatureEfficiencyHeatSevere`   |

- **Mating.** `isReadyToMate` is false when `t < temperatureColdStress` or `t > temperatureHeatStress`
  (`blocksMating`). The ready-to-mate input (offset 6), `readyToMate`, `canMatePair` and `findMate` follow it. `splitAll` is
  unchanged. No draw is made.
- **Equilibrium.** At a speed ratio `s` in a season with multiplier `L` the temperature changes by
  `0.01 s - 0.0075 L` per tick at the defaults. A sitter loses 0.008625 per tick in spring, 0.004125 in summer, 0.006375 in
  autumn and 0.010875 in winter; a full-speed agent gains 0.0025 per tick at `L` 1. Averaged over the year `L` is 1 and
  the temperature holds at an `s` of 0.75.

Cross-key rule: `0 < temperatureColdStress < temperatureColdModerate <= temperatureOptimalMax < temperatureHeatModerate <=
temperatureHeatStress < temperatureMax` and `temperatureColdStress < temperatureOptimalMin <= temperatureOptimalMax`. `SEASON_KEYS` in `config-validate.js` gains `temperatureModifier`, which
`checkSeasons` checks as a finite number rather than with `num(0)`. `TEMPERATURE_REPRODUCTION_SUPPRESSION_EXTREME` has
no key: the block is total. The Config defaults are set in T10.

## Cost

`stepTemperature`, `passiveMultiplier` and `thrustEfficiency` are a handful of comparisons and multiplies per alive
agent per tick, on arrays already in cache; `temperatureInputs` adds four stores to `writeBodyInputs`. The layout adds 4
of 147 inputs, so `forwardAll` grows by under 3%. `bench.step_ms@500` stays within `bench-check`'s 15% of
`bench/baseline.json`. Nothing is allocated per tick.
