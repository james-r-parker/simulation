# Training stages

**Status:** In progress - Phase 1 code built (T1 to T4, chunk A), T5 and T6 open; a gated ladder of stage worlds, cross-play between hunters and prey, an opponent pool, scene drills and one exam that says whether a champion set is good; Phase 1 (the detectors the ladder reads) is first.
**Validated:** f5ebac76 (2026-11-15)
**Priority:** 11 - the tools change no sim behaviour and no rule, so they build beside the world work; the runs that claim a skill wait for the held world, as [training.md](training.md) does
**Depends on:** [training.md](training.md), [senses-and-motor.md](senses-and-motor.md)

> Companion to [training.md](training.md), which holds the drills, the trainer, the curve and the export this doc extends. The survey behind it is [training-research.md](training-research.md).

A genome is trained by natural selection in whole worlds, as in [training.md](training.md). This doc changes how the worlds are ordered and how the result is judged. A stage is a world with one lesson. A stage ends when a gate of detectors says the lesson is learned, not on a generation count. Passed lessons are re-read at every checkpoint. Hunters and prey are read against each other's past, so an arms race is told from a cycle. An exam of ten rows says whether a champion set is good. Nothing here enters fitness, merit, mate rank or archive rank.

## Principle

- **A gate moves the world, never the score.** A gate decides when the next stage world starts. No offer, rank or birth reads a gate, a drill, a cross-play cell or an exam row ([principles.md](../principles.md), "Measure scenes, reward them almost never").
- **The curriculum changes the world, not the reward.** Every stage selects by survival and offspring under the live policy's fitness and proof rule.
- **Other blobs are the climate.** The lesson of a later stage is the other role's skill from an earlier one: prey evade hunters that hunt, hunters chase prey that evade.
- **A lesson counts when it is kept and inherited.** A passed gate that fails later is a finding. A champion whose descendants lose the skill has not learned it (selection rule 9).
- **Two customs survive export.** A champion set holds each specialisation's styles, not one best hunter ([principles.md](../principles.md), "Same spec, different custom").
- **One archive is a lead.** Every gate and exam verdict is read on 3 training-seed offsets and passes on at least 2.

- A stage whose name starts with `hunt`, `evade`, `arms-race`, `pack` or `habitat` runs hunters and has `minAgents` 0 (`validateStageFloors` in `js/evo/curriculum.js`, whose hunter-stage test T8 widens to these names).

The `hunt-life` extension and its dependency are specified under Release competence contracts.

## Gates

`js/evo/stage-gate.js` (new) exports `readGate(conditions, checkpoint)` and `gateState(history, conditions)`. Pure: no files, no clock.

| Part          | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Condition     | `{ "read": "<key>", "min": <n> }` or `{ "read": "<key>", "max": <n> }`. A key is a field of the checkpoint's gate readings: `drill.<name>.edgeLow`, `drill.<name>.winShareLow`, `drill.<name>.lossShare.<reason>`, `drill.<name>.winShareOverReference` (the win share's low bound over the `memoryless` reference's win share), `drill.pack-converge.gainLow`, `drill.pack-converge.blindGapLow`, `crossplay.hunterProgressLow`, `crossplay.preyProgressLow`, `crossplay.preyVsStage.<stage>`, `crossplay.cycleShare`, `retention.<stage>`, `retention.all` |
| Low bound     | A win share's low bound is `wilsonInterval` (`js/evo/binomial.js`) over the pooled trials of the champions the drill applies to. `edgeLow` is that low bound minus the high bound of the random brains' pooled win share. A gate checkpoint runs `GATE_TRIALS` (64) trials per champion and drill                                                                                                                                                                                                                                                            |
| Pass          | Every condition holds. A `null` reading fails                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Hold          | A stage is passed when its gate passes on `GATE_HOLD` (2) checkpoints in a row and `minGenerations` have run                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Stall         | A required stage that reaches `maxGenerations` without passing stops the run: `TrainStageStalled`, exit code 3, the archive and curve kept. An optional stage that stalls logs `TrainStageStalled` with `optional` true, and the next stage starts. No required stage is skipped                                                                                                                                                                                                                                                                             |
| Retention     | Every checkpoint after `minGenerations` of the current stage re-reads the gate of each passed stage (so a big world jump like `pack` to `habitat` has time for `TRAINER_N_CAP` sample turnover before triggering a review). `retention.<stage>` is 1 when it passes, 0 when not; `retention.all` is 1 when every passed stage's is. A passed gate that fails on 2 checkpoints in a row logs `TrainStageRegressed`                                                                                                                                            |
| Review        | After `TrainStageRegressed` the trainer runs `REVIEW_GENERATIONS` (5) generations on the regressed stage's world, then returns to the current stage. A stage reviewed `REVIEW_MAX` (3) times stops the run as a stall                                                                                                                                                                                                                                                                                                                                        |
| World metrics | The 4-seed checkpoint eval stays on the curve as columns. No gate condition reads an `eval.*` key: 4 seeds are under every metric's verdict count ([metrics.md](metrics.md))                                                                                                                                                                                                                                                                                                                                                                                 |
| Validity      | A gate is valid when the `memoryless` reference passes each of its drill conditions and the random brains fail each. T25 checks every gate of the ladder; an invalid condition is rewritten or dropped with a Decisions row                                                                                                                                                                                                                                                                                                                                  |
| Determinism   | Gate readings come from seeded drills and cross-play, so the stage plan of a run is a function of its seeds, curriculum and offset. `--workers 1` and `--workers 32` write identical archives                                                                                                                                                                                                                                                                                                                                                                |

A curriculum entry gains `minGenerations`, `maxGenerations`, `gate`, `pool` and `checkpointEvery`. An entry with `generations` and no `gate` is a fixed-length stage, as today, so `evals/train-curriculum*.json` load unchanged. `planStages` lays out fixed stages; `nextStage(state, checkpoint)` in `js/evo/curriculum.js` (new) advances a gated run. The archive's `stages` record gains `passedAt`, `reviews` and the gate readings at the pass.

> Note: an elite keeps its samples when the stage world changes. Clone founders re-test it in the new world (`nextClone` in `js/evo/archive.js`) and `TRAINER_N_CAP` (8) bounds how long old samples weigh, so a lower bound drifts to the new world over a few generations. A gate read in the first checkpoint of a stage reads the old stage's elites.

## Cross-play

`js/evo/crossplay.js` (new) plays a predator genome against a forager genome in the staged arena of the `prey-ahead` drill, both driven by their brains. `playTrial` in `js/evo/memory-probe-run.js` gains an optional `opponent` (`Subject`) that drives the `prey` or `hunter` role in place of a controller.

| Part            | Rule                                                                                                                                                                                                                                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Players         | Each checkpoint's champions: its predators and its foragers (one per specialisation until T20, one per style band after it)                                                                                                                                                                                   |
| Cell            | `kill[i][j]`: the share of `CROSS_TRIALS` (64) trials in which checkpoint `i`'s predators kill checkpoint `j`'s foragers, on the same seeded plans (`fork(createRng(seed), 'crossplay')`) for every cell                                                                                                      |
| Hunter progress | The latest predators' mean kill share over all earlier forager columns, minus the first predators' mean over the same columns. `hunterProgressLow` is the latest mean's Wilson low bound minus the first mean's high bound, over the pooled trials                                                            |
| Prey progress   | The first foragers' mean kill share suffered over all earlier predator rows, minus the latest foragers' mean over the same rows, with `preyProgressLow` built the same way. `preyVsStage.<stage>` is the same difference against the hunters of the pool snapshot taken when `<stage>` passed, as a low bound |
| Cycle share     | Of the pairs of adjacent checkpoints, the share in which the newer side does worse than the older side against the other role's pooled past by more than 0.1                                                                                                                                                  |
| Group cell      | `packKill[i][j]`: as `kill`, with three sibling clones of the predator and a prey one bite cannot kill (the staging of `js/evo/memory-probe-group.js`)                                                                                                                                                        |
| Output          | `npm run train:crossplay -- <dir>` (`scripts/train-crossplay.mjs`) writes `<dir>/crossplay.json` and prints the matrix and the three numbers. The trainer computes the latest row and column at each checkpoint of a stage whose gate reads `crossplay.*`                                                     |

## Opponent pool

`js/evo/opponent-pool.js` (new) keeps frozen archive snapshots (`snapshotArchive` in `js/evo/archive-snapshot.js`): one at each stage pass and one every `POOL_EVERY` (2) checkpoints, at most `POOL_MAX` (8), the stage-pass snapshots kept longest.

- In a stage with `pool` share `p`, each founder and floor entrant is drawn with probability `p` from a pool snapshot (uniform over snapshots) as an unmutated clone of an elite of the seeder's chosen specialisation, and otherwise from the frozen current archive as today. `createMapElitesV1` takes `opponents: { snapshots, share }`; `createSeeder` in `js/evo/policies/map-elites-seed.js` draws from `fork(rng, 'opponent-pool')`, so a share of 0 draws nothing and writes the archive it writes today.
- A pool founder is an opponent, not a candidate: the trainer drops an offer whose genome id is a pool founder's of that episode, so a genome the archive has replaced does not return through the pool (selection rule 1). Its children are new genomes born in this world, and their deaths are offered like any other.
- The pool is trainer state: it never reaches a champion file or the live world.

## Scene drills

Four drills join `DRILLS`, in `js/evo/drill-scenarios-social.js` (new, the shape of `js/evo/drill-scenarios.js`).

| Drill           | Scene                 | Subject  | Stage                                                                                                                                                                                  | Won when                                                    | Max ticks |
| --------------- | --------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- | --------- |
| `prey-crossing` | A real chase          | predator | One forager driven by `COMBAT_CONTROLLERS.fleer` at 0.6 of view, moving across the subject's heading (60 to 120 degrees off it)                                                        | the subject kills it                                        | 900       |
| `hunter-flank`  | A real chase          | forager  | One predator driven by `COMBAT_CONTROLLERS.hunter`, 500 px away, 90 to 150 degrees off the subject's heading                                                                           | the subject is alive at the end                             | 600       |

| `pack-converge` | Pack, or loner        | predator | Three sibling clones of the subject and one prey one bite cannot kill (`huntPlan` of `js/evo/memory-probe-group.js`, exported), with the `solo` and `kin-blind` controls of that probe | the prey dies                                               | 600       |

`pack-converge` reports three win shares and its gain: the trio's share minus the solo share, with `gainLow` from the two Wilson bounds. A trio that does no better than `kin-blind` hunts side by side, not together.

## Export by style

`exportBestPerStyle` in `js/evo/champion-export.js` (new) replaces `exportBestPerSpec` as the export of `train:export` and the checkpoint. For each specialisation it takes the tested elite with the highest lower bound in each of `STYLE_BANDS` (2) halves of the style axis of `descriptorV7` (`js/evo/descriptors.js`): for a hunter, short chases and long ones. A band with no tested elite gives no champion. A champion file gains `style` (`low` or `high`); `validateChampion` in `js/evo/league.js` accepts and ignores it. `exportBestPerSpec`, `bestElitePerSpec` and their uses are replaced in the same task.

## The exam

A row is `pass`, `fail`, `reported` (no bar) or `not run`. Rows 1 to 5, 8 and 9 need no target world. Rows 6, 7 and 10 need the world gate.

## Release competence contracts

These additions extend the existing ladder and exam; their reasoning is in [training-research.md](training-research.md#release-competence-review). They add no fitness, merit or mating reward. Recruitment instrumentation comes from [honest-budgets.md](honest-budgets.md) Phase 6; reuse it rather than adding a second lineage ledger.

### A complete hunter life

Insert required `hunt-life` between `hunt` and `evade`, with 10 to 60 generations and the existing two-checkpoint hold. Its world uses target birth, maturity, diet and energy rules, no floor or reseeding, and enough space for unsuccessful searches as well as encounters. Initial adults receive the normal founder budget; offspring receive only the normal parental gift. Charge all failed pursuit, bite, movement and maintenance costs. No kill, birth or juvenile ration is scripted.

The gate uses a dedicated seeded life-cycle evaluation, not the four-seed checkpoint eval columns. Register its readings alongside the existing gate keys and test null and insufficient-family cases as failures. The gate reports the share of founder families with a deliberate hunter kill, a birth and a child reaching maturity, plus net hunting income and juvenile failure causes. T25a fixes the observation horizon, family denominator, minimum independent episodes and pass threshold before the first ladder run, using competent and incompetent controls. No calibrated threshold means the gate is invalid, not passed. A required stage that stalls stops normally. This stage and dependent ladder runs wait for the recruitment diagnostics and a viable world budget; tool implementation can proceed earlier. Two descendant generations are required by the release exam, not by this introductory stage.

### Training, validation and sealed release worlds

T10a assigns disjoint seed namespaces and scenario manifests to training, checkpoint validation and release. Checkpoint gates, reviews and curriculum tuning read validation only. Release seeds and scenarios never select a checkpoint or offset. Freeze the candidate set, founder mixture, code, rules hash and curriculum hash before opening the release exam. A failed exam remains in the record; a revised candidate uses a new, precommitted release partition. Log every partition use, including resume, and refuse overlap. Do not claim that a repeatedly inspected exam remains held out.

Validation and release vary headings, spacing, food placement, density and starting seasonal phase within a declared target-world envelope. They do not change physical rules to manufacture success. Record exact seeds and scenario hashes for replay. Use paired worlds for comparisons; report uncertainty across independent world seeds and training runs, not just pooled trials from related clones. Two checkpoint passes are an advancement rule, not independent replication evidence.

### Inheritance follows families

Exam row 7 uses traced descendants of the released founders, not archive elites as a substitute. Track parentage through mating, splitting and role changes using stable identities; mixed ancestry is explicit and never counted twice in aggregate totals. Report all founder families, including those with no children, extinct lines and children still immature at the observation boundary. A fixed-seed sample of ordinary children and grandchildren supplies the descendant drills; best descendants are a separate diagnostic. Reset recurrent and temporary learned state through the normal newborn path before each drill.

For each drill, each descendant generation must have a win share at least half the founders' share and a low bound above the random brains' high bound, applied separately to children and grandchildren. It additionally requires evidence of descendant reproduction without rescue and the predeclared family-replacement bar from T23a. Missing descendants cannot pass through a smaller surviving denominator. Run for at least two complete seasonal cycles; unfinished generations are censored and cannot establish a pass. Report ordinary-descendant results, extinction and reproductive replacement together. Do not pool offsets to hide a failed run.

### Opponents and exported populations

Keep the simple forager `prey-ahead` cross-play matrix as a diagnostic. Add a release matrix across every prey specialisation, juvenile and mature bodies, cover, sparse encounters and depleted patches. Opponents include independently trained runs excluded from the candidate's training pool. Record outcomes per guild and condition, including failed pursuit cost. Hunters need viable opportunities in the mixed world; beating every defended prey is not a requirement.

The two style bands generate export candidates, not proof of two strategies. Exam row 8 also requires repeatable behavioural separation in matched scenes and viable descendant recruitment for both hunter styles. A short chase with no catch is not an ambush. Compare styles alone and in the intended release mixture, with matched total starting population and energy. Freeze founder counts, age distribution, spatial arrangement and kin assignment in the release manifest. Test the exact exported mixture under row 6; abundance of one style cannot conceal extinction of the other. No role quota or replacement injection maintains diversity.

### Stage-local archive evidence

T9a compares retained bounded samples with stage-local estimates on matched training seeds. Both arms carry the same genomes; the fresh-estimate arm preserves old observations for diagnostics but excludes their scores from current-stage ranking until re-evaluated. Record candidate turnover, retention, sample cost and later gate outcomes. Choose the scoring rule on validation data before release evaluation. Irrespective of that choice, an export candidate needs recorded evaluation under the target rules; an easy-stage score alone cannot qualify it. Stage and rules identifiers survive snapshots and resume, and worker counts produce identical results.

## Runs are kept

- A run writes to `.sim/train/<name>/` (git-ignored): `archive-<g>.json`, `curve.jsonl`, `train.jsonl`, `crossplay.json`, `exam.json` and `manifest.json` (the git sha, the command line, the curriculum file's hash, the seed offset, each stage's `rulesHash`, `passedAt` and gate readings).
- `scripts/train.mjs` refuses an `--out` under `/tmp` unless `--scratch` is given.
- A run a decision rests on is committed under `evals/decisions/<id>/`: the last archive, the curve, the cross-play matrix, the exam and the manifest.

## Season retraining

A rules change voids every champion file (`rulesHash`). `npm run train:season -- --out .sim/train/<season>` (`scripts/train-season.mjs`) runs the ladder on offsets 0, 64 and 128, then cross-play, the exam rows that need no world, and the export of offset 0 when it passes rows 3 and 4, else of the lowest offset that does; when a required stage stalls on 2 of 3 offsets it exports nothing and exits 3. It prints the wall time. Rows 6, 7 and 10 are run by hand after it.

## Detectors

All computed by the eval observer; none is a reward. The findings they answer are in [training-research.md](training-research.md), Metric audit.

| Metric                         | Direction      | Reads                                                                                                                                                                                                   |
| ------------------------------ | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `eval.chase_quit_share`        | watch (higher) | Of resolved chases, those that lapse while the prey is still on the hunter's rays and the range is not growing: the hunter stopped closing                                                              |
| `eval.chase_lost_share`        | watch          | Of resolved chases, those that lapse after the prey left the hunter's rays                                                                                                                              |
| `eval.chase_outrun_share`      | watch          | Of resolved chases, those that lapse with the prey on the rays and the range growing                                                                                                                    |
| `eval.chase_shaken_share`      | watch (higher) | `eval.chase_lost_share` plus `eval.chase_outrun_share` plus `eval.chase_escape_share`: the prey's side of every chase                                                                                   |
| `eval.chase_ticks_p50`, `_p90` | watch (higher) | Ticks from the opening of a chase to its resolution                                                                                                                                                     |
| `eval.pack_lift`               | higher         | Pack kills over the count expected if each kill's previous biter were drawn by the lineages' shares of all bites in the run; null under 30 paired kills (hunter kills whose previous biter is a hunter) |
| `eval.pack_prey_size_ratio`    | watch (higher) | Mean victim size at pack kills over mean victim size at solo kills; null under 10 of either                                                                                                             |
| `eval.style_lineage_share`     | higher         | Within a specialisation, the share of the variance of style at death that lies between lineages (lineages with `MIN_STYLE_DEATHS` deaths), averaged over specialisations                                |
| `eval.hunter_zero_kill_share`  | watch (lower)  | Changed: hunter lives after burn-in, lives alive at the last tick included at their end age                                                                                                             |
| `eval.escape_share`            | watch          | Changed: direction `watch`                                                                                                                                                                              |
| `eval.herd_dodge_share`        | watch (higher) | Renamed from `eval.dodge_skill`                                                                                                                                                                         |

As built: a lapse is the `GAVE_UP` end class of the chase record, split by the flags `LAPSE_LOST` (prey off the rays at the lapse tick) and `LAPSE_OUTRUN` (prey on the rays and its ray proximity fell by `RANGE_GROWS` since the hunter last closed); a lapse with neither is a quit. `eval.pack_lift` counts the paired kills in place of the eaten deaths the first draft named, since a solo kill has no previous biter to draw. `eval.hunter_zero_kill_share` counts living hunters at the last tick with their ledger kills so far, whatever their age. The drill rows carry `winShareLow` and `edgeLow` (the low bound of the win share minus the high bound of the pooled random brains' share); the reflex report prints each case's pass share with its Wilson bounds.

`eval.chase_giveup_share` and `eval.hunt_abort_rate` stay; the three lapse shares (quit, lost, outrun) partition the lapses and sum to `eval.chase_giveup_share`. Curves and reports written before T3 hold the old `eval.hunter_zero_kill_share`; the manifest's git sha tells them apart.

## Decisions

| Decision                                                                                                                                                                        | Why                                                                                                                                                                                                                                                 | Who                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| A gate reads drills and cross-play, never a 4-seed world metric                                                                                                                 | Every world metric needs 16 to 64 seeds for a verdict; a drill's trial count is set, so its interval is known                                                                                                                                       | Delegated (planning, 2026-11-15) |
| A gate is a stop rule on the world, like `findPlateau`; it is not a filter on offers                                                                                            | A filter on a detector score breeds drill-passers (selection rule 9); a gate changes which world runs next and nothing about who breeds in it                                                                                                       | Delegated (planning, 2026-11-15) |
| A stalled stage stops the run                                                                                                                                                   | A later stage built on an unlearned lesson is what T12 produced; a stall is the finding                                                                                                                                                             | Delegated (planning, 2026-11-15) |
| A regressed lesson is reviewed in its own world, and no generation mixes stage worlds                                                                                           | One world per generation keeps the merge order and the archives byte-identical; a review block is the same trainer loop                                                                                                                             | Delegated (planning, 2026-11-15) |
| A pool founder's own death is not offered; its children's are                                                                                                                   | Selection rule 1: a genome the archive replaced does not come back through the pool. Its children are mutated genomes that lived and proved themselves in this world, so they are offered; dropping them would need lineage tracking through births | Delegated (planning, 2026-11-15) |
| Scripted sparring partners in a stage world are not built                                                                                                                       | The trainer starts from random brains and no scripted behaviour reaches the archive (user, 2026-10-17); slowed prey is the world's own lever. Reopened only by the user if `hunt-contact` stalls on 2 of 3 offsets                                  | User, 2026-10-17; planner        |
| Refused: a pack term, a gate score or a cross-play number in fitness, merit, mate rank, archive rank or an offer filter                                                         | Pays an act and a score (selection rules 7 and 9)                                                                                                                                                                                                   | Planner, from principles.md      |
| The league stays a reported row                                                                                                                                                 | A league game is won on headcount after 50000 ticks; it reads a lineage's growth, and `eval.champion_elo` is deprecated in the registry                                                                                                             | Delegated (planning, 2026-11-15) |
| Export is by style band, and `exportBestPerSpec` is deleted                                                                                                                     | One champion a specialisation deletes the courser or the ambusher at the last step, after the archive kept both                                                                                                                                     | Delegated (planning, 2026-11-15) |
| The first ladder run happens before the world holds, and claims nothing about the target world                                                                                  | It tests the gates, the pool and the exam on rules that will change; a stage arena is not the default world, so the crash that froze the skill runs (review of 2026-11-11, H2) does not decide a gate                                               | Delegated (planning, 2026-11-15) |
| [training.md](training.md) T23 to T25 (arms e to g) run on the gated trainer; arm g's `hunt-slow` stage and `hunt-contact` are one stage file, `evals/stages/hunt-contact.json` | One stage file and one way of ending a stage                                                                                                                                                                                                        | Delegated (planning, 2026-11-15) |
| The fixed `generations` form of a curriculum entry stays                                                                                                                        | [training.md](training.md) T30 replicates arms a to c on `evals/train-curriculum-iter2-*.json`; it is a stage with no gate, not a second code path                                                                                                  | Delegated (planning, 2026-11-15) |
