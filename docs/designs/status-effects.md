> Companion to [body-genes.md](body-genes.md), whose lanes are what a body is for its whole life. This doc owns what changes within a life: an effect multiplies a lane, or closes a gate, for as long as it lasts.

A lane is constant for a life. A body is also cold, tired, full, hurt, sick, in a pack that has just called, or pressed against its kin, and each of those changes what it can do for a while. Today each is a rule of its own in a different file. Here each is one entry of a registry: what puts it on a body, how many times it stacks, how it fades, and which lanes it scales. The readers of a lane read the lane with its effects applied, and nothing else in the sim multiplies a lane.

Scenes served: **Pack, or loner**, **Call, or don't**, **Condition changes the walk**, **Refuge** (the huddle) and the trait **Needs conflict in the same tick** ([principles.md](../principles.md)). Selection rules 7 and 8 bound every social effect: the payoff returns to the actor's offspring, and a cheater must not win.

## The registry (`js/sim/effects.js`)

`EFFECTS` is a frozen list, in `js/sim/effect-list.js`; `js/sim/effects.js` holds the engine that is built from any list (`createEffects`, so the contract test runs it on fixture effects) and the readers bound to `EFFECTS`. `EFFECT_INDEX` (by name), `EFFECT` (by name in `UPPER_SNAKE`) and the per-slot state are built from the list.

| Field       | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`      | the effect's name: the key of its config numbers, of its inspector row, and of its detector                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `family`    | `body` (a state of the body), `feeding`, `social` or `combat`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `maxStacks` | the cap; a stack past it is dropped. 1 for an effect that is on or off                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `level`     | `stacks` (a whole count an applier raises, at most `maxStacks`), `share` (a number from 0 to 1 computed from the body when it is read, such as how full its store is), or `step` (0, 1 or 2 computed from the body when it is read, such as a temperature band)                                                                                                                                                                                                                                                                                                  |
| `fades`     | for a `stacks` effect: `ticks` (all stacks end when the effect's timer does; a new stack restarts it) or `every` (one stack leaves every `n` ticks). A `share` or `step` effect, and an effect whose clock is a timer the sim already keeps (`ateTimer`, `restTimer`, the call timers, the smoke cooldown, the pregnancy timer), stores nothing: its level is read from that state                                                                                                                                                                               |
| `scales`    | a list of `{lane, perStack}` (the lane is multiplied by `1 + perStack x level`, never below 0) or `{lane, levels}` (the lane is multiplied by `levels[level]`, for a `step` effect whose factors are not in a line); `perStack` and each entry of `levels` is a number, a config key or a lane, or `{key, scale, offset}` for `scale x value + offset` (a drag of `-fatSlowShare`, a ramp of `temperaturePassiveLossFactor - 1`); the lanes are named as in [body-genes.md](body-genes.md); an optional `by` names a lane of the body that multiplies `perStack` |
| `gates`     | a list of the gates the effect closes while its level is above 0: `eat`, `mate`, `split`, `bite`, `alarm`, `hunt`, `smoke`                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `drains`    | a list of `{perTick, cause}`: energy removed each tick the effect is on, `perTick x level`, booked under the `LOSS_CAUSE` named; for a rule that takes a flat amount, not a share of a cost                                                                                                                                                                                                                                                                                                                                                                      |
| `applier`   | the name of the rule that puts it on a body (below)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `visible`   | whether the renderer and the inspector show it                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

Only a `stacks` effect stores anything: `effectStacks[effect][slot]` and `effectTicks[effect][slot]`, both `Float64Array` rows of `world.agentRows`, so they are hashed, saved and zeroed by `freeAgent` with the rest of an agent's state.

### How a lane is read

`liveOf(world, slot, LANE.X) = world.lanes.X[slot] x the factor of every effect that scales X, in registry order`.

- An effect is evaluated where it is read, from the state as it stands at that point of the tick. A `share` or `step` level is computed then; a `stacks` level is the stored count. This is what keeps today's order: grazing reads this tick's `BITE` output, the passive cost reads the temperature after `stepTemperature`, the fat factor reads the energy after the call costs, and a meal closes the `eat` gate within the same `feed`.
- A gate is read with `gateOpen(world, slot, GATE.EAT)`, which is closed when any effect that names it has a level above 0, read the same way.
- `fadeEffects(world)` is the one pass over stored stacks: it runs as the last entry of `STEP_PHASES` in `js/sim/step.js`, counts each `ticks` timer down and drops a stack of each `every` effect on its tick. A stack gained in tick `t` with `ticks: n` is on through tick `t + n - 1`.
- A reader that takes `liveOf` reads its lane; a reader this doc touches is moved from the config key to its lane in the same commit and the lane is marked `moved` ([body-genes.md](body-genes.md), "The lane catalogue"), so Phase 5 there moves what is left.
- Nothing allocates and nothing draws from the RNG. Factors multiply in registry order, so a world replays bit for bit.

### Appliers (`js/sim/effect-appliers.js`)

A `stacks` effect is raised by `applyEffect(world, slot, EFFECT.X, source)`, called at the site where the cause happens, in the phase it happens in: where a call is heard (`hearOne` in `js/sim/calls.js`), where a bite lands (`js/sim/feeding.js`), where a defender shoves (`tryDefenderRepel`). It adds one stack up to `maxStacks`, restarts a `ticks` timer, and pushes `EffectApplied`. Two effects are raised on a clock instead: `chilled` (in `stepTemperature`) and `huddled` (a pass over the spatial hash every 8 ticks, in slot order, in the signal phase).

### What the body feels

A brain already reads its energy, its temperature bands, `ate`, `bitten`, `pregnant` and what it hears. One body input is added with the layout of [body-genes.md](body-genes.md) Phase 1: `reserve`, the sprint store's level, so a brain can pace a graded sprint. No effect adds another input.

## Every modifier of today, as an effect (Phase 1)

As built, the factors multiply on the lane in registry order, so thrust, turn and the standing cost round differently from the old sequence: the `busy` short golden and the busy and bouncy wasm physics digests moved (the default, disease and sprint-store short goldens did not) and were re-pinned with that commit. A call is two gates, not one, because an alarm and a hunt call each wait on their own timer.

## The social effects (Phase 2)

Each is built with its numbers at 0 (no effect) and switched on by Phase 3, which chooses the numbers with the calculator and reads them under the keep rule. Each row states where its payoff returns and what stops a cheater, as selection rules 7 and 8 require. Kin is `isKin` in `js/sim/kin.js` (a parent, a child or a sibling); T12 reads how often a hunter has kin in call range, and the pack is widened to the lineage only if that share is under 0.1.

Hearing gains an owner: `hearOne` in `js/sim/calls.js` keeps the loudest call's loudness and bearing today; it also keeps the caller's slot and genome id (`world.heardFrom`), and a hearer gains a stack once per call, on the tick it first hears it, not on each tick the call lasts.

## The calculator and the levels

- [role-budget.md](role-budget.md) reads effects through `roleParams(config, specName, traits, effects)`: a level per effect, composed as `liveOf` composes it. The defender's row reads `staggered`, the scout's row `alert`, the sitter's row `chilled`, and a new row `pack:forager` reads two hunters, one rallied, against one alone and prints `packGain`, the catch margin a rally adds.
- [brain-reflex-tests.md](brain-reflex-tests.md) Phase 5 holds `answer-the-call` (its T21a): a hunter with a kin's hunt call heard from a bearing and no prey in view turns to the bearing.

| A factor is never below 0                                      | The old `fatFactor` could go below 0 only for a `fatSlowShare` lane of 1 or more (the config key is under 1, but a trait or a body override can lift the lane), which would reverse a body's thrust; `1 + perStack x level` is clamped at 0 for every effect, and a test pins the case                                                                                     |

| Three forms: a factor on a lane, a table of factors, a drain   | A ramp, a band table and a flat energy loss are what the sim has; one form cannot keep all three numbers the same                                                                                                                                                                                                                                                          |
| Social numbers start at 0 and are chosen with the calculator   | An effect's strength is a balance question; the mechanism lands first so the calculator and the detectors can read it                                                                                                                                                                                                                                                      |
| The effects are built before any training                      | Each changes what a trained brain must learn; one retraining follows all of them (user, 2026-11-21)                                                                                                                                                                                                                                                                        |
| Effects amplify, the defaults carry the job (user, 2026-11-21) | Every role's job works at the defaults with every effect off ([role-budget.md](role-budget.md) gates its rows that way). The social and adrenaline effects, for example a defender that answers an alarm moving faster, are margin for teamwork once it takes off. Phase 3 sizes each effect as a margin above a row that is already green, never to turn a red row green. |
