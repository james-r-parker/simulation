## Build queue (12)

Unbuilt docs in priority order - 1 is built next. Set in each doc's `**Priority:**` line; the evolution loop proposes re-ranks.

1. [Natural selection](natural-selection.md) - the default world fails the principles (spinning, a scout monoculture, lucky lives that breed, dead genomes that return), and one big-bang build with every change on by default avoids flags, dual paths and a re-pin per tuning round (user, 2026-10-29)
2. [Flora](flora.md) - flora phases in order, ahead of the paused natural-selection balancing work (user, 2026-10-31)
3. [Megafauna](megafauna.md) - built after flora (Priority 2), which it extends: it reads flora's patch weights, per-item lifetimes, fertile-zone fungus and seeding path (user, 2026-10-30)
4. [Fitness and selection](fitness-and-selection.md) - after natural-selection.md (Priority 1), which closes this plan's Phase 4 when its T19 moves the status lines; the worlds sit in a scout monoculture where behaviour stops improving, and every later tuning night, the trainer and the champions measure a fitness this doc replaces
5. [Brain capacity and memory](brain-capacity-and-memory.md) - measurement before redesign: a brain experiment judged by `fitnessV1` measures the wrong thing, so it queues after natural-selection.md (Priority 1), which closes fitness-and-selection.md Phase 4 (user, 2026-10-29)
6. [World balance and biology](world-balance.md) - the post-feature balance round follows flora and megafauna; the current rank is unchanged
7. [Quality gates and test tiers](quality-gates-and-test-tiers.md) - Phase 3 (PR perf job, CPU lock in check.sh, busy-aware bench-check) protects every other lane while several agents share the machine (manager, 2026-10-17)
8. [Worker and renderer](worker-and-renderer.md) - comes before the trainer so world tuning can be judged by watching it, not only by scorecards (user, 2026-10-16)
9. [Evolution rework](evolution-rework.md) - its Phase 3, the trainer, bakes the world into champions, so it waits for the world gate below: predator-prey.md, the renderer and world-balance.md
10. [Improvement loop](improvement-loop.md) - automates measuring and proposing once the evolution rework and the renderer give it something worth tuning
11. [v6 tidy-up and docs](v6-tidy-up-and-docs.md) - the last stage of v6: nothing legacy is left and every doc describes the app as built
12. [Deployment and community](deployment-and-community.md) - the last stage: put v6 online, then open it to the community (user, 2026-10-16)
