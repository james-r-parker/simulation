# Brain inspection

**Status:** Proposed - Phase 1 (the dossier: labelled weights, drill traces and unit ablation) is built first; Phase 2 adds the `inspect-brain` skill and the first inspection of trained champions.
**Validated:** 2dd6b77 (2026-11-04)
**Priority:** 14 - last in the queue (user, 2026-11-04): a diagnostic for champions that fail a drill, useful only once the drills and the trainer exist
**Depends on:** [training.md](training.md)

A champion that fails a drill gets a **dossier**: its weights labelled unit by unit, the hidden state and outputs of its brain tick by tick through the drill's trials, and the win share with each hidden unit silenced. An agent reads the dossier, names the unit or input path that blocks the skill, and tests that claim with an in-memory edit replayed on the same trials. The dossier is a detector: nothing in it enters fitness, merit, mate rank or archive rank ([principles.md](../principles.md), Measure scenes, reward them almost never), and an edited brain never leaves the process that tests it.

## Labels

`js/evo/brain-labels.js` (new) names every position in a weight row from `brainLayout` and `inputOffsets` in [brain-layout.js](../../js/sim/brain-layout.js).

| Function              | Returns                                                                                                                                                                                                                                                                                                                    |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `inputLabels(config)` | One name per pooled-row input: `<channel>.hit<k>.<strength\|cos\|sin>` for each of `POOLED_CHANNELS`, `food.hue<k>`, the `BODY_INPUT` names (`bitten`, `scent`, `hunt_scent`, `heard_alarm`, `heard_hunt`, `sex`, `memory_a`, `memory_b`) with their antenna or side suffix, and `body.<i>` for the rest of the body block |
| `outputLabels()`      | One name per gene output, in `GENE_OUTPUTS` order, from `OUTPUT_INDEX` (`thrust`, `turn`, `sprint`, `mate`, `bite`, `alarm`, `smoke`, `hunt`, `memory_a`, `memory_b`)                                                                                                                                                      |
| `unitLabel(j)`        | `h<j>`                                                                                                                                                                                                                                                                                                                     |

## Dossier

`js/evo/brain-dossier.js` (new) builds the weight view; it is pure and reads one `Float32Array` weight row.

- **`unitTable(weights, layout, labels, { top })`** returns one row per hidden unit: its leak gene, its bias, its `top` (default 8) largest-magnitude incoming weights from `wIn` and from `wRec`, and every outgoing weight to the gene outputs from `wOut`, each with its label and value.
- **`skipTable(weights, layout, labels, { top })`** returns, per gene output, its bias and the `top` largest-magnitude `wSkip` weights (the reflex path that bypasses the hidden layer).
- **`traitRow(weights, layout)`** returns the four trait genes by `TRAIT_INDEX` name.

`js/evo/brain-trace.js` (new) records one subject through one trial.

- `playTrial` in [memory-probe-run.js](../../js/evo/memory-probe-run.js) gains an optional `onTick(world, slots)` called after each `step`; existing callers pass none and behave as today.
- **`createTraceRecorder({ maxTicks })`** preallocates typed arrays for the subject slot's pooled row, hidden row and output row per tick, plus its position, heading and energy, and returns `onTick` and `finish()`. `finish()` returns the filled ticks, the trial's result and the ticks to the result.
- **`traceSummary(trace, labels)`** returns, per hidden unit, its mean, its range and the tick of its largest change; per output, the share of ticks it fires (above 0); and the inputs that are ever nonzero.

`js/evo/brain-edit.js` (new) applies edits to a copy of a weight row.

| Edit                                        | Effect on the copy                                                     |
| ------------------------------------------- | ---------------------------------------------------------------------- |
| `{ op: 'silence', unit }`                   | Zeroes unit `unit`'s outgoing weights in `wOut` and in `wRec`          |
| `{ op: 'set', block, row, col, value }`     | Sets one weight of `wIn`, `wRec`, `wOut`, `wSkip`, `bHidden` or `bOut` |
| `{ op: 'scale', block, row, col?, factor }` | Multiplies one weight, or a whole row when `col` is omitted            |

- **`applyEdits(weights, layout, edits)`** returns a new row; the input row is unchanged. An index outside its block throws `RangeError` naming the edit.

`js/evo/brain-ablation.js` (new) runs **`ablateUnits({ subject, drill, seed, trials, config })`**: the drill's trials once intact and once per hidden unit with that unit silenced, returning the win share for each and its change from intact.

## Command

`npm run inspect -- --champion <file> --drill <name> --out <dir>` (`scripts/inspect-brain.mjs`, new; `--seed <n>` (1), `--trials <n>` (32), `--trace-trials <n>` (4), `--top <n>` (8), `--edit <edits.json>`, `--config <file.json>`, `--workers <n>`):

- The champion loads through `loadChampions` in [memory-probe.mjs](../../scripts/memory-probe.mjs); a layout mismatch exits 1 with its `probe.layout` log.
- The drill comes from `DRILLS` in `js/evo/drill-scenarios.js` ([training.md](training.md) Phase 1) and its trials from the same `drill:<name>` stream as `npm run drill`, so the dossier explains the same trials the drill table scored.
- `<dir>` receives `weights.md` (the unit, skip and trait tables), `trace-<trial>.jsonl` for the first `--trace-trials` trials (one line per tick: labelled nonzero inputs, hidden row, outputs, position, heading, energy), `summary.md` (the `traceSummary` tables, each traced trial's result) and `ablation.md` (win share intact and per silenced unit, sorted by change).
- `--edit <edits.json>` takes a list of edits, applies them with `applyEdits`, reruns the same trials and adds `edit.md`: the edits, win share before and after, and the change. The edited row is never written to a file.
- Ablation trials run on [worker-pool.mjs](../../scripts/lib/worker-pool.mjs) in index order, so `--workers 1` and `--workers 8` write the same files.

## Skill

`.claude/skills/inspect-brain/SKILL.md` (new, Phase 2) is the procedure an agent follows: run `npm run drill` to pick a failing champion and drill, run `npm run inspect`, read `ablation.md` before `weights.md`, state one claim naming units, inputs or outputs, test it with `--edit`, and report the claim with the edit's win-share change. A claim whose edit does not move the win share outside the drill's trial noise (one trial in `--trials`) is reported as unconfirmed. Findings go into [sim-notes.md](sim-notes.md) under `## Learned while building`; an edit never goes into a genome, a champion file or the archive.

## Phases

### Phase 1 - Dossier

**Targets:** none - a diagnostic tool; it changes no genome, rule or default

Labels, the weight tables, the trace recorder with the `onTick` hook, edits, ablation and `npm run inspect`. Done when `npm run inspect -- --champion <file> --drill food-ahead --out .sim/inspect/check` writes the four files for a champion exported by `npm run train:export`, and `--edit` with a `silence` edit writes `edit.md`.

### Phase 2 - Skill and first inspection

**Targets:** none - its output is a finding in sim-notes.md, not a metric

The `inspect-brain` skill and its first use on the champions of training.md Phase 2's done run: one inspection per drill with an edge at or below 0, each claim recorded with its edit and win-share change.
