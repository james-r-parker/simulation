# Brain inspection

**Status:** Proposed - Phase 1 (the dossier: labelled weights, drill traces and unit ablation) is built first; Phase 2 adds the `inspect-brain` skill and the first inspection of trained champions.
**Validated:** d6ca3e6c (2026-11-07)
**Priority:** 18 - last in the queue (user, 2026-11-04): a diagnostic for champions that fail a drill, useful only once the drills and the trainer exist
**Depends on:** [training.md](training.md)

A champion that fails a drill gets a **dossier**: its weights labelled unit by unit, the hidden state and outputs of its brain tick by tick through the drill's trials, and the win share with each hidden unit silenced. An agent reads the dossier, names the unit or input path that blocks the skill, and tests that claim with an in-memory edit replayed on the same trials. The dossier is a detector: nothing in it enters fitness, merit, mate rank or archive rank ([principles.md](../principles.md), Measure scenes, reward them almost never), and an edited brain never leaves the process that tests it.

## Dossier

`js/evo/brain-dossier.js` (new) builds the weight view; it is pure and reads one `Float32Array` weight row. It shows the genome's weights; with `hebbianRate` above 0 the hidden-to-output weights in use are the agent's `fastOut` copy, which starts equal to them at birth and drifts during the trial.

- **`unitTable(weights, layout, labels, { top })`** returns one row per hidden unit: its leak gene, its bias, its `top` (default 8) largest-magnitude incoming weights from `wIn` and from `wRec`, and every outgoing weight to the gene outputs from `wOut`, each with its label and value.
- **`skipTable(weights, layout, labels, { top })`** returns, per gene output, its bias and the `top` largest-magnitude `wSkip` weights (the reflex path that bypasses the hidden layer).
- **`traitRow(weights, layout)`** returns the four trait genes by `TRAIT_INDEX` name.

`js/evo/brain-trace.js` (new) records one subject through one trial.

- `playTrial` in [memory-probe-run.js](../../js/evo/memory-probe-run.js) gains an optional `onTick(world, slots, tick)` called after each `step`; its return value stays a boolean, and existing callers pass none and behave as today.
- **`createTraceRecorder({ maxTicks })`** preallocates typed arrays for the subject slot's pooled row, hidden row and output row per tick, plus its position, heading, energy and `alive` flag, and returns `onTick` and `finish(won)`. Ticks after the subject dies record `alive` 0 and zeros. `finish(won)` returns the filled ticks, `won`, and the tick count, which is the tick `plan.done` ended the trial or `plan.maxTicks`.
- **`traceSummary(trace, labels)`** returns, per hidden unit, its mean, its range and the tick of its largest change; per output, the share of alive ticks it fires (above 0); and the inputs that are ever nonzero.

`js/evo/brain-edit.js` (new) applies edits to a copy of a weight row. A block's `row` and `col` follow its storage order:

| Block     | `row`                       | `col`                                            |
| --------- | --------------------------- | ------------------------------------------------ |
| `wIn`     | input (`inputLabels` index) | hidden unit                                      |
| `wRec`    | from-unit                   | to-unit                                          |
| `wOut`    | hidden unit                 | gene output column (`GENE_OUTPUTS` index)        |
| `wSkip`   | pooled input (0 to 55)      | gene output column                               |
| `bHidden` | -                           | hidden unit                                      |
| `bOut`    | -                           | gene output column                               |
| `leak`    | -                           | hidden unit (the leak gene at `leakStart + col`) |
| `trait`   | -                           | `TRAIT_INDEX` value                              |

| Edit                                        | Effect on the copy                                                                     |
| ------------------------------------------- | -------------------------------------------------------------------------------------- |
| `{ op: 'silence', unit }`                   | Zeroes row `unit` of `wOut` and of `wRec`: every weight that carries the unit's output |
| `{ op: 'set', block, row?, col, value }`    | Sets one gene                                                                          |
| `{ op: 'scale', block, row, col?, factor }` | Multiplies one gene, or a whole row of a two-dimensional block when `col` is omitted   |

- **`applyEdits(weights, layout, edits)`** returns a new row; the input row is unchanged. An unknown block, a missing `row` on a two-dimensional block or an index outside its block throws `RangeError` naming the edit.
- **`silenceHook(units)`** returns an `onTick` that zeroes the silenced units' rows of the subject slot's `fastOut` after every step.

> Note: `resetFastOut` copies the edited `wOut` at birth, but `hebbianStep` moves `fastOut` away from 0 every tick while `hebbianRate` is above 0, so a `silence` edit alone leaks the unit back into the outputs. Every run with a `silence` edit chains `silenceHook` with the trace recorder's `onTick`.

`js/evo/brain-ablation.js` (new):

- **`ablateUnit({ subject, drill, unit, seed, trials, config })`** runs the drill's trials with one unit silenced (unit `null` runs them intact) through `drillSubject` in `js/evo/drill.js` ([training.md](training.md) Phase 1), and returns each trial's result.
- **`compareTrials(before, after)`** returns both win shares, the change, the paired trials that flip each way, and the exact two-sided McNemar p value on those flips (`mcnemarP`).

## Command

`npm run inspect -- --champions <dir> --name <champion> --drill <name> --out <dir>` (`scripts/inspect-brain.mjs` and `scripts/inspect-worker.mjs`, new; `--seed <n>` (1), `--trials <n>` (32), `--trace-trials <n>` (4), `--top <n>` (8), `--edit <edits.json>`, `--config <file.json>`, `--workers <n>`):

- Champions load through `loadChampions` in [memory-probe.mjs](../../scripts/memory-probe.mjs); a layout mismatch exits 1 with its `probe.layout` log. `--name` picks one champion by its `name`; it is optional when the directory holds one champion, and an unknown name exits 1 listing the names.
- The drill comes from `DRILLS` in `js/evo/drill-scenarios.js` ([training.md](training.md) Phase 1). Its trials draw from the `drill:<name>` stream, so they equal the trials `npm run drill` plays for the same seed and trial count.
- `<dir>` receives `weights.md` (the unit, skip and trait tables), `trace-<trial>.jsonl` for the first `--trace-trials` trials (one line per tick: labelled nonzero inputs, hidden row, outputs, position, heading, energy, alive), `summary.md` (the `traceSummary` tables, each traced trial's result) and `ablation.md` (one row per hidden unit, `brainHidden` (32 by default): win share intact and silenced, the change, the flips and `mcnemarP`, sorted by change).
- `--edit <edits.json>` takes a list of edits, applies them with `applyEdits`, reruns the same trials and adds `edit.md`: the edits and the `compareTrials` row against intact. The edited row is never written to a file.
- The intact run and each unit's ablation are one task each on `runPool` in [worker-pool.mjs](../../scripts/lib/worker-pool.mjs); `scripts/inspect-worker.mjs` serves them with `serveTasks`. Results are merged in task order, so `--workers 1` and `--workers 8` write the same files.

## Skill

`.claude/skills/inspect-brain/SKILL.md` (new, Phase 2) is the procedure an agent follows: run `npm run drill` to pick a failing champion and drill, run `npm run inspect`, read `ablation.md` before `weights.md`, state one claim naming units, inputs or outputs, test it with `--edit`, and report the claim with the edit's `compareTrials` row. A claim is confirmed when its edit moves the win share in the claimed direction with `mcnemarP` below 0.05; otherwise it is reported as unconfirmed. Findings go into [sim-notes.md](sim-notes.md) under `## Learned while building`; an edit never goes into a genome, a champion file or the archive.

## Decisions

| Decision                                                             | Why                                                                                                          | Who                       |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------- |
| Last in the Build queue                                              | A diagnostic for trained champions; it needs the drills and the trainer first                                | User, 2026-11-04          |
| Edits stay in memory; no edited genome reaches a file or the archive | Hand-made behaviour in the archive breaks selection by survival and offspring (training.md, user 2026-10-17) | User, 2026-10-17; planner |
| The dossier carries traces and ablation, not weights alone           | Weights alone do not show which path a behaviour uses; silencing a unit is the causal check                  | Planner                   |
