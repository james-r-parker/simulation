# Body genes

**Status:** Proposed - a per-spec body table, a trait registry with per-spec gene menus, paired costs and one inheritance routine, and six always-on brain inputs for the size and speed of the bodies in view; Phase 1 (body and senses, one layout version) is the next chunk of the hunting lane.
**Validated:** f77acde1 (2026-11-21)
**Scheduled by:** [fair-chase.md](fair-chase.md) step 1 - the next chunk of the hunting lane: Phase 1 (body and senses) is built before the calculator, which reads it; Phase 2 follows role-budget.md Phase 1, and Phase 3 chooses the numbers with the calculator
**Depends on:** [fair-chase.md](fair-chase.md)

Today a genome holds four trait genes (`TRAIT_INDEX` in `js/sim/brain-layout.js`: `SIZE`, `VISION`, `CHILD_SHARE`, `LEARN`), each moving its trait by at most 30% through `traitValue` in `js/sim/traits.js`, the same for every specialisation. Every other body number is a global config key (`maxVelocity`, `maxThrust`, the temperature bands, `fatSlowShare`, `sprintCost`, ...) or a per-spec multiplier no gene reaches. Genes shape how an agent thinks and hardly at all how it is built.

This doc keeps the five specialisations (`SPECIALISATION_KEYS` in `js/sim/config-spec-rules.js`) and gives them a body that genes can change. A spec's table holds its values (speed, thrust, heat, fat, burn, size); a spec's gene menu names which traits its genes may shift and by how much; each heritable trait is paired with a cost, so no gene is free. The existing four genes are the first menu entries. A last phase lets an agent read what a body physically shows, its size and its speed, so a hunter can pick the small, the slow and the spent and avoid what is large.

Scenes served: **Same spec, different custom** (a lineage of fast, lean or fat bodies inside one spec), **A real chase** (a faster predator is a hotter one), **Other blobs are the climate**, and the trait **A body is a budget** ([principles.md](../principles.md)). [role-budget.md](role-budget.md) reads the spec table and the gene ranges to say whether a role is possible for the best and the worst body of a spec.

Phase 1 moves these global body settings into the spec table as per-spec fields. Each is a multiplier (default 1) or an offset (default 0), so every default world is unchanged. `specParams` and `specTable` in `js/sim/spec-params.js` read them; `specTables` in `js/sim/world.js` builds one lane per field.

Already per-spec and unchanged: `visionRange`, `rearVisionShare`, `turnMultiplier`, `moveCostMultiplier`, `passiveLossMultiplier`, `maxEnergyMultiplier`, `sprintBoost`, `sprintDrainMultiplier`, `splitMinEnergyMultiplier`, `cooldownMultiplier`, `biteMultiplier`, `biteTakenMultiplier`, `kickMultiplier`, `plantFoodValue`, `meatFoodValue`, `canHunt`.

A new spec-rule type, `geneMenu`, validates the `genes` field of an entry in `js/sim/config-rules.js` and `js/sim/config-spec-rules.js`: an object from a trait name of the registry to a span in `[0, MAX_TRAIT_SPAN]` (0.5), unknown names refused.

## The trait system

A trait is one entry of a registry. The layout, the birth, the mutation, the inspector, the detectors and the calculator read the registry and loop over it; none names a trait. Adding or changing a trait is an edit to its entry and its numbers.

### The registry (`js/sim/body-traits.js`)

`TRAITS` is a frozen list. `TRAIT_GENES` is its length and `TRAIT_INDEX` is built from it, so the layout follows the registry.

| Field        | Meaning                                                                                                                                 |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| `name`       | the trait's name, the key of a spec's menu and of every report                                                                          |
| `index`      | the gene's offset from `traitStart`; indices are append-only, and a removed trait leaves its index unused until the next layout version |
| `kind`       | `ratio` (the gene gives `r = 1 + span x tanh(g)`) or `offset` (it gives `span x tanh(g)` in the trait's unit, used by `heatBand`)       |
| `effects`    | a list of `{lane, power}`: each per-slot lane the trait multiplies by `r^power` (a `ratio` trait) or shifts (an `offset` trait)         |
| `costs`      | a list of `{lane, exponentKey}`: each lane the trait's paired cost multiplies by `r^config[exponentKey]`; an exponent of 0 is no cost   |
| `inherit`    | `either` (the child takes the gene whole from one parent) or `blend` (the parents' mean); default `either`                              |
| `sigmaScale` | the trait's mutation step as a multiple of `traitMutationSigma`; default 1                                                              |
| `budget`     | whether [role-budget.md](role-budget.md) reads the trait (`traitCorners`)                                                               |
| `describe`   | one line for the inspector and the generated table                                                                                      |

A lane is a per-slot value a reader already uses (the speed cap, thrust, the turn rate, the store size, the drain, the refill, the heat gain, the six temperature thresholds, the resting burn, the sprint cost, the base size, the ray length, the child share, the Hebbian rate). `LANES` in the same file names each lane's base: the spec's field times the global key. `applyTraits(world, slot)` computes every lane once per birth as `base x product of r^power over the traits that name it`, and `applyGenes` in `js/sim/traits.js` calls it; nothing is computed per tick. With every gene at 0, or every span at 0, each lane equals its base, so the world is the spec table's.

| Trait         | Gene index | Shifts (by the ratio `r`)                                                                                                                                                                                           | Paired cost (multiplier `r^k` or rule)                                                                                                          |
| ------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `size`        | 0          | `baseSize` (spec `baseSizeMultiplier` x `baseSize`)                                                                                                                                                                 | Standing loss `sizeEnergyLoss x size` (exists); turn rate x `r^-sizeTurn` (new key)                                                             |
| `vision`      | 1          | ray length (`visionOf` in `js/sim/traits.js`)                                                                                                                                                                       | Standing loss `visionCost` above ratio 1 (`visionLoss` in `js/sim/energy.js`, exists)                                                           |
| `childShare`  | 2          | the share of energy a mother gives a child                                                                                                                                                                          | The mother's own energy (exists)                                                                                                                |
| `learn`       | 3          | the Hebbian rate multiplier (`LEARN` in `js/sim/wasm-brain.js`)                                                                                                                                                     | None: not a body trait                                                                                                                          |
| `speed`       | 4          | speed cap and thrust, both x `r`                                                                                                                                                                                    | Movement cost `movementCost x speed^2` (exists); heat gain x `r^speedHeat` and `heatSpeedCap` lifts the cap on `speed / maxVelocity` (new keys) |
| `sprintStore` | 5          | the store drain `sprintDrain` ÷ `r` (a longer burst) and the refill ÷ `r` (per-slot `drainBySlot` and `refillBySlot` lanes read by `stepSprintStore`, which reads a per-spec drain table and a scalar refill today) | Heat per sprinting tick `sprintHeat x r^sprintStoreHeat` (new keys): a longer burst runs hotter                                                 |
| `fat`         | 6          | the energy store `maxEnergy x maxEnergyMultiplier` x `r`                                                                                                                                                            | Fat slows thrust and turn by `fatSlowShare x fatSlowMultiplier x r^fatSlow x energy / store` (new key); a fuller body is larger (exists)        |
| `heatBand`    | 7          | the six temperature thresholds, all shifted by `heatBand` degrees together                                                                                                                                          | Built in: a body tuned to heat has its cold stress at a higher temperature, so it is worse in winter and in the cold bands                      |
| `burn`        | 8          | `passiveLossMultiplier` and `sprintCostMultiplier`, both x `r`                                                                                                                                                      | Thrust x `r^burnThrust` (new key): a body that burns less has less power                                                                        |

The existing four keep their indices and their `TRAIT_SPAN` of 0.3. `TRAIT_GENES` becomes 9.

### Inheritance (`js/evo/trait-inherit.js`)

Every birth passes its trait genes through one function, `inheritTraits(child, mother, father, layout, rng, config)`; `father` is null for a split.

1. For each trait in index order: with a father, the gene comes whole from the mother or the father on one `nextFloat` (`either`), or is their mean (`blend`, no draw); with no father it is the mother's.
2. For each trait in index order: with the birth's mutation probability, add `traitMutationSigma x sigmaScale x N(0, 1)`.
3. Clamp to plus or minus `traitGeneClamp`.

`childGenome` in `js/evo/crossover.js` and `mutate` in `js/evo/mutation.js` call it for the trait block and keep the leak genes and the weights as they are. The draws come from the birth's RNG stream in this fixed order, so a world replays from seed and config.

### The contract tests

`test/sim/body-traits.contract.test.js` runs one suite over every registry entry, so a new trait is covered by adding its entry:

| Property              | Assertion                                                                                                                                                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Neutral               | a gene of 0 gives ratio 1 (shift 0) and every lane equals its base; a span of 0 does the same for any gene                                                                                                                     |
| Bounded and monotonic | the ratio rises with the gene and stays inside `1 +- span`                                                                                                                                                                     |
| Paired cost           | with its exponent above 0, each cost lane moves in the costly direction as the gene rises                                                                                                                                      |
| Composition           | a lane two traits name equals the base times both ratios, against a naive loop                                                                                                                                                 |
| Inheritance           | before mutation a child's gene is one of its parents' (`either`) or their mean (`blend`); over 10000 births the mutation step has standard deviation `traitMutationSigma x sigmaScale` within 5%, and no gene leaves the clamp |
| Coverage              | the inspector lists the trait, `eval.gene_spread.<name>` exists, and a trait with `budget` is read by `traitCorners`                                                                                                           |

`test/sim/body-traits.test.js` holds what is particular to one trait (the six thresholds move together for `heatBand`, the store size reaches every `maxEnergyBySpec` reader).

### The table (`npm run traits`)

`scripts/traits.mjs` prints, for a config (`--config`, `--set` as `role:budget`), each spec's value of every lane at the gene's minimum, 0 and maximum, with the paired cost at each, and `--write` generates `docs/trait-table.md` (`--check` in the `conventions` gate). A tweak to a span or a cost is read there before any run.

### Adding a trait

1. Add the registry entry (the next free index, its effects, its costs).
2. If it names a new lane: add the lane to `LANES` with its base, to `specTables` in `js/sim/world.js`, and read it where the global key is read.
3. Add its span to each spec's menu (0 where the spec does not vary) and its cost exponent key.
4. Bump `BRAIN_LAYOUT_NAME`, add the `library/seasons.json` entry, and re-pin the goldens in their own commit.
5. Run the contract tests and `npm run traits -- --write`.

## The body sense

`agentChannel` in `js/sim/ray-march.js` sorts a hit on an agent into kin, threat (it could bite the caster), prey (the caster could bite it) or other, and the channel holds the hit's proximity. That is all a brain reads of another body: a hunter sees a slow, spent reproducer, a fast scout and a large defender that shoves as the same `prey` signal at the same distance.

Six new inputs let a brain read what a body physically shows. No agent carries a label; a spec is told apart as far as its body differs. The inputs are always on: there is no switch.

### Raw lanes (JS)

`writeRay` in `js/sim/ray-march.js` writes two per-ray lanes beside `rayHue`, at `slot x rayCount + ray`. The sense kernel (`wasm/src/sense.rs`) finds the nearest hit and is unchanged: the hit agent's slot is `key - kind x KIND_STRIDE`.

| Lane       | Written for an agent hit                                                                                                                                       | Else |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| `raySize`  | `tanh(size[hit] / size[caster] - 1)` (`detTanh`): 0 for an equal body, negative for a smaller one                                                              | 0    |
| `raySpeed` | `min(1, hypot(vx[hit], vy[hit]) / (maxVelocity x SPEED_SENSE_SPAN))` with `SPEED_SENSE_SPAN` 2, so a body at the cruise cap reads 0.5 and a sprinting one more | 0    |

Both are `Float32Array(maxAgents x rayCount)` lanes of `world` (`js/sim/world.js`), in `BRAIN_FIELDS` and `arenaSpecs` of `js/sim/wasm-arena.js`, as `rayHue` is. `bodySenseOf(world, caster, hit)` in `js/sim/body-sense.js` computes the pair and allocates nothing.

### Pooled values (Rust)

`pool` in `wasm/src/brain.rs` keeps two hits a channel as `[strength, cos, sin]` and carries each food hit's hue with it through the demotion. It carries the size and the speed of a prey hit and of a threat hit the same way.

| Pooled index | Value                                                                                                                                     |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 0 to 53      | the nine channels, six values each, unchanged (food 0, threat 6, prey 12, other 18, kin 24, wall 30, obstacle 36, smoke 42, megafauna 48) |
| 54, 55       | size and speed of the strongest prey hit                                                                                                  |
| 56, 57       | size and speed of the second prey hit                                                                                                     |
| 58, 59       | size and speed of the strongest threat hit                                                                                                |
| 60, 61       | the two food hues (`foodHueStart = POOLED_VALUES - FOOD_HUE_VALUES`, and `hue_start = pv - 2` in `pool`, both still hold)                 |
| 62 to 97     | the 36 body inputs                                                                                                                        |

| Constant                               | Today       | After                                                                                                             |

| `BODY_SENSE_VALUES` (new)              | -           | 6                                                                                                                 |

A value with no hit in its slot is 0. The six values have `wSkip` rows like every pooled value, so a birth reflex can wire one. Kin and other hits carry no size or speed: a hunter compares two prey, and a prey judges the one thing that threatens it.

Computed by the eval observer; none is a reward.

## The calculator reads the menu

[role-budget.md](role-budget.md) resolves a body through `roleParams(config, specName)`. Phase 2 adds `roleParams(config, specName, traits)` with a ratio per trait, and `traitCorners(config, specName)` in `js/evo/role-budget-genes.js`, which enumerates the corners of the menu traits a row reads (`vision`, `speed`, `sprintStore`, `fat`, `size`, `burn`, `heatBand`; at most 2^7 corners). The `--genes` flag of `npm run role:budget` takes `none` (default), `best-vs-worst` (the performer at its best corner against the pressure at its worst), `worst-vs-best` and `corners` (the minimum and maximum slack of every cell and the corner that gives each). "The best defender against the worst predator" is `--genes best-vs-worst --rows defender:predator`.

## Decisions

| Decision                                                                                                                                               | Holds because                                                                                                                                                                                               |
| ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The five specs stay; genes move values inside a spec                                                                                                   | A role's identity (can hunt, plant and meat value, bite) stays discrete; a gene range is a body inside a role, and [role-budget.md](role-budget.md) can bound it by its corners                             |
| The spec table gains fields before any gene reads them                                                                                                 | A gene shifts a per-spec value; the move is a no-op at the defaults and is proven by unchanged goldens                                                                                                      |
| Each trait is paired with a cost, shipped with the trait                                                                                               | An unpaired gene drifts to its span's edge (`eval.gene_edge_share` reads it); `E-BG-1` measures the drift with no cost and the costs are screened against it                                                |
| Where physics already prices a trait, the existing cost is the pair                                                                                    | Speed pays through `movementCost x speed^2`, size through `sizeEnergyLoss`, vision through `visionLoss`, turn through `turnCost`; a new key is added only for the missing half                              |
| `heatBand` shifts all six thresholds together                                                                                                          | The cold side moves with the hot side, so heat tolerance is bought with cold tolerance with no extra key                                                                                                    |
| No flag: a span of 0 is a trait switched off, and the six inputs are always on                                                                         | A flag doubles every path and its tests; the menu already says which traits vary, and the inputs are judged by whether trained brains use them (user, 2026-11-21)                                           |
| One registry, read by the layout, the birth, the inspector, the detectors and the calculator                                                           | A trait added or changed in one place cannot be half-wired; the contract tests run over the registry, so a new trait is tested by existing                                                                  |
| Trait genes are clamped to plus or minus 3                                                                                                             | `tanh` is flat beyond that: a gene that drifts there no longer changes its trait, so mutation cannot bring the lineage back                                                                                 |
| One layout version for the inputs and the genes                                                                                                        | Each layout change refuses every saved genome; one change before any training means one retraining                                                                                                          |
| The numbers are chosen after the calculator is built                                                                                                   | The calculator is what says whether a span leaves a role possible; spans picked before it are guesses                                                                                                       |
| A brain reads size and speed, never a spec label                                                                                                       | A label is a fact no body shows; size and speed are what a real hunter reads, they are honest because they are the body, and a spec is told apart only as far as its body differs (user, 2026-11-21)        |
| Six values, placed between the channels and the food hues                                                                                              | Two prey hits to compare and one threat to judge; before the hues, so `foodHueStart` and the kernel's `hue_start` keep their formulas and the nine channel blocks keep their indices for the birth reflexes |
| Phase 4 runs only when `choiceGain` justifies it                                                                                                       | A brain input is a cost; a hunter that gains no margin from choosing among targets has nothing to read                                                                                                      |
| Rules and layout changes land on `main` as breaking commits (`!`, `BREAKING CHANGE:` footer) with the next `library/seasons.json` entry in the same PR | The season opens in the commit that changes `rulesHash`, and the user is the only user                                                                                                                      |
| The continuous replacement of specs is not part of this doc                                                                                            | The specs and their templates stay                                                                                                                                                                          |
