# Body genes

**Status:** Proposed - five specialisations keep their roles, the body settings that should differ by spec move into the spec table, and each spec declares a gene menu of the body traits its genes may shift, each paired with a cost; a visible cue and a brain input let an agent read who it is looking at. Phase 1 (the spec-table move) is first.
**Validated:** f77acde1 (2026-11-21)
**Scheduled by:** [world-balance.md](world-balance.md) step 10 - builds on prey-guilds.md, which shows which trade-offs hold niches, and on role-budget.md Phase 1, which reads the gene ranges
**Depends on:** [honest-budgets.md](honest-budgets.md), [prey-guilds.md](prey-guilds.md), [role-budget.md](role-budget.md)

Today a genome holds four trait genes (`TRAIT_INDEX` in `js/sim/brain-layout.js`: `SIZE`, `VISION`, `CHILD_SHARE`, `LEARN`), each moving its trait by at most 30% through `traitValue` in `js/sim/traits.js`, the same for every specialisation. Every other body number is a global config key (`maxVelocity`, `maxThrust`, the temperature bands, `fatSlowShare`, `sprintCost`, ...) or a per-spec multiplier no gene reaches. Genes shape how an agent thinks and hardly at all how it is built.

This doc keeps the five specialisations (`SPECIALISATION_KEYS` in `js/sim/config-spec-rules.js`) and gives them a body that genes can change. A spec's table holds its values (speed, thrust, heat, fat, burn, size, cue); a spec's gene menu names which traits its genes may shift and by how much; each heritable trait is paired with a cost, so no gene is free. The existing four genes are the first menu entries. A last phase gives agents a way to read another agent's body cue, so a hunter can pick or avoid a target and a prey can display or mimic.

Scenes served: **Same spec, different custom** (a lineage of fast, lean or fat bodies inside one spec), **A real chase** (a faster predator is a hotter one), **Other blobs are the climate**, and the trait **A body is a budget** ([principles.md](../principles.md)). [role-budget.md](role-budget.md) reads the spec table and the gene ranges to say whether a role is possible for the best and the worst body of a spec.

## The spec table

Phase 1 moves these global body settings into the spec table as per-spec fields. Each is a multiplier (default 1) or an offset (default 0), so every default world is unchanged. `specParams` and `specTable` in `js/sim/spec-params.js` read them; `specTables` in `js/sim/world.js` builds one lane per field.

| `thrustMultiplier`       | 1        | `maxThrust`                                                                                                                                                               | `thrustOf` in `js/sim/physics.js`                                            |

Already per-spec and unchanged: `visionRange`, `rearVisionShare`, `turnMultiplier`, `moveCostMultiplier`, `passiveLossMultiplier`, `maxEnergyMultiplier`, `sprintBoost`, `sprintDrainMultiplier`, `splitMinEnergyMultiplier`, `cooldownMultiplier`, `biteMultiplier`, `biteTakenMultiplier`, `kickMultiplier`, `plantFoodValue`, `meatFoodValue`, `canHunt`.

Left global, with the reason in the inventory (T1): `damping` (a medium property), `restitution`, `biteArc` (jaw geometry shared by every hunter), `sprintMultiplier` (the boost's unit; `sprintBoost` is the per-spec value), `temperatureMax`, `temperatureStart`, the efficiency levels, the digest, handling and satiation timers, `maturityTicks`, `pregnancyTicks`.

A new spec-rule type, `geneMenu`, validates the `genes` field of an entry in `js/sim/config-rules.js` and `js/sim/config-spec-rules.js`: an object from a trait name of the registry to a span in `[0, MAX_TRAIT_SPAN]` (0.5), unknown names refused.

## The gene menu

A menu entry gives a trait a span. A gene `g` shifts its trait by the ratio `r = 1 + span x tanh(g)` (`traitValue` of `js/sim/traits.js` generalised with the span of the spec's menu), or by `span x tanh(g)` degrees for `heatBand`. A span of 0 fixes the trait. A random genome starts every trait gene at 0 (the spec's own value). Mutation and crossover treat trait genes as they do today (`TRAIT_SIGMA` in `js/evo/mutation.js`, `crossover` in `js/evo/crossover.js`).

The trait registry is `js/sim/body-traits.js`: for each trait its gene index (`TRAIT_INDEX`), the value it shifts, and its paired cost. A trait ratio is computed once per birth in `applyGenes` and stored in per-slot lanes; nothing is computed per tick.

| Trait         | Gene index | Shifts (by the ratio `r`)                                                     | Paired cost (multiplier `r^k` or rule)                                                                                                          |
| ------------- | ---------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `size`        | 0          | `baseSize` (spec `baseSizeMultiplier` x `baseSize`)                           | Standing loss `sizeEnergyLoss x size` (exists); turn rate x `r^-sizeTurn` (new key)                                                             |
| `vision`      | 1          | ray length (`visionOf` in `js/sim/traits.js`)                                 | Standing loss `visionCost` above ratio 1 (`visionLoss` in `js/sim/energy.js`, exists)                                                           |
| `childShare`  | 2          | the share of energy a mother gives a child                                    | The mother's own energy (exists)                                                                                                                |
| `learn`       | 3          | the Hebbian rate multiplier (`LEARN` in `js/sim/wasm-brain.js`)               | None: not a body trait                                                                                                                          |
| `speed`       | 4          | speed cap and thrust, both x `r`                                              | Movement cost `movementCost x speed^2` (exists); heat gain x `r^speedHeat` and `heatSpeedCap` lifts the cap on `speed / maxVelocity` (new keys) |
| `sprintStore` | 5          | the store drain `sprintDrain` ÷ `r` (a longer burst) and the refill ÷ `r`     | Heat per sprinting tick `sprintHeat x r^sprintStoreHeat` (new keys): a longer burst runs hotter                                                 |
| `fat`         | 6          | the energy store `maxEnergy x maxEnergyMultiplier` x `r`                      | Fat slows thrust and turn by `fatSlowShare x fatSlowMultiplier x r^fatSlow x energy / store` (new key); a fuller body is larger (exists)        |
| `heatBand`    | 7          | the six temperature thresholds, all shifted by `heatBand` degrees together    | Built in: a body tuned to heat has its cold stress at a higher temperature, so it is worse in winter and in the cold bands                      |
| `burn`        | 8          | `passiveLossMultiplier` and `sprintCostMultiplier`, both x `r`                | Thrust x `r^burnThrust` (new key): a body that burns less has less power                                                                        |
| `display`     | 9          | the body's visible cue (Phase 4), by `span x tanh(g)` around the spec's `cue` | Standing loss `passiveLoss x displayCost x abs(cue - spec cue)` (new key): a body that signals more, or mimics, pays                            |

The existing four keep their gene indices; `TRAIT_GENES` becomes 10. A trait that no spec's menu lists is never read.

Initial spans (a menu entry is a share of the spec's value; `heatBand` is in degrees; 0 fixes the trait). Each is a starting value that the Phase 3 screens set.

## Who is that (Phase 4)

`agentChannel` in `js/sim/ray-march.js` sorts a hit on an agent into kin, threat (it could bite the caster), prey (the caster could bite it) or other. An agent carries no visible marker (`rayHue` holds the food hue only), so a hunter sees a slow reproducer, a fast scout and a kicking defender as the same `prey` signal and can learn to pick or avoid targets only from outcomes.

Phase 4 gives every agent a visible cue and every brain four values to read it. The cue is the spec's `cue` shifted by the `display` gene and clamped to `[0, 1]`, stored in a per-slot `cue` lane. Defaults: forager 0.25, predator 0.75, reproducer 0.4, scout 0.55, defender 0.9.

| Change           | Where                                                                                                                                                                                                                  |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Raw ray value    | `RAY_CHANNELS` 10 to 11: the cue of an agent hit is written beside its channel in `writeRay` (`js/sim/ray-march.js`); 0 for every other kind                                                                           |
| Pooled values    | `CUE_VALUES` (new, 4) in `js/sim/brain-layout.js`: the cue of the strongest hit on the kin, threat, prey and other channels, after the food hues; `POOLED_VALUES` 56 to 60; `pool` in `js/sim/ray-pool.js` writes them |
| Sense kernel     | `gather` and the pooled write in `wasm/src/sense.rs` read the agent cue lane (a new `f32` lane in the arena, `js/sim/wasm-sense.js`); rebuilt with `scripts/build-wasm.sh`, Rust by Opus                               |
| Brain and layout | `inputCount` grows by 4; `wIn` and `wSkip` grow by 4 rows; `BRAIN_LAYOUT_NAME` `pooled-v6` to `pooled-v7`; every champion and archive of `pooled-v6` is refused at load                                                |
| Renderer         | the agent model is tinted by the cue (`js/app/renderer/models.js`, the pack worker's rig), so what the brain reads is what the viewer sees                                                                             |

A new brain input is a cost ([AGENTS.md](../../AGENTS.md), Boundaries): it needs a scene metric to move, and it passes the keep rule.

| Metric                            | Reads                                                                                                                                                             | Direction                       |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| `eval.hunter_defender_bite_ratio` | Bites a hunter starts on defenders per defender-in-view tick over the same for other prey (null with no defender in view); under 1 means hunters avoid what kicks | `watch` (lower)                 |
| `eval.warned_escape_share`        | Of chases that end on a prey that heard an alarm within `callTicks`, the escape share minus the escape share of prey that heard none                              | `watch` (higher)                |
| `eval.hunter_kills_per_life_mean` | The hunter's income, the keep-rule guard of [fair-chase.md](fair-chase.md) Step 3                                                                                 | `higher` (T11 of fair-chase.md) |

Phase 4 starts with a gate: `npm run role:budget -- --mix <the default mix>` on the defaults prints `predator>average` and `predator>best`. When `choiceGain` is under `tightTicks` and `catchableShare` is 1, a hunter gains nothing from telling its targets apart and Phase 4 stops with the reading recorded.

Computed by the eval observer; none is a reward.

| Metric                     | Direction | Reads                                                                                                                            |

| `eval.gene_spread.<trait>` | watch     | Standard deviation of the trait ratio across living agents of each spec after burn-in                                            |
| `eval.gene_edge_share`     | watch     | The share of living agents with any menu gene at or beyond 90% of its span: a menu that is too narrow or a cost that is too weak |

## The calculator reads the menu

[role-budget.md](role-budget.md) resolves a body through `roleParams(config, specName)`. Phase 2 adds `roleParams(config, specName, traits)` with a ratio per trait, and `traitCorners(config, specName)` in `js/evo/role-budget-genes.js`, which enumerates the corners of the menu traits a row reads (`vision`, `speed`, `sprintStore`, `fat`, `size`, `burn`, `heatBand`; at most 2^7 corners). The `--genes` flag of `npm run role:budget` takes `none` (default), `best-vs-worst` (the performer at its best corner against the pressure at its worst), `worst-vs-best` and `corners` (the minimum and maximum slack of every cell and the corner that gives each). "The best defender against the worst predator" is `--genes best-vs-worst --rows defender<predator`.

## Decisions

| Decision                                                                 | Holds because                                                                                                                                                                   |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The five specs stay; genes move values inside a spec                     | A role's identity (can hunt, plant and meat value, bite) stays discrete; a gene range is a body inside a role, and [role-budget.md](role-budget.md) can bound it by its corners |
| The spec table gains fields before any gene reads them                   | A gene shifts a per-spec value; the move is a no-op at the defaults and is proven by unchanged goldens                                                                          |
| Each trait is paired with a cost, shipped with the trait                 | An unpaired gene drifts to its span's edge (`eval.gene_edge_share` reads it); `E-BG-1` measures the drift with no cost and the costs are screened against it                    |
| Where physics already prices a trait, the existing cost is the pair      | Speed pays through `movementCost x speed^2`, size through `sizeEnergyLoss`, vision through `visionLoss`, turn through `turnCost`; a new key is added only for the missing half  |
| `heatBand` shifts all six thresholds together                            | The cold side moves with the hot side, so heat tolerance is bought with cold tolerance with no extra key                                                                        |
| One flag, `bodyGenesEnabled`, then deleted at adoption                   | The keep rule reads the bundle once with the genes off; the flag is deleted by T18a with the losing path (`scripts/flag-ledger.json`)                                           |
| The cue is a visible value with a gene (option b), not a spec marker (a) | A spec index on a ray is a label no body shows and cannot be mimicked; a cue value with a `display` gene and a cost is a signal that can be honest, lied about and paid for     |
| Both options are not taken together                                      | A spec marker beside the cue would let a brain ignore the cost of mimicry; one cue carries both                                                                                 |
| Four cue values, one per agent channel, not one per hit                  | A hunter needs the cue of what it targets (prey), what threatens it, kin and others; the strongest hit per channel is the pooled convention of the food hues                    |
| Phase 4 runs only when `choiceGain` justifies it                         | A brain input is a cost; a hunter that gains no margin from choosing among targets has nothing to read                                                                          |
| Two layout breaks, `pooled-v6` then `pooled-v7`                          | The gene count and the input count are separate changes with separate keep-rule reads; the user is the only user and accepts breaking champions and archives                    |
| The continuous replacement of specs is not part of this doc              | The specs and their templates stay                                                                                                                                              |
