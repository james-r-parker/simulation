## Look

Crisp neon vector. Every rule below holds at every frame rate and on both GPU backends.

| Rule              | Value                                                                                                                                                                                                          |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Background        | `#000000`, cleared once per frame, never tinted or changed by season, lens, load or backend; only a sparse field of still depth points (`DEPTH_POINTS` 1200, 1.2 device px, brightness 0.12 to 0.4) sits on it |
| Shapes            | Signed distance fields per model part; coverage is `smoothstep` over one `fwidth` of the distance (analytic anti-aliasing), plus 4x MSAA on the canvas                                                         |
| Rim               | A bright outline of `RIM_PX` (1.5 device px) at every zoom, in the item's role colour                                                                                                                          |
| Fill              | Flat and faint, `FILL_SHARE` (0.18) of the rim colour; no gradient, no noise, no texture                                                                                                                       |
| Idle glow         | None. No halo, bloom, haze, vignette, grain or blur anywhere                                                                                                                                                   |
| Event flash       | Bite, kill, birth, mate, call and pollination flash an additive radial glow for at most `FLASH_MAX_TICKS` (24) ticks with the wall-time floor `FX_MIN_MS` (250 ms); nothing else glows                         |
| Least size        | A body is drawn at least `MIN_PX_HUNTER` (24) or `MIN_PX_OTHER` (20) device px across (`minPxTable` in [display-size.js](../../js/app/display-size.js))                                                        |
| Seasons           | Shown by crisp elements on the map (the season motes, frost ticks, drought cracks), never by background colour                                                                                                 |
| Lenses            | Crisp contour lines and outlined shapes; a lens dims nothing below 0.55 and blurs nothing                                                                                                                      |
| Degrading         | Only effect particle counts drop under load (`adaptFxBudget`); every model, clip and layer draws at all times                                                                                                  |
| Colour management | `ColorManagement.enabled` is false, `toneMapping` is `NoToneMapping`, `outputColorSpace` is `LinearSRGBColorSpace`: every colour is a display value written straight to the canvas                             |

> Note: three's `Renderer` draws through an extra framebuffer target, which turns MSAA off on the canvas and adds a full-screen pass, whenever `toneMapping` is not `NoToneMapping` or the output colour space differs from `ColorManagement.workingColorSpace` (`needsFrameBufferTarget`). With colour management on, a hex `Color` is also converted from sRGB to linear, which would darken the display values.

## Models

A model is a list of parts. A part is one SDF primitive with a pivot, a role colour, a draw order and an optional state gate. `models.js` holds the catalogue as pure data; `model-material.js` turns one model into one TSL node material. Every rendered item has exactly one model, and a model has at most `MAX_PARTS` (16) parts.

| Primitive  | Parameters                                           |
| ---------- | ---------------------------------------------------- |
| `circle`   | radius                                               |
| `ring`     | radius, width, dash count (0 solid)                  |
| `box`      | half width, half height, corner                      |
| `poly`     | up to `MAX_POINTS` (10) vertices, convex or concave  |
| `segment`  | two points, width                                    |
| `arc`      | radius, width, start, sweep                          |
| `dots`     | radius, count, ring radius, phase                    |
| `blob`     | the instance's `rockShape` harmonics (`sdBlob`)      |
| `membrane` | half axes, ripple share, lobes, phase (`sdMembrane`) |
| `wave`     | root, tip, swing, frequency, phase, width (`sdWave`) |

A part's distance is in model units (body radius 1). Parts combine by draw order: a later part's fill covers an earlier one, and every part keeps its rim. A gated part draws only while its state bit or value is set.

### Agent models

Cells, not icons: a rippling membrane (`membrane`, its phase the agent's wave phase), organelles inside and the way it
swims, with thin rims and faint fills and no faces. The nucleus (bound to `eye`) swells and shrinks with the juvenile,
resting and fleeing cues.

| Model        | Parts                                                                                                                                   |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| `predator`   | An elongated membrane, two lips at the front (`arc`, bound to `jawUp` and `jawDown`) that open and close round prey, a nucleus set back |
| `forager`    | A round membrane and one nucleus sitting forward                                                                                        |
| `reproducer` | A round membrane and two nuclei (`dots`) whose spacing grows with gestation01, so the cell is seen to divide                            |
| `scout`      | A small slim membrane, a beating flagellum (`wave`) behind it, two sensory cilia (bound to `limbA` and `limbB`) and a nucleus           |
| `defender`   | A round membrane inside a ring of short spines (a dashed `ring`), a thin inner wall and a central nucleus                               |

`wavePhase` in `agent-rig.js` gives each agent's wave phase (into `gate2.w`): its own phase plus wall time at 0.6 Hz
at rest rising to 3 Hz at top speed, so membranes ripple and flagella beat faster as a cell swims faster.

## Animation clips

A clip is a set of keyframe tracks on the twelve rig channels (`CHANNELS` in `clips.js`). A track names a channel and keys `[t, value, ease]` with `t` in 0 to 1; the ease (an `FX_EASE` name) shapes the segment that ends at the key. A model's parts bind to channels (`bind` in `models.js`); the body channels move the whole model.

| Channel     | Rest | Meaning                                                                       | Layering |
| ----------- | ---- | ----------------------------------------------------------------------------- | -------- |
| `tx`, `ty`  | 0    | Body offset in body radii                                                     | add      |
| `rot`       | 0    | Body rotation, radians                                                        | add      |
| `sx`, `sy`  | 1    | Body scale along and across the heading                                       | multiply |
| `open`      | 0    | Jaw or mouth opening, 0 to 1 (`jawUp`, `jawDown` turn by `JAW_OPEN`)          | add      |
| `eye`       | 1    | Eye scale (`eye`)                                                             | multiply |
| `flash`     | 0    | Additive event glow over the body, 0 to 1                                     | add      |
| `ring`      | 1    | Call ring scale (`ring`)                                                      | multiply |
| `ringAlpha` | 0    | Call ring opacity                                                             | add      |
| `limb`      | 0    | Leg and antenna swing, radians (`limbA` turns by `+limb`, `limbB` by `-limb`) | add      |
| `head`      | 0    | Head dip and fruit bob, body radii (`head`)                                   | add      |

`clip-sampler.js` evaluates a clip exactly (`sampleClip`), tabulates every clip at `CLIP_SAMPLES` (64) points (`bakeClips`) and layers a baked clip onto one instance's rig by blending two neighbouring samples (`applyClip`, allocation-free). The packers apply each instance's clips once per frame and upload the rig as three `vec4` instance attributes, so the GPU reads no clip data.

Clips are one-shot (driven by a body tween's kind and age, `tweenAge` in [body-tweens.js](../../js/app/renderer/body-tweens.js)) or looping (at the clip's `rate` in Hz from a per-instance phase, scaled by an amplitude such as `speed01`). A one-shot clip layers on the loops. `body-tweens.js` gains the kind `KILL` (24 ticks, rank 5), which `playDeath` in [effects-combat.js](../../js/app/renderer/effects-combat.js) starts on the killer of a body eaten in place of `GULP`. `clipForTween` (new, in `clips.js`) maps each `TWEEN` kind to its clip.

Particle motion keeps the `FX_CURVES` table (shape, motion, ease, scale and alpha keys). `packFx` in `fx-pack.js` evaluates each live instance on the CPU while packing, in closed form (eased time, keyed scale and brightness, `out`, `in`, `rise`, `fall` and `orbit` motion), lifts its colour to the neon lightness with `toDisplay` (intensity `bright x min(1, max(gain, MIN_GAIN))`, `MIN_GAIN` 0.75) and writes it into its shape's bucket, so particles cost no compute pass and look the same on both backends.

## Architecture

```
worker snapshot ──> interpolateInto (agents) ──> agents-pack ──> agent-draw (5 instanced meshes, model + clips)
               ├──> trackHerds (herds by slot) ─> herd-pack ──> herd-draw
               ├──> food-pack ──────────────────────────────────> food-draw
               └──> world-pack (patches, zones, clouds, motes) ─> world-draw
effect records ──> effects-player ──> body tweens (clips), fx-ring ──> fx-draw (closed-form particles, flashes)
                                   └─> mate threads, pursuits, overlays ──> line-buffer ──> line-draw
pheromone field ──> contour-draw (scent lens iso-lines)
stage: WebGPURenderer (WebGL2 fallback), MSAA 4x, ortho camera, black clear, layers back to front
```

Every `*-draw.js` module is a thin GPU shell over a pure packer (`*-pack.js`, `herd-track.js`, `fx-ring.js`) that is unit tested.

### Stage

`stage.js` replaces `scene.js`. `createStage` is async: it builds `new WebGPURenderer(stageOptions(params))` (`three/webgpu`), awaits `renderer.init()`, appends the canvas and returns `canvas`, `renderer`, `backend`, `resize`, `draw`, `rebuild`, `isLost` and `dispose`.

- `chooseBackend` (pure, in `stage-options.js`) picks WebGPU on a hardware adapter and WebGL2 with no adapter or a software fallback adapter (headless Chromium's SwiftShader, whose device cannot present); `?backend=webgpu` or `?backend=webgl2` forces either.
- `stageOptions` (pure, in `stage-options.js`): `antialias: true`, `samples: 4`, `alpha: false`, `depth: false`, `stencil: false`, `powerPreference: 'high-performance'`; `trackTimestamp` with `?gputime=1`; `forceWebGL` when the chosen backend is WebGL2.
- After `init`, `renderer.backend.isWebGPUBackend` names the backend; the stage logs `RendererReady` (backend, the forced backend, samples, device pixel ratio).
- `setPixelRatio(1)` and `setSize(width, height, false)` in device pixels from `canvasPixelSize` (`MAX_PIXEL_RATIO` 2 stays, so a 3840x2160 canvas at ratio 1.5 or 2 draws at native resolution).
- One `Scene`, one `OrthographicCamera`, `autoClear` on with clear colour `#000000`; layers mount in the order of the Layers table, `renderOrder` by position; every material has `depthTest` and `depthWrite` false.
- The stage assigns `renderer.onDeviceLost`: it marks the stage lost, logs `DeviceLost` and rebuilds the renderer and every layer once, then logs `DeviceRestored`. A second loss within 10 s logs `RendererFailed` and shows the render failure message. `DeviceLost` and `DeviceRestored` replace the `ContextLost` and `ContextRestored` app events; the WebGL2 backend's context loss takes the same path.
- `renderer.init()` rejecting logs `RendererInitFailed` with the message and shows the render failure message.
- The render failure message (`showRenderFailure`, new, in `js/app/ui/render-failure.js`): "This browser could not start the GPU renderer (WebGPU or WebGL2)." over the black canvas. The `<noscript>` text in `index.html` names "WebGPU or WebGL2".

Wall-gap crossings play the `wallCross` effect recipe (a ring at the gap). Winter motes gather on the cold margins (density by how deep their row is in the cold margin, `terrain.coldMarginWidth`).

### Agents

`agents-pack.js` keeps its buckets (pose, colour, state, extra, motion, tween, body) and gains `index`, each row's agent index. `rigBucket` in `agent-rig.js` then writes per row:

- the rim colour (`toDisplay` of the family or lineage colour, or of `temperatureColor` under the temperature lens) and a fill share that grows with energy (`FILL_FLOOR` 0.1 at 0, `FILL_SHARE` at full), never the rim brightness;
- the state gates, the pollen colour and the call colour;
- the rig: the condition loops, the jaw value and the clip `clipForTween` gives the body tween.

`agent-draw.js` builds one `InstancedMesh` per spec from `modelMaterial(model, {inputs, look})`. The vertex node places the quad, scaled to cover `modelBounds` after its clips' extreme keys; the fragment node evaluates the parts' distances under their clip transforms and writes rim and fill coverage.

### Herds

`herd-track.js` blends herd animals between the two held snapshots as `interpolateInto` blends agents: matched by slot, position and heading blended at the same alpha (the heading by the shorter arc), unmatched animals at their newest position. A matched pair further apart than `herdRunSpeed` times the ticks between the snapshots plus `herdRadius` is a reused slot (a calf born into a dead animal's slot) and is not blended. Herds move at the frame rate.

The snapshot herd record (`writeHerds` in [snapshot.js](../../js/sim/snapshot.js)) carries the animal's slot as a `u32` in word 2 in place of the radius; `ready.info` gains `herdRadius` and `herdRunSpeed`. The record stays 6 words. Nothing the sim computes changes: `worldHash`, the goldens, the effect stream and `rulesHash` stay as they are.

#### The death (T31 to T34)

#### The bump (T37)

What existed before: nothing. The protocol carries no collision or impact record (`COLLISION` is only a death cause, whose recipe played at a death), and a body hitting a rock, the wall or another body drew exactly as it did a frame earlier. The renderer reads it from the blended frame, as the chase cue is read:

- `bumps.js` (pure) keeps each slot's last speed share. A body that was running (at least `BUMP_MIN_SPEED`, 0.3 of top speed) and loses `BUMP_SOFT` (0.3) of top speed in one frame is a soft bump; `BUMP_HARD` (0.6) is a hard one. The impact is the speed lost, so a harder hit squashes more. At most `MAX_BUMPS` (32) a frame. This is an approximation: a hunter braking hard to stalk can read as a soft bump, which costs nothing worse than a faint squash.
- The squash is along the body's heading, the way it was moving, which is the contact normal for a head-on hit: the `bump` clip (`sx` to 0.9, `sy` to 1.06, back by 1.03 and rest, 10 ticks) and `bumpHard` (`sx` to 0.8, `sy` to 1.12, 14 ticks). No flash, no particles. A faint ripple rides on it: a dent at the nose of depth `BUMP_DENT` 0.05 (soft) or 0.12 (hard) on the same `dents.js` store.
- Priority: the bump tween has rank 0, the lowest, so any running tween (a bite's flinch or lunge, a kill) keeps the slot; the dent keeps the deeper of two, so a bite dent (0.3) is never replaced by a bump's.
- No pool of its own: it uses the body tweens and dents, which are preallocated per slot.

#### Budget

- Dying bodies: at most `MAX_DYING` (64), each one extra instance row; a dent is a few typed-array writes per bitten agent.
- Wakes: at most `MAX_WAKES` (64) bodies, two lines each; the tether keeps `MAX_PURSUITS` (48).
- Particles: a bite adds about 11 and a death 8 to 12 instances through `playRecipe`, which the family token buckets (combat 80 per second) and the frame cap already bound; `adaptFxBudget` sheds them first under load. Every model, clip and dying body still draws at all times.
- The vertex attribute count of an agent mesh rises from 9 to 10, still two vertex buffers (the interleaved instance buffer and the quad), under WebGPU's 8 buffers and 16 attributes.
- Nothing allocates per frame: the pools, caches and line buffers are created once per world.

## Decisions

| Decision                                                                  | Reason                                                                                                                                                                                                                     |
| ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Particles in closed form on the CPU while packing, no compute pass        | The same look on WebGPU and the WebGL2 fallback and no per-frame dispatch, which holds the rule that load never changes the look; a few hundred evaluations a frame                                                        |
| The herd slot replaces the radius word in the snapshot                    | Herds need an id to interpolate; the radius is a config constant; the record keeps its size                                                                                                                                |
| A distance rule detects a reused herd slot                                | The sim keeps no herd generation, and adding one changes `js/sim` state; a calf never moves a herd run in one interval                                                                                                     |
| No `?renderer=` switch                                                    | The user (2026-11-14): one all-out replacement pull request                                                                                                                                                                |
| The dying body is drawn from a last-seen cache, not from the snapshot     | The worker's `DIED` record carries only the genome, lineage, cause and killer, and the body is absent from the snapshot before the record plays; a cache keeps the specialisation, pose and size without a protocol change |
| Dying bodies run on wall time, particles on ticks                         | A death must read for 1 to 2 s whatever the sim speed; the particles keep the Phase 1 tick clock and its wall floor                                                                                                        |
| The dent is one instance lane and one membrane parameter, not a new model | The membrane already ripples; a local radial offset needs no new primitive and costs one attribute (10 of 16)                                                                                                              |
| The wake is lines, not a particle recipe                                  | A wake lasts as long as the body sprints; lines with a fading alpha are one buffer a frame and need no spawn budget                                                                                                        |
| The tether stays, faint                                                   | The user asked for an optional, very faint tether; the pursuit pairs already exist                                                                                                                                         |
| The `ghost` ring leaves the death recipes                                 | The dying body replaces it; two outlines of one body would read as a double image                                                                                                                                          |
| No sim, worker or `worldHash` change                                      | Everything new is derived on the render side from the snapshot, the effect records and the clock                                                                                                                           |
| The before numbers live in this doc and the pull request body             | `bench/browser-baseline.json` holds one record per viewport, which the after run replaces                                                                                                                                  |

## Verification

3. Manual walk on the PG32UCDP in Windows Chrome:
    1. Load the app; the background is black and stays black through a full year at speed x8 (the season motes change, the background does not) and while zoomed out at 1000 agents.
    2. Zoom to one forager, predator, reproducer, scout and defender: each edge is sharp at 1:1 pixels, with no halo.
    3. Follow a predator through a chase: stalk, lunge, jaw snap, and on a kill the flash and shards; the flash is gone within a quarter second.
    4. Watch a herd beside agents: it moves as smoothly as they do; grazing heads dip; a stampede gallops.
    5. Find each food species, a carcass ageing, a patch filling (fruit glints) and wilting (leaf motes), a fertile and a dung zone, rocks, the wall, a gap crossing and a refuge lighting up.
    6. Watch a mating, a birth by mating and by split, an alarm and a pack call, smoke, pollen carried and pollination, a sick, an infected, a sated, a cold, a hot, a resting and an in-cover blob.
    7. Turn on each lens (scent, temperature, territory, vision, calls) and select an agent: every line is crisp.
    8. Switch the palette to `cvd-safe` and `high-contrast`: rims stay crisp and readable.
    9. Load `?backend=webgl2`: the same look, no console error.
    10. Load in Firefox: the WebGL2 fallback draws the same look.
