# Crisp renderer

**Status:** Proposed - one pull request replaces the WebGL renderer with a WebGPURenderer and TSL renderer in a crisp neon vector look; Phase 1 is the whole replacement.
**Validated:** 6a245c94 (2026-11-14)
**Priority:** 1 - the user's brief (2026-11-14): the renderer is the part of the app the user is least happy with, and it changes no sim behaviour, so it is built in its own session beside the eval lanes

> Supersedes the drawing parts of [worker-and-renderer.md](worker-and-renderer.md) (Renderer, Look, the Phase 2 budgets, Phases 6 and 7 drawing) and [renderer-event-effects.md](renderer-event-effects.md) (the visual signatures, Ambient layers and Toggles). Their data parts stay: the protocol, the snapshot, interpolation, the effect records, flag edges, body tweens, the effect budget, the director and the audio.

The renderer draws every item from a designed vector model with keyframed animation clips, on true black, through three's `WebGPURenderer` with its WebGL2 fallback. It ships as one pull request; the old renderer is deleted in it.

## Look

Crisp neon vector. Every rule below holds at every frame rate and on both GPU backends.

| Rule              | Value                                                                                                                                                                                  |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Background        | `#000000`, cleared once per frame, never tinted, never changed by season, lens, load or backend                                                                                        |
| Shapes            | Signed distance fields per model part; coverage is `smoothstep` over one `fwidth` of the distance (analytic anti-aliasing), plus 4x MSAA on the canvas                                 |
| Rim               | A bright outline of `RIM_PX` (1.5 device px) at every zoom, in the item's role colour                                                                                                  |
| Fill              | Flat, `FILL_SHARE` (0.28) of the rim colour; no gradient, no noise, no texture                                                                                                         |
| Idle glow         | None. No halo, bloom, haze, vignette, grain or blur anywhere                                                                                                                           |
| Event flash       | Bite, kill, birth, mate, call and pollination flash an additive radial glow for at most `FLASH_MAX_TICKS` (24) ticks with the wall-time floor `FX_MIN_MS` (250 ms); nothing else glows |
| Least size        | A body is drawn at least `MIN_PX_HUNTER` (24) or `MIN_PX_OTHER` (20) device px across (`minPxTable` in [display-size.js](../../js/app/display-size.js))                                |
| Seasons           | Shown by crisp elements on the map (the season motes, frost ticks, drought cracks), never by background colour                                                                         |
| Lenses            | Crisp contour lines and outlined shapes; a lens dims nothing below 0.55 and blurs nothing                                                                                              |
| Degrading         | Only effect particle counts drop under load (`adaptFxBudget`); every model, clip and layer draws at all times                                                                          |
| Colour management | `ColorManagement.enabled` is false, `toneMapping` is `NoToneMapping`, `outputColorSpace` is `LinearSRGBColorSpace`: every colour is a display value written straight to the canvas     |

> Note: three's `Renderer` draws through an extra framebuffer target, which turns MSAA off on the canvas and adds a full-screen pass, whenever `toneMapping` is not `NoToneMapping` or the output colour space differs from `ColorManagement.workingColorSpace` (`needsFrameBufferTarget`). With colour management on, a hex `Color` is also converted from sRGB to linear, which would darken the display values.

## Models

A model is a list of parts. A part is one SDF primitive with a pivot, a role colour, a draw order and an optional state gate. `models.js` holds the catalogue as pure data; `model-material.js` turns one model into one TSL node material. Every rendered item has exactly one model, and a model has at most `MAX_PARTS` (16) parts.

| Primitive | Parameters                           |
| --------- | ------------------------------------ |
| `circle`  | radius                               |
| `ring`    | radius, width, dash count (0 solid)  |
| `box`     | half width, half height, corner      |
| `poly`    | up to 8 vertices (convex or concave) |
| `segment` | two points, width                    |
| `arc`     | radius, width, start, sweep          |
| `dots`    | radius, count, ring radius           |

A part's distance is in model units (body radius 1). Parts combine by draw order: a later part's fill covers an earlier one, and every part keeps its rim. A gated part draws only while its state bit or value is set.

## Animation clips

A clip is a set of keyframe tracks on a model's parts. A track names a part, a channel and keys `[t, value, ease]` with `t` in 0 to 1. `clips.js` holds the catalogue; `clip-sampler.js` samples a clip on the CPU (`sampleClip`) and bakes every clip into one float `DataTexture` with `NearestFilter` (`bakeClips`).

| Channel    | Meaning                                 |
| ---------- | --------------------------------------- |
| `tx`, `ty` | Part offset in body radii               |
| `rot`      | Part rotation about its pivot, radians  |
| `sx`, `sy` | Part scale along and across the heading |
| `open`     | Jaw or mouth opening, 0 to 1            |
| `alpha`    | Part opacity                            |
| `flash`    | Additive event glow, 0 to 1             |

The baked texture holds `CLIP_SAMPLES` (64) samples per track row, two RGBA texels per sample (the eight channels). The nodes read two neighbouring samples with `textureLoad` and blend them in TSL, so no float-filterable texture is needed. Eases are the `FX_EASE` names.

Clips are one-shot (driven by a body tween's kind and age, `tweenAge` in [body-tweens.js](../../js/app/renderer/body-tweens.js)) or looping (driven by the agent's phase and speed). A one-shot clip layers on the loops; offsets and rotations add, scales multiply. `body-tweens.js` gains the kind `KILL` (24 ticks, rank 5), which `playDeath` in [effects-combat.js](../../js/app/renderer/effects-combat.js) starts on the killer of a body eaten in place of `GULP`. `clipForTween` (new, in `clips.js`) maps each `TWEEN` kind to its clip.

Particle motion keeps the `FX_CURVES` table (shape, motion, ease, scale and alpha keys). `fx-draw.js` evaluates it in the vertex node in closed form (drag `k`: `p = p0 + v0 (1 - e^(-k t)) / k`), so particles cost no compute pass and look the same on both backends.

## Architecture

```
worker snapshot ──> interpolateInto (agents) ──> agents-pack ──> agent-draw (5 instanced meshes, model + clips)
               ├──> trackHerds (herds by slot) ─> herd-pack ──> herd-draw
               ├──> food-pack ──────────────────────────────────> food-draw
               └──> world-pack (patches, zones, clouds, motes) ─> world-draw
effect records ──> effects-player ──> body tweens (clips), fx-ring ──> fx-draw (closed-form particles, flashes)
                                   └─> mate threads, pursuits, pointers ──> line-pack ──> line-draw
pheromone field ──> contour-draw (scent lens iso-lines)
stage: WebGPURenderer (WebGL2 fallback), MSAA 4x, ortho camera, black clear, layers back to front
```

Every `*-draw.js` module is a thin GPU shell over a pure packer (`*-pack.js`, `herd-track.js`, `fx-ring.js`) that is unit tested.

### Stage

`stage.js` replaces `scene.js`. `createStage` is async: it builds `new WebGPURenderer(stageOptions(params))` (`three/webgpu`), awaits `renderer.init()`, appends the canvas and returns `canvas`, `renderer`, `backend`, `resize`, `draw`, `rebuild`, `isLost` and `dispose`.

- `stageOptions` (pure, in `stage-options.js`): `antialias: true`, `samples: 4`, `alpha: false`, `depth: false`, `stencil: false`, `powerPreference: 'high-performance'`; `trackTimestamp` with `?gputime=1`; `forceWebGL` with `?backend=webgl2`.
- After `init`, `renderer.backend.isWebGPUBackend` names the backend; the stage logs `RendererReady`.
- `setPixelRatio(1)` and `setSize(width, height, false)` in device pixels from `canvasPixelSize` (`MAX_PIXEL_RATIO` 2 stays, so a 3840x2160 canvas at ratio 1.5 or 2 draws at native resolution).
- One `Scene`, one `OrthographicCamera`, `autoClear` on with clear colour `#000000`; layers mount in the order of the Layers table, `renderOrder` by position; every material has `depthTest` and `depthWrite` false.
- The stage assigns `renderer.onDeviceLost`: it marks the stage lost, logs `DeviceLost` and rebuilds the renderer and every layer once, then logs `DeviceRestored`. A second loss within 10 s logs `RendererFailed` and shows the render failure message. `DeviceLost` and `DeviceRestored` replace the `ContextLost` and `ContextRestored` app events; the WebGL2 backend's context loss takes the same path.
- `renderer.init()` rejecting logs `RendererInitFailed` with the message and shows the render failure message.
- The render failure message (`showRenderFailure`, new, in `js/app/ui/render-failure.js`): "This browser could not start the GPU renderer (WebGPU or WebGL2)." over the black canvas. The `<noscript>` text in `index.html` names "WebGPU or WebGL2".

Season motes are seeded per world (`createPrng`), keep their positions across seasons and change model and role with `frame.season`; over the last 5% of a season (`seasonProgress` over 0.95) each mote switches at its own seeded moment, so the change ripples across the map. Winter motes gather on the cold margins (density by how deep their row is in the cold margin, `terrain.coldMarginWidth`).

### Agents

`agents-pack.js` keeps its buckets (pose, colour, state, extra, motion, tween, body). Its packing adds:

- `color.rgb` is the rim colour from `palette.js` and the family slot; energy sets the fill share (0.18 at 0, `FILL_SHARE` at full), never the rim brightness.
- `tween.x` holds the clip id from `clipForTween`; the jaw value and the state bits pick the loop clips in the node.

`agent-draw.js` builds one `InstancedMesh` per spec from `modelMaterial(model, clips)`. The vertex node places the quad, scaled to cover `modelBounds` after its clips' extreme keys; the fragment node evaluates the parts' distances under their clip transforms and writes rim and fill coverage.

### Herds

`herd-track.js` blends herd animals between the two held snapshots as `interpolateInto` blends agents: matched by slot, position and heading blended at the same alpha (the heading by the shorter arc), unmatched animals at their newest position. A matched pair further apart than `herdRunSpeed` times the ticks between the snapshots plus `herdRadius` is a reused slot (a calf born into a dead animal's slot) and is not blended. Herds move at the frame rate.

The snapshot herd record (`writeHerds` in [snapshot.js](../../js/sim/snapshot.js)) carries the animal's slot as a `u32` in word 2 in place of the radius; `ready.info` gains `herdRadius` and `herdRunSpeed`. The record stays 6 words. Nothing the sim computes changes: `worldHash`, the goldens, the effect stream and `rulesHash` stay as they are.

`HERD_FIELD` (new, in [snapshot-view.js](../../js/app/snapshot-view.js)):

| Word | Field              |
| ---- | ------------------ |
| 0    | `X` (f32)          |
| 1    | `Y` (f32)          |
| 2    | `SLOT` (u32)       |
| 3    | `SPEED` (f32, 0-1) |
| 4    | `HEADING` (f32)    |
| 5    | `GROUP` (u32)      |

### Effects

The data side stays: `effects-player.js`, `effects-combat.js`, `effects-life.js`, `effects-signals.js`, `effects-flee.js`, `effects-terrain.js`, `effects-world.js`, `effects-weather.js`, `effects-edges.js`, `client-kinds.js`, `flag-edges.js`, `food-grid.js`, `flora-colors.js`, `herd-colors.js`, `rock-shape.js`, `refuge-occupancy.js`, `body-tweens.js`, `fx-recipes.js`, `fx-curves.js` (without `curveUniforms`), `fx-budget.js`, `fx-names.js`, `fx-log-overlay.js`, `fx-demo.js`, `mate-threads.js` (the pool), `trails.js` and `fx-pointers.js` (the data).

- `fx-ring.js` is the pure half of `fx-pool.js`: `createFxRing`, `spawnFx`, the rebase and the dirty range. `FX_CAPACITY` is 4096.
- `fx-budget.js` loses `setFxLook`, `setFxQuality` and the level index of `FRAME_CAP`; `adaptFxBudget` alone scales counts, between `MIN_SCALE` and `MAX_SCALE`.
- `fx-recipes.js` keeps every recipe name, family and shape; part colours take palette roles, and a part with `flash` set writes into the flash layer instead of the pool.

### GPU time

`gpu-time.js` (new, replaces `gpu-timer.js`) calls `renderer.resolveTimestampsAsync('render')` with one call in flight, divides the summed milliseconds it returns by the frames drawn since the previous resolve, and keeps the ring `__perf` reports as `gpuMs`. An `undefined` result (no `trackTimestamp`, or no `timestamp-query` feature) records nothing, and `browser.gpu_frame_p95_ms` is `null`. `scripts/lib/perf-v6-run.mjs` loads the page with `&gputime=1`.

## Decisions

| Decision                                                      | Reason                                                                                                                           |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Particles in closed form in the vertex node, no compute pass  | The same look on WebGPU and the WebGL2 fallback and no per-frame dispatch, which holds the rule that load never changes the look |
| The herd slot replaces the radius word in the snapshot        | Herds need an id to interpolate; the radius is a config constant; the record keeps its size                                      |
| A distance rule detects a reused herd slot                    | The sim keeps no herd generation, and adding one changes `js/sim` state; a calf never moves a herd run in one interval           |
| No `?renderer=` switch                                        | The user (2026-11-14): one all-out replacement pull request                                                                      |
| The before numbers live in this doc and the pull request body | `bench/browser-baseline.json` holds one record per viewport, which the after run replaces                                        |
