# Unit knockout

**Status:** In progress - Phase 1 (T1 to T8) is built and on main in season 11, off by default (`unitKnockoutRate` 0); T9 (the screen and ladder grids) is built. The rate screen E-UK-1 (T10), the 64-seed eval, the ladder and drills, and the adopt-or-delete call are open.
**Validated:** 3c6f1225 (2026-11-21)
**Scheduled by:** [training-loop.md](training-loop.md) step 2 - silencing one hidden unit lifts a champion from 6 to 24 of 128 on `prey-ahead`, a gain no small weight step reaches; cheap and needs no sim rule
**Depends on:** [brain-inspection.md](brain-inspection.md)

A birth can carry a **knockout**: one hidden unit of the child's brain is switched off for life. The unit's state stays at 0, so none of its outgoing weights reach another unit or an output. The knockout is heritable, travels with the unit's gene block through crossover, and reverts when a later mutation hits the same gene. Evolution then reaches, in one step, the kind of edit that brain inspection made by hand.

Scope: the knockout operator, where births call it, the leak-rate mapping that makes a knocked unit silent, the metrics that read knockouts, and the measurement that adopts or deletes it. The rest of the brain mutation operator (sparse mutation, silent-row decay, step sizes) belongs to [brain-capacity-and-memory.md](brain-capacity-and-memory.md) and [evolution-rework.md](evolution-rework.md), and does not change here.

## Nature model

- Loss-of-function mutations (gene knockouts) are a common class of spontaneous mutation. Most are neutral or harmful; some are adaptive. In the long-term evolution experiment with _E. coli_, the loss of the ribose operon rose early in all 12 populations.
- A silenced gene keeps its sequence, which then drifts under no selection, as a pseudogene does. A rare back-mutation restores a working gene, usually weaker than the original.
- Here a hidden unit is the gene. The knockout freezes the unit's state at 0; its incoming and outgoing weights stay in the genome and keep mutating like any other gene. A mutation of the unit's leak gene restores the unit as a very slow one (leak gene -4).

## Knockout

| Item            | Rule                                                                                                                                                                                                                                                                                                                                                                  |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Marker          | The unit's leak gene (block `leakStart`, one per hidden unit in `brainLayout` in [brain-layout.js](../../js/sim/brain-layout.js)) at or below `KNOCKOUT_LEAK_GENE` (-8) in `js/sim/traits.js`. `isKnockedOut(gene)` in the same file tests it                                                                                                                         |
| Silence         | `leakRateOf` in [traits.js](../../js/sim/traits.js) returns 0 for a knocked gene, so `applyGenes` writes `leakRate` 0. The kernel's hidden step is `(1 - a) x old + a x tanh(sum)`; with `a` 0 and a hidden row that starts at 0 (a fresh slot is zero, and `freeAgent` in [world.js](../../js/sim/world.js) zeroes a freed one), the unit reads exactly 0 every tick |
| Plasticity      | The Hebbian step (`hebbian_step` in `wasm/src/brain.rs`) moves the unit's `fastOut` row toward its `wOut` row, but the row is multiplied by the unit's state, 0, so it reaches no output                                                                                                                                                                              |
| Operator        | `knockOutUnit(row, layout, rng, rate)` in `js/evo/unit-knockout.js` (new). Rate 0 draws nothing and returns -1. Otherwise it draws one `nextFloat`; below `rate` it draws one `nextInt(rng, layout.hidden)`, writes `KNOCKOUT_LEAK_GENE` to that unit's leak gene and returns the unit, else returns -1                                                               |
| Already knocked | Knocking a knocked unit writes the same value; the row is unchanged                                                                                                                                                                                                                                                                                                   |
| Revert          | `mutateWeights` in [mutation.js](../../js/evo/mutation.js) steps the leak gene by `TRAIT_SIGMA` and clamps to `WEIGHT_CLAMP`, so any mutation of a knocked gene writes -4: the unit returns with `leakRateOf(-4)` (0.038 at `leakMin` 0.02)                                                                                                                           |
| Inheritance     | `crossNeurons` in [crossover.js](../../js/evo/crossover.js) copies leak gene `h` with neuron `h`'s block, so a knockout passes to a child with the unit it silences                                                                                                                                                                                                   |
| Kin             | The genetic distance in [genetics.js](../../js/sim/genetics.js) does not sample leak genes, so a knockout does not change kin recognition                                                                                                                                                                                                                             |
| Files           | -8 is a valid float32 in every genome, archive and champion file; `BRAIN_LAYOUT_NAME` stays `pooled-v5`. Mutation and random initialisation keep a leak gene within plus or minus 4, so a saved genome with no knockout holds no gene at or below -8                                                                                                                  |

> Note: the knockout is the genome form of brain inspection's `silence` edit with `silenceHook`. A silenced unit's state is computed but every weight that carries it is 0; a knocked unit's weights are intact but its state is 0. Every other unit and every output receive the same sums, so a drill replays the same trials with the same outcomes either way (pinned by `test/evo/unit-knockout.slow.test.js`).

### Where births call it

`knockOutUnit` runs after `mutateWeights` wherever a mutated row is written from a config, with `rate` = `unitKnockoutRate`:

| Call site                                                                                   | Rows                                      | Stream       | Log `source`        |
| ------------------------------------------------------------------------------------------- | ----------------------------------------- | ------------ | ------------------- |
| `childBrain` in `createBirth` in [natural-birth.js](../../js/evo/policies/natural-birth.js) | every mate and split birth                | `mutation`   | `mate`, `split`     |
| `seedBrain` in [map-elites-seed.js](../../js/evo/policies/map-elites-seed.js)               | a mutated archive seed                    | `brain-init` | `archive`           |
| `seedUnarchived` in [map-elites-seed.js](../../js/evo/policies/map-elites-seed.js)          | a mutated champion seed                   | `brain-init` | `champion`          |
| `breed` in [learn-probe.js](../../js/evo/learn-probe.js)                                    | each mutated child of a lesson population | the probe's  | none (no world log) |

`createRandomBrain` in [random-brain.js](../../js/evo/policies/random-brain.js) shares `childBrain`, so its births knock too, with no `UnitKnockedOut` (it passes no log). An unmutated clone, a pool founder and a random genome are not knocked. In `childBrain` the order is: `mutateSigma`, crossover or copy, `applyBirthReflex`, `mutateWeights`, `knockOutUnit`, then `decaySilentInputs`.

### Neutral share

A unit with no effect on survival is knocked out with a long-run probability of about `(p / H) / (p / H + r)`, where `p` is `unitKnockoutRate`, `H` is `brainHidden` (32) and `r` is the per-gene mutation probability (`resolveMutationRate`; `invsqrt` gives 0.01425 on the 4926-gene `pooled-v5` row at 32 hidden):

| `unitKnockoutRate` | Neutral share |
| -----------------: | ------------: |
|               0.01 |         0.021 |
|               0.03 |         0.062 |
|                0.1 |         0.180 |

`eval.knockout_unit_share` under the neutral share means selection removes knockouts; over it means selection keeps them.

## Metrics

| Metric                            | Module                                              | Counts                                                                              | Status at Phase 1 |
| --------------------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------------- | ----------------- |
| `eval.knockout_unit_share`        | [metrics-memory.js](../../js/evo/metrics-memory.js) | Knocked hidden units over all hidden units of the agents sampled at each checkpoint | `unverified`      |
| `eval.knockout_unit_share.hunter` | [metrics-memory.js](../../js/evo/metrics-memory.js) | The same over sampled agents whose specialisation `canHunt`                         | `unverified`      |

`addLeak` in `metrics-memory.js` and `lifeLeak` in [metrics-leak-skill.js](../../js/evo/metrics-leak-skill.js) leave knocked units out: the leak sum, `slowUnits`, `floorUnits` (a knocked gene is under `FLOOR_GENE`) and the divisor count working units only, and an agent with every unit knocked adds nothing (its mean is NaN and is skipped). So `eval.leak_rate_mean`, `eval.leak_slow_share`, `eval.leak_at_floor_share`, `eval.leak_lineage_spread` and the `eval.leak_*_corr` metrics read the working units only. `eval.hidden_persistence` needs no change: a unit at 0 adds nothing to its cosine.
