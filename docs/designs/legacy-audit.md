# Legacy audit

**Status:** Reference - defects and inefficiencies in the legacy app (`js/*.js`), by file and symbol, each with the doc that removes it.
**Validated:** bd49bce (2026-10-11)

Each finding names the file, the symbol, what the code does and what that breaks. Findings have stable ids
(`NN-2`, `FIT-4`) that other design docs cite as evidence.

- Nothing here is fixed in place. The **Removed by** column names the design doc whose replacement module makes the
  finding obsolete; the legacy file is deleted in `worker-and-renderer.md` Phase 3.
- Planned docs: `headless-sim-core.md`, `evolution-evals.md`, `evolution-rework.md`, `worker-and-renderer.md`.
- A finding that no longer matches the code is removed in the PR that changes the code, and the stamp is restamped.

## Neural network

All five specialisations in `AGENT_CONFIGS` ([agents.js](../../js/constants/agents.js)) use `hiddenSize: 64`.

| Id   | Finding                                                                                                                                                                                                                                                                                                                                                                                   | Where                                                                                                   | Removed by                                                             |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| NN-1 | The WGSL shader declares `var hidden: array<f32, 32>` and loops to `hiddenSize` (64). Dawn and Tint clamp the out-of-bounds index, so units 32-63 all write `hidden[31]`: hidden units 31-63 and the recurrent state they feed are wrong.                                                                                                                                                 | `createPipelineForSpecialization` in [gpu-compute.js](../../js/gpu-compute.js)                          | `headless-sim-core.md` (`forwardAll` in `js/sim/brain.js`)             |
| NN-2 | Inputs are packed at each agent's index in this tick's `validAgents`, but weights are uploaded only for agents `checkWeightChanged` flags. When an agent dies or is born, later agents shift index and run on the weights left in that slot by the previous occupant, until the next `cleanupWeightCache` or buffer reallocation. Behaviour and fitness are credited to the wrong genome. | `processSpecialization`, `checkWeightChanged` in [gpu-compute.js](../../js/gpu-compute.js)              | `headless-sim-core.md`                                                 |
| NN-3 | `checkWeightChanged` compares the first weight of each matrix and, when they match, reports the weights unchanged without hashing; the full `fastHashWeights` samples at most 15 weights per matrix.                                                                                                                                                                                      | `checkWeightChanged`, `fastHashWeights` in [gpu-compute.js](../../js/gpu-compute.js)                    | `headless-sim-core.md`                                                 |
| NN-4 | `weightCache` is keyed by `Agent` object. The in-step dead-agent cleanup deletes by `agent.id` from a list already filtered to living agents, so it never removes an entry. `cleanupWeightCache` tests the object keys against a `Set` of ids, so it clears the whole cache whenever it runs.                                                                                             | `processSpecialization`, `cleanupWeightCache` in [gpu-compute.js](../../js/gpu-compute.js)              | `headless-sim-core.md`                                                 |
| NN-5 | Weights whose dimensions do not match the architecture are replaced with random weights and written back to `agent.gene.weights`; the agent keeps its `geneId`, lineage and accumulated fitness.                                                                                                                                                                                          | `NeuralNetwork` constructor in [neural-network.js](../../js/neural-network.js); `processSpecialization` | `evolution-rework.md` (`js/evo/genome.js` rejects a mismatched genome) |
| NN-6 | `NeuralNetwork.forward` returns `hiddenState` and `output` arrays from the module-level `neuralArrayPool`. `Agent.think` keeps `result.hiddenState` as `this.hiddenState`, then calls `result.release()`, which returns the same arrays to the pool. The next agent's `forward` overwrites them, so agents share hidden state.                                                            | `forward`, `neuralArrayPool` in [neural-network.js](../../js/neural-network.js); `Agent.think`          | `headless-sim-core.md` (per-agent hidden state in `js/sim/brain.js`)   |
| NN-7 | The CPU path runs when fewer than `minAgentsForGPU` (20) agents are alive, or when a GPU batch is skipped. It multiplies the hidden state by 0.9 after each step; the GPU path does not. The same brain behaves differently by path.                                                                                                                                                      | `Agent.think`, `Agent.update` in [agent.js](../../js/agent.js); `batchNeuralNetworkForward`             | `headless-sim-core.md`                                                 |
| NN-8 | The network has no biases: `weights1` and `weights2` only.                                                                                                                                                                                                                                                                                                                                | `NeuralNetwork` in [neural-network.js](../../js/neural-network.js)                                      | `headless-sim-core.md`                                                 |
| NN-9 | Weights are nested JS arrays. `NeuralNetwork.mutate` rebuilds both matrices with `map` on every call and perturbs every weight.                                                                                                                                                                                                                                                           | `mutate` in [neural-network.js](../../js/neural-network.js)                                             | `evolution-rework.md` (`js/evo/mutation.js`)                           |

## Inputs

Inputs are built per agent per tick by `convertGpuRayResultsToInputs` in [physics.js](../../js/physics.js); the
network's input count is `PERCEPTION_INPUTS` in the `Agent` constructor in [agent.js](../../js/agent.js).

| Id   | Finding                                                                                                                                                                                                                                                                                                                                                                                | Where                                                                                                      | Removed by                                   |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| IN-1 | `PERCEPTION_INPUTS` is a hand-written sum with a `+ 1` "empirical correction"; it is not derived from the code that builds the inputs.                                                                                                                                                                                                                                                 | `Agent` constructor                                                                                        | `headless-sim-core.md` (`js/sim/sensors.js`) |
| IN-2 | The ray one-hot has four slots. Wall and obstacle share `[0,0,0,1]`; a same-size agent is encoded as larger plus smaller `[0,1,1,0]`; kin are not distinguished.                                                                                                                                                                                                                       | `convertGpuRayResultsToInputs`                                                                             | `headless-sim-core.md`                       |
| IN-3 | The six alignment-ray inputs are the constant 0.5.                                                                                                                                                                                                                                                                                                                                     | `convertGpuRayResultsToInputs`                                                                             | `headless-sim-core.md`                       |
| IN-4 | The speed ratio is pushed twice in a row.                                                                                                                                                                                                                                                                                                                                              | `convertGpuRayResultsToInputs`                                                                             | `headless-sim-core.md`                       |
| IN-5 | The rotation-change input is the constant 0.                                                                                                                                                                                                                                                                                                                                           | `convertGpuRayResultsToInputs`                                                                             | `headless-sim-core.md`                       |
| IN-6 | Ray hit types are miscounted downstream of the one-hot: predator threat counts `hitTypeValue === 2` (food), food proximity and food availability count `hitTypeValue === 1` (wall), and mate availability tests `'same_size_agent'` and `hitTypeValue === 6`, which are never produced, so it is always 0. `closestPredatorSizeRatio` is the constant 1.2, so vulnerability is binary. | `convertGpuRayResultsToInputs`                                                                             | `headless-sim-core.md`                       |
| IN-7 | The age input is wall-clock seconds divided by 60 (see FIT-1).                                                                                                                                                                                                                                                                                                                         | `convertGpuRayResultsToInputs`                                                                             | `headless-sim-core.md`                       |
| IN-8 | `gameLoop` traces every agent with `maxRaysPerAgent` from the scout config (24), and the shader spaces rays by 2π/24. A 16-ray agent uses the first 16 rays, an asymmetric 240° arc, while its `rayData` angles use a 2π/16 step.                                                                                                                                                      | `gameLoop`; `batchRayTracing` in [gpu-physics.js](../../js/gpu-physics.js); `convertGpuRayResultsToInputs` | `headless-sim-core.md` (`js/sim/sensors.js`) |

## Fitness

Fitness is `calculateFitness` in [agent.js](../../js/agent.js): `calculateSurvivalScore`, `calculateActionScore` and
`calculateSpecializationScore`, weighted by `FITNESS_CATEGORIES`.

| Id    | Finding                                                                                                                                                                                                                                                                     | Where                                                               | Removed by                                                    |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------- |
| FIT-1 | `Agent.age` is `(Date.now() - birthTime) / 1000`. The survival score, the forager gathering rate and the gene-pool age criterion use it, so fitness depends on frame rate, `gameSpeed` and whether the tab is in the background.                                            | `Agent.update`, `calculateSurvivalScore`, `calculateFitness`        | `evolution-rework.md` (`js/evo/fitness.js`, counted in ticks) |
| FIT-2 | `fit` needs 4 of 6 points, or fitness above `EXCEPTIONAL_FITNESS_THRESHOLD` (2000) alone. Fitness at least `GENE_POOL_MIN_FITNESS` (1750, worth 2 points) plus any two of age, exploration and turns towards food (1 each) qualify an agent that has never eaten.           | `calculateFitness`; [gene-pool.js](../../js/constants/gene-pool.js) | `evolution-rework.md`                                         |
| FIT-3 | Defender score is `framesAlive * 0.3` "guarding", `framesAlive * 0.5` "patrol" while `isInTerritory`, and `framesAlive * 0.1` "mitigation" while `aggression > 0.5`. No ally proximity or interception is measured; a defender scores for being alive.                      | `calculateSpecializationScore`                                      | `evolution-rework.md`                                         |
| FIT-4 | Two similar-size agents in contact exchange `BITE_SIZE * 0.1` energy in a random direction every tick, and the gainer's `foodEaten` rises. `foodEaten` feeds `ACTION_SCORING.FOOD_EATEN` and the `fit` food criterion, so food is farmed by bumping.                        | `checkCollisions` in [physics.js](../../js/physics.js)              | `headless-sim-core.md`, `evolution-rework.md`                 |
| FIT-5 | Several terms are estimates, not measurements: predator damage is `kills * 100`, forager and scout shouts are fractions of food eaten and cells explored, reproducer offspring survival is `offspring * 0.3`, and the scout vision bonus comes from the `maxRayDist` trait. | `calculateSpecializationScore`                                      | `evolution-rework.md`                                         |
| FIT-6 | Forager food efficiency divides current `energy` by `foodEaten`.                                                                                                                                                                                                            | `calculateSpecializationScore`                                      | `evolution-rework.md`                                         |
| FIT-7 | A wall hit subtracts damage from `this.fitness`; the next `calculateFitness` overwrites `fitness`, so the penalty never counts.                                                                                                                                             | `Agent.update`, `calculateFitness`                                  | `evolution-rework.md`                                         |

## Lifecycle and physics

| Id     | Finding                                                                                                                                                                                                                                                                                                                                                                                  | Where                                                                                                             | Removed by                                       |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| LIFE-1 | Each agent queries its quadtree neighbours, so every contact is visited from both sides. Separation, impulse, predation and energy exchange run before the `processedCollisions` check, which gates only mating. Most contacts are resolved twice per tick, which doubles the bump farming in FIT-4.                                                                                     | `checkCollisions` in [physics.js](../../js/physics.js)                                                            | `headless-sim-core.md` (`js/sim/physics.js`)     |
| LIFE-2 | `Agent.update` calls `split()` (when `energy > maxEnergy * 0.8`) and `birthChild()` and drops the returned `Agent`. `split()` halves the parent's energy and increments `offspring`; `birthChild()` consumes a pregnancy whose cost `tryMate` already paid. Either way no child enters the world. `Simulation.gameLoop` separately calls both and queues the child on `agentSpawnQueue`. | `Agent.update`, `split`, `birthChild` in [agent.js](../../js/agent.js); `gameLoop` in [game.js](../../js/game.js) | `headless-sim-core.md` (`js/sim/lifecycle.js`)   |
| LIFE-3 | `pregnancyTimer` advances every iteration in `Agent.update` and once per frame in `Simulation.gameLoop`. Pregnancy length, and whether the child is kept (`gameLoop`) or dropped (`Agent.update`, LIFE-2), depend on `gameSpeed` and the iteration in which mating happened; at speed 1 pregnancy lasts half of `PREGNANCY_DURATION_FRAMES`.                                             | `Agent.update`; `gameLoop`                                                                                        | `headless-sim-core.md`                           |
| LIFE-4 | There is no fixed timestep. `gameLoop` runs `Math.floor(gameSpeed)` iterations per frame and moves agents by a per-iteration velocity with no `dt`.                                                                                                                                                                                                                                      | `gameLoop` in [game.js](../../js/game.js)                                                                         | `headless-sim-core.md`, `worker-and-renderer.md` |
| LIFE-5 | When ray tracing or the GPU network fails, the iteration `continue`s without updating agents, while spawning, food and the frame counter still advance. Without WebGPU (`canUseGpu` false) every iteration skips, so agents never update.                                                                                                                                                | `gameLoop`                                                                                                        | `headless-sim-core.md`                           |

## Selection and persistence

The gene pool is `GenePoolDatabase` in [database.js](../../js/database.js), backed by IndexedDB `BlobEvolutionDB`
version 1, store `genePools` keyed by `geneId` ([database-worker.js](../../public/database-worker.js)).

| Id    | Finding                                                                                                                                                                                                                                   | Where                                                                                     | Removed by                                              |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| SEL-1 | `getRandomAgent` and `getMatingPair` pick a gene pool with `randomGeneId`, uniformly over up to `MAX_GENE_POOLS` (500) pools. A weak pool is chosen as often as the best; selection pressure exists only inside one 10-entry pool.        | `randomGeneId`, `getRandomAgent`, `getMatingPair`                                         | `evolution-rework.md` (`js/evo/archive.js`)             |
| SEL-2 | Only a new `geneId` is re-tested (`ValidationManager`, 2-3 runs). An agent whose `geneId` already has a pool is saved on death with its single-life fitness, and a stored fitness is never re-evaluated.                                  | `gameLoop` death handling; `ValidationManager` in [validation.js](../../js/validation.js) | `evolution-rework.md` (Welford mean, re-evaluation)     |
| SEL-3 | `processQueue` merges existing then new entries and keeps the first occurrence of each `id`, so a re-saved agent with a higher fitness is discarded in favour of its older entry. Duplicate weights under different ids are not detected. | `processQueue`                                                                            | `evolution-rework.md`                                   |
| SEL-4 | `geneId` is a lineage label: splits, births and pool crossovers keep a parent's `geneId`. Pools, validation and renderer meshes are keyed by it, so one pool holds many different genomes.                                                | `birthChild`, `split`; `repopulate` in [spawn.js](../../js/spawn.js)                      | `evolution-rework.md` (genome ids)                      |
| SEL-5 | The crossover branch of `repopulate` calls `spawnAgent` with no `mutationRate`, so children of two pooled parents are never mutated. `getMatingPair` draws both parents from one pool, so crossover never crosses lineages.               | `repopulate` in [spawn.js](../../js/spawn.js); `getMatingPair`                            | `evolution-rework.md` (`js/evo/crossover.js`)           |
| SEL-6 | Stored records hold nested weight arrays with no architecture or input-schema version; a record from an older layout is randomised on load (NN-5).                                                                                        | `queueSaveAgent`; `public/database-worker.js`                                             | `worker-and-renderer.md` (IndexedDB v2 `archive` store) |

| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
