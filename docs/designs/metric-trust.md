The eval metrics are the rules every choice is made by: keep rules, screen verdicts, phase Targets, the training curve and its plateau. All 268 metrics a live report carries are held to the same five checks, and the registry records each:

| Check      | Holds when                                                                                                                                               | Recorded as                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| Definition | One plain sentence says what the metric counts, from which events or fields, in which unit, and when it is `null`                                        | `meaning`, `counts`, `unit`, `nullWhen` |
| Arithmetic | A test feeds hand-built events through `observe` and `computeMetrics` and gets the value the definition gives                                            | `tests.arithmetic`                      |
| Source     | A test runs the real `step` on a scripted world whose answer is known by construction, and the metric reads that answer                                  | `tests.source`                          |
| Liveness   | On the defaults (128 seeds, floor on and floor off) the metric is `null` on at most 10% of seeds and takes at least 2 values, or `expectedFlat` says why | `liveness`, `expectedFlat`              |
| Power      | Split resampling of the 128-seed runs gives its false-positive rate and the smallest change it detects at 16 and 32 seeds                                | `power`, `minSeeds`                     |

A metric with all five is `verified`. A verdict, a keep rule or a screen gate rests only on `verified` metrics; any other metric is reported with its interval and no verdict.

## Registry

`js/evo/metric-registry/` holds the data files of the families, `entry.js` (the entry shape and the `entry` helper) and `index.js`, which merges the families into `METRICS` (a frozen object keyed by full metric name) and exports the type `MetricName` (`keyof typeof METRICS`), `metricName(base, suffix)`, `minSeedsFor` and `DEFAULT_MIN_SEEDS` (moved from `js/evo/compare-seeds.js`). A family of more than 28 entries is split into `<family>-2.js` and `-3.js`, and every file has a mirrored test, `test/evo/metric-registry/<file>.test.js`. Every key in a family file is spelled as a literal, so `MetricName` is a union of names and never `string`. `MetricRecord` in `js/evo/metrics-stats.js` is `Partial<Record<MetricName, MetricResult>>`, the type every producer returns, and `bySuffix(base, suffixes, resultAt)` builds the results of a parameterised metric through `metricName`.

| Field          | Type                                                          | Holds                                                                                                                                                                                                                                                                                  |
| -------------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `family`       | string                                                        | The family file's name (`hunters`, `core`, ...)                                                                                                                                                                                                                                        |
| `module`       | string                                                        | The repo path of the module that computes it                                                                                                                                                                                                                                           |
| `meaning`      | string                                                        | One sentence read first: what a higher value means in the world                                                                                                                                                                                                                        |
| `counts`       | string                                                        | What is counted, from which events or world fields, over which ticks                                                                                                                                                                                                                   |
| `unit`         | string                                                        | `share`, `count`, `per 1k agent-ticks`, `ticks`, `px`, `ratio`, `correlation`, `trend`, ...                                                                                                                                                                                            |
| `direction`    | `higher` \| `lower` \| `watch`                                | What `eval:compare` scores as better                                                                                                                                                                                                                                                   |
| `intended`     | `higher` \| `lower`                                           | For a `watch` metric, the direction `eval:power --include-watch` plants                                                                                                                                                                                                                |
| `nullWhen`     | string[]                                                      | Each `none` reason the module can give                                                                                                                                                                                                                                                 |
| `expectedFlat` | string \| null                                                | Why the metric is `null` or constant on the defaults (the feature or config that makes it move), or `null`                                                                                                                                                                             |
| `renamedFrom`  | string[]                                                      | Old names; `eval:compare` reads an old report through them                                                                                                                                                                                                                             |
| `deprecated`   | string \| null                                                | Why the metric is kept unverified until its deletion task, or `null`                                                                                                                                                                                                                   |
| `tests`        | `{arithmetic: string, source: string}`                        | Repo paths of the tests that pin it; each file names the metric                                                                                                                                                                                                                        |
| `liveness`     | `{nullShare, distinct, report}` \| null                       | From the T22 runs                                                                                                                                                                                                                                                                      |
| `power`        | `{fpr16, fpr32, mde16, mde32, referenceMean, report}` \| null | From the T27 read; `referenceMean` turns the detectable change, a fraction of the mean, into an absolute one                                                                                                                                                                           |
| `minSeeds`     | 16 \| 32 \| 64 \| null                                        | The fewest seeds a verdict needs; `null` when no seed count meets the power bar. Until Phase 4 every entry is `null`, and `minSeedsFor` gives the legacy 32 of `eval.floor_episodes`, `eval.lineages_alive`, `eval.lineage_turnover` and `eval.predator_share_cv`, and 16 for the rest |

`metricStatus(entry)` in `js/evo/metric-registry/status.js` computes the status, which no file writes: `deprecated` when `deprecated` is set; `verified` when `tests.arithmetic`, `tests.source`, `liveness` (meeting the liveness bar, or with `expectedFlat`) and `power` are filled and `minSeeds` is not `null`; `unverified` otherwise.

The **power bar** at a seed count: the false-positive rate is at most 0.10, and the smallest detectable change is at most 0.20 of the reference mean. A metric of unit `share` uses an absolute 0.05 in place of the relative bar, and one of unit `correlation` or `trend`, or with a reference mean within 0.01 of 0, uses an absolute 0.10.

## Source tests

A source test runs `step` on a world from `test/evo/helpers/` with scripted controllers, then `computeMetrics`, and asserts a value known by construction. Where an exact value cannot be planted, it asserts the two ends (a controller that never does the thing reads 0; one that always does reads the full value) and one middle point. Every source test plants one event in the final tick and one in the tick a body dies, and asserts both are counted.

### One kill

`isDeliberateKill(world, victim)` in `js/sim/kills.js` is the only rule for a kill: the victim died of a bite, the fatal bite was deliberate, and its biter has `canHunt`. The fatal bite's own deliberateness is recorded when the bite lands (`lastBiteDeliberate` is set before the victim is freed), so a bite in the tick a body dies counts.

| Counter                                                                                                                                  | Outside `worldHash` | Uses `isDeliberateKill` from                                 | A dead killer                      |

| `noteLedgerKill`, `HunterKill` events                                                                                                    | yes                 | T14                                                          | credited                           |
| `noteBiteLedger`: a fatal bite that is a kill books kill energy; any other fatal bite books bite gain (`hunterIncomeBySpec` kind `BITE`) | yes                 | T14                                                          | credited                           |

`test/evo/kills.agreement.slow.test.js` (the sim counter against the observer) is extended to the ledger and the events.

### When a metric reads

Metrics read synchronously: `step` clears the event ring (`clearEvents`) at its start, `feedPolicy` calls `observe` after every step including the last, and `computeMetrics` runs once on the finished observer. `pushEvent` throws on a full ring, so no event is dropped silently. The worker pool and the log file are the only asynchronous parts, and both are awaited (`runPool`, the replay log's `close`).

### Invariants

`test/evo/metric-invariants.slow.test.js` runs the live defaults for 20000 ticks on 4 seeds and checks:

- The sum of `kills` over `HunterLedger` records equals the count of `HunterKill` events, and every life with kill energy above 0 has at least 1 kill.
- `eval.hunter_income_share.kill`, `.bite`, `.carcass` and `.herd` sum to 1 when any is not `null`.
- Every `*_share` metric is in [0, 1]; every `*_per_1k` metric is at least 0.
- `eval.birth_source_share.*` sums to 1; `eval.births_per_1k` equals mate plus split births per 1000 agent-ticks.
- `eval.prey_summer_min` is at least the trace's lowest prey count after burn-in.
- A report from the worker pool (`runPool`) equals `computeMetrics` on the same seed run in-process, metric by metric.

## Verdicts

- `compareReports` takes direction, `minSeeds` and `renamedFrom` from `METRICS` (T8 built the direction and `minSeeds` part; a name absent from the registry, other than a `bench.`, `browser.` or fitness-prefixed one, has no direction and is `unknown metric`, not `higher`). A row for a metric that is not `verified` prints `unverified` in place of a verdict, and `--fail-on-worse` ignores it.
- `keepRule(before, after)` in `js/evo/keep-rule.js` is the no-harm test of `docs/principles.md`: a paired bootstrap on the share of seeds with hunters alive at the last tick and the share ending under 80 agents, plus every `verified` guard, each `worse` only when the interval excludes 0. The adoption bar of principles.md (12 of 16 alive, no more seeds under 80 than the defaults) is printed beside it as counts with their intervals and is unchanged. `npm run screen` and `npm run eval:compare -- --keep-rule` print both.
- The screen table prints each arm's interval beside every seed count, and its gate criteria read only `verified` metrics.
