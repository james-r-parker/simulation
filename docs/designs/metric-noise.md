## Contract

The inventory includes registered metrics whose current `metricStatus` is `unverified`, in `Proposed` or `In progress`
docs. It expands trailing wildcards against the registry. It includes Targets in built phases of active docs and
conservative references in done/prediction paragraphs, tables and labelled sections, including task rows that ask for
a prediction. Such a reference identifies a dependency to review, not proof that every named plan is presently stalled.
Explicit declarations of no baseline prediction do not create a dependency. Implemented, Reference, Superseded and
unregistered future metrics are outside this inventory. This doc is excluded from its own scan.

`findTargets` in [scripts/lib/metric-noise.mjs](../../scripts/lib/metric-noise.mjs) returns each name once with its
source plan, line and context. `--references` exposes those locations for auditing; committed prose links files,
not line numbers. `metricStatus` and `meetsPowerBar` remain authoritative.

Power uses [defaults-floor-on-E276.json](../../evals/power/defaults-floor-on-E276.json): 128 seeds, 200000 ticks,
`rulesHash` `4110c4d043dd1658` (season 12 after step 5; E254 read season 11). The [triage](../../evals/power/unverified-2026-11-19.md) is context, not a frozen
membership list. Each command is single-process and starts no simulation; at most four disjoint metric batches run concurrently:

```bash
npm run eval:power -- evals/power/defaults-floor-on-E276.json --include-watch --sizes 16,32,64 --metrics "$(node scripts/metric-noise.mjs --metrics)" --json
```

The saved reading is `evals/power/metric-noise-E276.json` (`BASELINE` in `scripts/metric-noise.mjs`), with the source SHA-256 and batch membership. Each metric/size has its own deterministic RNG fork, so disjoint batches reproduce the combined command. It uses the default 1000 A/A
splits and 200 splits per planted change. FPR must be at most 0.10; MDE must be at most 0.20 relative, 0.05 absolute
for `share`, or 0.10 absolute for `correlation`, `trend` and means within 0.01 of zero. Other units retain their registry
bar, even units named `share difference` or `share change`. Relative MDE is multiplied by the absolute reference mean
for the near-zero and correlation/trend checks. A missing reading fails; no extrapolation beyond 64 is a pass.

A power pass alone does not update registry status, fill missing arithmetic/source tests, fix null coverage, or give a
watch metric a directional verdict. Phase 2 closes the remaining trust checks before a plan uses a replacement.
E276 measures the defaults at its recorded rules, not every future treatment or longer window.

**Targets:** none - detector definitions and trust checks only; no change to a scene's frequency is claimed.

Every Phase 1 metric failing through 64 has a candidate below. A candidate is a variance hypothesis, not a verified
replacement. New names are literal registry entries beside the old names; existing computations and names stay intact.
A longer observation window uses 600000 ticks, with complete 144000-tick years after burn-in, and keeps the same
within-window event rules. More ticks can reduce within-run noise but cannot guarantee removal of between-seed noise.

Pooled definitions carry per-seed numerator/denominator sufficient statistics in the report. Their estimate is the ratio
of sums; bootstrap and A/A split resampling resample whole seeds and recompute the ratio, rather than averaging seed

validation and round-trip tests in the same replacement chunk.

Median candidates estimate a typical seed rather than an event-weighted world. Longer-window and per-life candidates
also change the interpretation of a plan's numeric bar. The adopting plan rewrites its prediction and done bar before
any treatment run; old and new bars are never silently interchangeable. A median with a majority of zeros is refused.
