# Brain capacity and memory

**Status:** In progress - the big bang (user, 2026-10-30): the instruments, the probes and a chosen brain (sparse mutation, silent-row decay, early memory, a lower leak floor, the skip block, no `SPLIT` genes) built as the defaults on the natural-selection big-bang branch, one PR (chunk B3 built the skip block, the deleted `SPLIT` genes, the silent-input mask as world state and the four defaults; `instinctWeight` 1 is a default from the survival screen; the long goldens are re-pinned); the experiments follow as tuning screens on the new world.
**Validated:** d8a8561 (2026-10-29)
**Priority:** 3 - measurement before redesign: a brain experiment judged by `fitnessV1` measures the wrong thing, so it queues after natural-selection.md (Priority 1), which closes fitness-and-selection.md Phase 4 (user, 2026-10-29)
**Depends on:** [natural-selection.md](natural-selection.md), [fitness-and-selection.md](fitness-and-selection.md) (Phase 4), [evolution-evals.md](evolution-evals.md), [world-balance.md](world-balance.md) (Phase 3, built)

Every blob thinks with one Elman recurrent network of 32 leaky hidden units. How much of that network evolution uses, and whether the mutation operator and the input code let it be used, is unmeasured. This doc measures first -
mutation drift, input sparsity, memory, leak rates, plasticity - and changes the brain only where the measurements show
a gain. The purpose is to find the best option for this world and adopt it: config keys and a layout version are only
the mechanism for comparing options, each experiment phase ends by making its winner the live default and removing
the losing options, and nothing is left built but switched off.

A change is adopted when it helps evolution discover more sophisticated behaviour, not when it only makes the brain
more complex.

More sensors or more hidden units are refused as a substitute for a scene ([principles.md](../principles.md)). A
size, layout or input change is adopted only when a named scene is impossible, or a scene detector stays flat, with the
senses and memory the blob already has. Every experiment names the scene it serves (the Scene column of the table
below), and its verdict cites that scene's detector from [natural-selection.md](natural-selection.md).

The project goal is worlds that are interesting to watch. The brain is the ceiling on what a blob can do, so the
read-out is behaviour, not weights:

- **Individual:** deliberate hunting and foraging, evasion, remembering where food was.
- **Social:** coordinated hunting, flocking, calling and answering, group defence.
- **Long-term:** migration, territory, seasonal adaptation.
- **Surprise:** behaviours the metrics were not written for.

Scope: the mutation operator and initialisation of the brain genome, the input representation, brain size, the leak
floor, Hebbian learning, the memory read-back, and the metrics and probes that tell them apart. Out of scope: new
architectures (GRU, LSTM, attention), new sensors, new outputs, the world rules and the fitness function. Phase 4 ends
with a verdict on whether a new architecture is worth a doc of its own; it builds none. GRU, LSTM and hidden layers
larger than the sweep stay out until the mutation, input-code and probe fixes below are measured: a bigger or gated
net cannot cure a horizon limit or an input code that cancels, and the probes and long-horizon metrics say which it is.

The ordering constraint with [evolution-rework.md](evolution-rework.md): its Phase 3 trainer bakes the genome layout
into champions, so Phase 4 of this doc lands before that trainer is built.

### Layout `pooled-v2`

The only layout, built by the natural-selection big bang (`js/sim/ray-pool.js` and `js/sim/brain-layout.js`, with the
discrimination checks of T10b). `elman-v1` and the `brainLayout` key are deleted. Phase 1 describes and measures this
layout as built before B3: 81 inputs, the `SPLIT` column kept and no skip; B3 added the skip block and removed the `SPLIT` genes.

- **Pooled inputs.** For each of eight channels (food, can-bite-me, can-bite-it, other, kin, wall, obstacle, smoke) the
  brain reads the **two strongest hits** over the 16 rays, strongest first, each as a strength `s` (the ray's proximity)
  and the cosine and sine of that ray's angle in the agent's own frame. An unused slot is 0 in all three values (a channel
  with one hit leaves its second slot 0; the first ray wins a tie). That is 8 x 2 x 3 = 48 values, then the 33 body inputs
  (the 35 of `elman-v1` less the season sine and cosine): 81 inputs instead of 179. A proximity-weighted sum of x and y is
  not used because it cancels (food left and right gives none; a corridor gives no wall). The strength of can-bite-me
  (threat), can-bite-it, other and kin is the channel value of the strongest ray, which already holds the ray's
  proximity. The strength of food, wall, obstacle and smoke is the proximity channel of the nearest ray with the flag
  set, because the flag itself is 1. Every pooled input lies in [-1, 1] (strength 0 to 1, cosine and sine -1 to 1):
  `randomWeights` assumes inputs of order 1, and a sum of 16 rays would saturate `tanh` at birth.
  `poolRays` writes them into a `pooled` row per slot in the brain phase with a two-slot insertion per ray and no
  allocation. The `inputs` row keeps the raw rays, so the observer, the life counters and the renderer read what they read
  now. The top 2 are what lets two targets of one channel on opposite sides, or the two walls of a passage, reach the
  brain at all; the discrimination checks (below) measure how far that goes. The sensory audit (T14) may amend this list,
  the channel set or the ranges; an amendment is a layout revision screened in `E53` beside the skip arms.
- **Skip** (built, no key). A `wSkip` block from the 48 pooled values to the outputs that have genes (10 without `SPLIT` genes, 11 with), added
  to the output sums before `tanh`, so reflexes (food ahead to thrust, threat to turn away, prey in reach to bite) need
  no hidden unit. The skip sees only the pooled rays, not energy or mate-ready; those stay among the 33 body inputs
  (33 of the 81 inputs).
- **No season inputs.** The sine and cosine of the year phase are deleted (`seasonInputs` never shipped as a key). The
  blob is not told the calendar; it feels the season through its temperature inputs and the food on its rays
  (principles.md, "senses are local"). The body block is 33 inputs; the observer, the inspector labels and
  `inputActivity` follow.
- **No `SPLIT` genes** (built, no key). The `SPLIT` output column keeps its slot in the 11-wide
  output row (indices unchanged) and has no weight, bias or Hebbian update; it reads 0.
- **Genome length** is the Genome sizes table: `brainLayout(config).weightCount` for the hidden width (4,494 at 32). The
  output blocks `wOut`, `bOut` and `wSkip` have `geneOutputs` (10) columns, gene column `g` driving output
  `GENE_OUTPUTS[g]` (`js/sim/brain-layout.js`: every output but `SPLIT`). Random skip weights have standard deviation
  `1 / sqrt(48)`, crossover takes each output's skip column whole from one parent, and the skip block is genome only
  (no Hebbian update).
- `brainLayout(config)` returns the offsets; the genome, champion and archive `layout` field carries the input and output
  counts, and `assertGenomeFits` and `validateChampion` reject a mismatch naming it.

### Discrimination checks for `pooled-v2`

`js/evo/pool-discrimination.js` stages scenes where different situations need different actions and scores a scripted
controller (`../../js/evo/scripted.js` style) that reads the pooled row against one that reads the raw rays. Both run
on the same seeded scenes; the check passes when the pooled controller scores within 10% of the raw-ray controller.

| Scene               | Staging                                                                                                        | Score                                     |
| ------------------- | -------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `two-food-opposite` | Two food items at equal range on opposite sides of the agent                                                   | Share of trials that eat both             |
| `two-threats-apart` | Two scripted `hunter`s closing from different sides                                                            | Share of trials alive after 300           |
| `corridor`          | Walls left and right, food ahead and food behind (a passage; a single strongest wall hit per channel is wrong) | Share of trials that reach the food ahead |

The first run, on the strongest hit per channel (24 pooled values, 57 inputs), scored `two-food-opposite` 1.00 pooled to
1.00 raw, `two-threats-apart` 0.69 to 0.88 and `corridor` 0.00 to 1.00, so the plan's rule added the top-2-per-channel
variant before the switch: 8 channels x 2 hits x 3 values = 48 pooled values and 81 inputs. The scenes did not change; the
pooled controllers now read both hits (`flee` sums the two threat hits, `followCorridor` averages the lateral push of the
two obstacle hits). The result on the built layout is in `sim-notes.md` ("Top-2 pooled rays"). `E53` judges `pooled-v2` on `eval.catch_rate`, `eval.pursuit_kill_share`, `E53` judges `pooled-v2` on `eval.catch_rate`, `eval.pursuit_kill_share`,
`eval.escape_rate` and `eval.evasion_skill` as well as `eval.deliberate_food_share`.

## Metrics

All are computed in `js/evo/` from the observer and the world, reported by `computeMetrics`, and accepted by
`validateReport` when present. They are observational: nothing in `js/sim/` reads them. The checkpoint-sampled agents
are the existing `sampleSlots` result in `../../js/evo/observer-checkpoint.js`; the new samplers read it and make no
draw of their own, so `observer.rng` draws and `eval.diversity` are unchanged. Each metric is `watch` in
`DIRECTIONS` (`../../js/evo/compare.js`) until `E48`'s `eval:power` figures say which have a direction worth
enforcing. A `null` is `none(reason)` (`../../js/evo/metrics-stats.js`).

Cost: the per-tick work is the memory-output statistics (every 4 ticks) and the input-activity sample (every 16 ticks);
everything else runs at the checkpoint on its sampled agents or at death. Buffers are sized at observer creation and the
hot path allocates nothing. The budget is 0.05 ms per tick at 500 agents on top of the observer budget in
fitness-and-selection.md (0.25 ms).

## Memory probes

The metrics show what the population does. A probe shows what one brain can do, in a staged world with a known answer.
`js/evo/memory-probe.js` (pure: no files, no clock) builds each scenario from a seed, runs a genome through it on a
headless world, and returns a score. The arena follows `../../test/sim/helpers/predator-arena.js`: an empty world with
no floor and no immigrants.

Two controls separate memory from reflex. Both overwrite the agent's `inputs` and `hidden` rows after the sense phase
and before `forwardAll`, from a `brain` phase wrapper in the style of `controller-brain.js`:

- **Blindfold:** for `B` ticks the probe writes 0 into the agent's ray block. The body block stays, except in
  `predator-out-of-view`, where the layout's own scent block (the 13 scent and call inputs: body offsets 17 to 29) is also zeroed for the window, so the hunter cannot be tracked by smell or heard.
  `scent-after-sight-loss` leaves them on: scent is what it tests.
- **Amnesia:** each tick the probe zeroes the agent's `hidden` row and the layout's own memory pair (the `MEMORY_A` and
  `MEMORY_B` read-backs: body offsets 31 and 32), so the brain has no state at
  all.

**Offsets come from the layout, never from a literal.** The probe writes no index it typed. Every row it overwrites (the
ray block, the scent block, the memory pair, and for the group-hunt probe the kin channel, the heard hunt call and the
hunt scent) is found through `inputOffsets(config)`, the offset table `js/sim/brain-layout.js` exports and natural-selection.md T10
builds beside `brainLayout`. Where the layout pools the rays, the probe overwrites the raw `inputs` row before
`ray-pool.js` runs, so the pooled row is rebuilt from the overwritten rays. Each probe runs on the layout and on a config with another `rayCount`, and the zeroed indices must equal the
table's. A check fails the build on a numeric offset in probe code (T10b).

A genome's `probe.memory_gain.<scenario>` is its score intact minus its score under amnesia, in the scenario's units.
A genome that wins both ways is reacting, not remembering. The reference points are the scripted controllers
(`../../js/evo/scripted.js`): memoryless ones must score a gain of 0, and a hand-written controller that stores its
target in `MEMORY_A` must score a clearly positive gain. A probe that cannot tell those apart is broken.

| Scenario                 | Staging                                                                                                                                                            | Score                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `food-then-blind`        | One food item 400 px away at a random bearing is in view for 20 ticks, then the agent is blindfolded for 60; the food stays                                        | `probe.food_reach`: share of trials where the agent eats the food within 300 ticks of the blindfold ending  |
| `predator-out-of-view`   | A scripted `hunter` closes on the agent from 500 px; after the agent has fled 20 ticks its rays, scent and call inputs are zeroed for 60; the hunter keeps hunting | `probe.flee_survival`: share of trials where the agent is alive 300 ticks after the blindfold ends          |
| `scent-after-sight-loss` | A scripted prey (`fleer`) runs through the agent's view and out of it; the agent has a `canHunt` specialisation; scent inputs are the defaults (`scent-inputs.js`) | `probe.scent_follow`: share of trials where the agent bites the prey within 600 ticks of losing sight of it |

Each genome runs 32 trials per scenario (bearing and start drawn from the probe's own seeded stream) per control. The
score of a set of genomes is the mean over the genomes. The probe builds its world from the champion's `layout` and
config, so it runs genomes of either layout. Genomes come from champion files (`validateChampion`,
`../../js/evo/league.js`) and from the top genomes of an eval run. `scripts/memory-probe.mjs`
(`npm run probe:memory -- --champions <dir> --scenarios food-then-blind,...`) prints the three scores per control.

A scenario's two readings, intact and amnesia, are read through this table:

| Intact | Amnesia | Reading                                              |
| ------ | ------- | ---------------------------------------------------- |
| good   | good    | Solvable from the current senses; no memory is shown |
| better | worse   | Internal state contributes                           |
| poor   | poor    | Not evolved, or too hard for this brain              |
| good   | poor    | Strong evidence for memory                           |

`scent-after-sight-loss` success can be use of the current scent inputs, not memory; it is read through this table and
counts as memory only when amnesia (which zeroes the layout's memory pair and `hidden`, not scent) lowers it.

**Horizon.** A 60-tick blindfold is 1 second. `food-then-blind` also runs with a 600-tick blindfold (10 seconds), reported
as `probe.food_reach@600`; the intact-minus-amnesia gain there is read with the 60-tick one. The 60-tick probes judge that horizon only. Seasonal migration and territory
last far longer than every `leakMin` arm holds a value (0.005 is a half-life of about 140 ticks), so the long horizon is
judged by `eval.migration_index` and `eval.winter_pop_ratio`, not by the probes. If the probes pass and those two stay
flat, the bottleneck is the horizon, not the hidden size.

### Group-hunt probe

`probe.group_coordination` (T10a) asks whether hunters that sense each other kill more than hunters that cannot. The
arena is the same empty arena; the prey is a scripted `fleer` of the size a lone hunter cannot kill in one bite; the
hunters are three copies of one `canHunt` genome staged as siblings (a shared nonzero parent id), so the kin ray
channel fires between them. 32 trials per control from the probe's seeded stream, same starts in both.

- **Primary control:** three clones that sense each other against three that cannot. In the blind trio the probe zeroes
  the ally channels each tick before the brain runs: on every ray whose hit is kin, the proximity and the kin class
  channel (`CH_KIN`, ray channel 5 of `RAY_CHANNELS`); the heard hunt call (loudness, ahead, side: scent offsets 10 to 12);
  and the hunt scent (here, left antenna, right antenna: scent offsets 4 to 6). Calls between them are still sent and
  cost the same; nobody hears them. `probe.group_coordination` is kills per trio within 600 ticks with the senses
  intact minus the blind trio's, and the ratio is reported beside it.
- **Secondary:** kills per hunter of the trio over kills of a solo hunter of the same genome on the same starts,
  `probe.group_gain`. A `watch` reading, not a gate.
- **A ratio above 1 is not coordination on its own.** Three hunters meet the prey more often than one, so
  `probe.group_gain` above 1 follows from the arithmetic of more bodies. Only the intact-minus-blind difference reads
  the allies: a genome with a gain above 1 and a coordination of 0 hunts alone, three times.

## Phases

### The big bang (overrides Phases 1 to 4)

The user folded this plan into the natural-selection big bang (2026-10-30): every brain change re-pins the goldens,
re-records the bench and re-runs the survival screen, so building them after that branch merges would pay for all three
twice. The brain ships with the world on the same branch and PR, and the experiments become tuning screens on the new
world. The task rows below still say what each change is; this section overrides how and when they are delivered.

- **No flags.** As in [natural-selection.md](natural-selection.md): a behaviour change replaces the old code outright.
  A numeric value stays a config key, since those are the tuning knobs; it defaults to the big-bang value. A boolean with
  one chosen value is not a key: its other path is not built.
- **The big-bang brain.** Each value is the hypothesis's own reading of the evidence in the code, not a measurement:

  `eval.hebb_drift_clamped_share` is high.
- **Built on the big-bang branch after stage 6a**, one agent per chunk, one commit per task, the pre-commit hook per
  commit: (B1) the instruments: T1a and the samplers and diagnostics T3 to T8, with `leakMin` and the mutation keys (T1
