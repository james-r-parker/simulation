# Brain capacity and memory

**Status:** Proposed - Phase 1 first: the instruments, the keys the experiments sweep and the memory probes; the live brain changes only at a phase's decision step, when a measured winner becomes the default.
**Validated:** 8036aba (2026-10-28)
**Priority:** 4 - measurement before redesign: a brain experiment judged by `fitnessV1` measures the wrong thing, so it queues after fitness-and-selection.md Phase 4
**Depends on:** [fitness-and-selection.md](fitness-and-selection.md) (Phase 4), [evolution-evals.md](evolution-evals.md), [world-balance.md](world-balance.md) (Phase 3, built)

Every blob thinks with one Elman recurrent network of 32 leaky hidden units. How much of that network evolution uses, and whether the mutation operator and the input code let it be used, is unmeasured. This doc measures first -
mutation drift, input sparsity, memory, leak rates, plasticity - and changes the brain only where the measurements show
a gain. The purpose is to find the best option for this world and adopt it: config keys and a layout version are only
the mechanism for comparing options, each experiment phase ends by making its winner the live default and removing
the losing options, and nothing is left built but switched off.

The project goal is worlds that are interesting to watch. The brain is the ceiling on what a blob can do, so the
read-out is behaviour, not weights:

- **Individual:** deliberate hunting and foraging, evasion, remembering where food was.
- **Social:** coordinated hunting, flocking, calling and answering, group defence.
- **Long-term:** migration, territory, seasonal adaptation.
- **Surprise:** behaviours the metrics were not written for.

Scope: the mutation operator and initialisation of the brain genome, the input representation, brain size, the leak
floor, Hebbian learning, the memory read-back, and the metrics and probes that tell them apart. Out of scope: new
architectures (GRU, LSTM, attention), new sensors, new outputs, the world rules and the fitness function. Phase 4 ends
with a verdict on whether a new architecture is worth a doc of its own; it builds none.

The ordering constraint with [evolution-rework.md](evolution-rework.md): its Phase 3 trainer bakes the genome layout
into champions, so Phase 4 of this doc lands before that trainer is built.

## Config keys

Each key is a no-op at its default while the experiments run, so Phase 1 replays bit-for-bit; the keys are the way
the arms differ. At each phase's decision step the winning value becomes the default (and the `FEATURES_ON` value), and
every losing option, its key and its code path are removed or retired, so no option stays built and switched off. The
new keys are added to
`FEATURE_RULES` (`../../js/sim/config-rules.js`), `FEATURES_OFF` and `FEATURES_ON` (`../../scripts/lib/features-on.mjs`).
`brainHidden` already has its rule in `config-validate.js`; `hebbianRate` is already in `FEATURE_RULES`.

| Key              | Type, bounds                 | Default    | Meaning                                                                                                                                                                                                                              |
| ---------------- | ---------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `brainHidden`    | int 1 to 128 (exists)        | 32         | Hidden units. The sweep arms are 16, 24, 32, 48 and 64                                                                                                                                                                               |
| `hebbianRate`    | num (exists)                 | 0.0001     | 0 skips `hebbianStep`. The sweep arms are 0, 0.00003, 0.0001, 0.0003 and 0.001                                                                                                                                                       |
| `leakMin`        | num, above 0, below 1        | 0.05       | Replaces the `LEAK_MIN` constant in the leak-rate fill. The sweep arms are 0.05, 0.02, 0.01 and 0.005                                                                                                                                |
| `hebbianDecay`   | num, 0 to 1                  | 0.01       | Replaces the `HEBB_DECAY` constant. Swept in `E56` at 0.003, 0.01 and 0.03 on the best `hebbianRate` when `eval.hebb_drift_clamped_share` is high; otherwise 0.01 is recorded as the value and the key is removed                    |
| `memoryReadback` | bool                         | true       | False writes 0 to body inputs 33 and 34 and leaves `leakEnabled` alone. `FEATURES_OFF` holds `true`; T39 removes the key when `true` wins                                                                                            |

| `leakGeneStart`  | num, minus 4 to 4            | 3          | Replaces `LEAK_GENE_START` in `randomWeights` and `baseline-v5`. The arms are 3, 1, 0 (`a` 0.525) and -1                                                                                                                             |
| `brainLayout`    | enum `elman-v1`, `pooled-v2` | `elman-v1` | The brain layout version (Phase 3). `pooled-v2` pools the rays into ego-frame summaries                                                                                                                                              |

(none is committed; `../../evals/league.json` is empty).

### Layout `pooled-v2`

A second layout selected by `brainLayout` while `E53` compares it with `elman-v1`. At the Phase 3 decision one layout
remains: if `pooled-v2` wins it becomes the only layout and `elman-v1` and the `brainLayout` key are removed; if not,
`pooled-v2` and its code are removed.

- **Pooled inputs.** For each of eight channels (food, can-bite-me, can-bite-it, other, kin, wall, obstacle, smoke) the
  brain reads a proximity-weighted x and y in the agent's own frame (ray angle cosine and sine), 16 values, then the 35
  body inputs: 51 inputs instead of 179. `js/sim/ray-pool.js` writes them into a `pooled` row per slot in the brain
  phase. The `inputs` row keeps the raw rays, so the observer, the life counters and the renderer read what they read now.
- **Skip** (`brainSkip`). A `wSkip` block from the 16 pooled values to the outputs (160 floats), added to the output sums before `tanh`,
  so reflexes (food ahead to thrust, threat to turn away, prey in reach to bite) need no hidden unit.
- **No `SPLIT` genes** (`splitGenes` false, either layout). The `SPLIT` output column keeps its slot in the 11-wide
  output row (indices unchanged) and has no weight, bias or Hebbian update; it reads 0.
- **Genome length** with the skip and without `SPLIT` genes. `wIn` 51 x H, `wRec` H x H, `bHidden` H, `wOut` H x 10,
  `bOut` 10, `wSkip` 160, trait genes 4, leak genes H: 2,262 floats at 24 hidden and 3,214 at 32, against 7,183 for
  `elman-v1` at 32.
- `brainLayout(config)` returns the offsets of whichever layout the config names; the genome, champion and archive
  `layout` field carries the layout name, and `assertGenomeFits` and `validateChampion` reject a mismatch naming it.

## Metrics

All are computed in `js/evo/` from the observer and the world, reported by `computeMetrics`, and accepted by
`validateReport` when present. They are observational: nothing in `js/sim/` reads them. The checkpoint-sampled agents
are the existing `sampleSlots` result in `../../js/evo/observer-checkpoint.js`; the new samplers read it and make no
draw of their own, so `observer.rng` draws and `eval.diversity` are unchanged. Each metric is `watch` in
`DIRECTIONS` (`../../js/evo/compare.js`) until `E48`'s `eval:power` figures say which have a direction worth
enforcing. A `null` is `none(reason)` (`../../js/evo/metrics-stats.js`).

Cost: the per-tick work is the memory-output statistics (every 4 ticks) and the input-activity sample (every 16 ticks);
everything else runs at the checkpoint on its sampled agents or at death. Buffers are sized at observer creation and the
hot path allocates nothing. The budget is 0.05 ms per tick at 500 agents on top of the observer budget in
fitness-and-selection.md (0.25 ms).

| --------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |

## Memory probes

The metrics show what the population does. A probe shows what one brain can do, in a staged world with a known answer.
`js/evo/memory-probe.js` (pure: no files, no clock) builds each scenario from a seed, runs a genome through it on a
headless world, and returns a score. The arena follows `../../test/sim/helpers/predator-arena.js`: an empty world with
no floor and no immigrants.

Two controls separate memory from reflex. Both overwrite the agent's `inputs` and `hidden` rows after the sense phase
and before `forwardAll`, from a `brain` phase wrapper in the style of `controller-brain.js`:

- **Blindfold:** for `B` ticks the probe writes 0 into the agent's ray block (not the body block).
- **Amnesia:** each tick the probe zeroes the agent's `hidden` row and body inputs 33 and 34, so the brain has no state at all.

A genome's `probe.memory_gain.<scenario>` is its score intact minus its score under amnesia, in the scenario's units.
A genome that wins both ways is reacting, not remembering. The reference points are the scripted controllers
(`../../js/evo/scripted.js`): memoryless ones must score a gain of 0, and a hand-written controller that stores its
target in `MEMORY_A` must score a clearly positive gain. A probe that cannot tell those apart is broken.

| Scenario                 | Staging                                                                                                                                                            | Score                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `food-then-blind`        | One food item 400 px away at a random bearing is in view for 20 ticks, then the agent is blindfolded for 60; the food stays                                        | `probe.food_reach`: share of trials where the agent eats the food within 300 ticks of the blindfold ending  |
| `predator-out-of-view`   | A scripted `hunter` closes on the agent from 500 px; after the agent has fled 20 ticks it is blindfolded for 60; the hunter keeps hunting                          | `probe.flee_survival`: share of trials where the agent is alive 300 ticks after the blindfold ends          |
| `scent-after-sight-loss` | A scripted prey (`fleer`) runs through the agent's view and out of it; the agent has a `canHunt` specialisation; scent inputs are the defaults (`scent-inputs.js`) | `probe.scent_follow`: share of trials where the agent bites the prey within 600 ticks of losing sight of it |

Each genome runs 32 trials per scenario (bearing and start drawn from the probe's own seeded stream) per control. The
score of a set of genomes is the mean over the genomes. The probe builds its world from the champion's `layout` and
config, so it runs genomes of either layout. Genomes come from champion files (`validateChampion`,
`../../js/evo/league.js`) and from the top genomes of an eval run. `scripts/memory-probe.mjs`
(`npm run probe:memory -- --champions <dir> --scenarios food-then-blind,...`) prints the three scores per control.

**Screen scorecard** (in order): (1) no collapse: population above `minAgents` and below `maxAgents` on 4 of 4 seeds,
`eval.born_share` at least 0.5, at least 5 lineages; (2) `eval.deliberate_food_share`, `eval.skill_trend` and
`eval.p90_fitness.*` against the `base` arm; (3) `eval.births_per_1k` and `eval.lineages_alive` not down more than 15%;

**Speed of improvement** is read from `eval.deliberate_food_trend` and `eval.skill_trend` (windowed over the run) and
from the per-window values in the report, not from the final value alone: a net that ends higher but climbs more
slowly is reported as both.

**Predictions** recorded before the runs. From the multiply-accumulate counts: the brain phase at 500 agents costs about
0.5, 1.1, 1.8 and 2.5 ms for 16, 32, 48 and 64 hidden units (`bench.step_ms@500` about 1.8, 2.4, 3.0 and 3.8 ms). A
longer genome is harder to search, so the first window of a 64-unit arm is predicted slower than the 32-unit arm's.
