# Pack worker

**Status:** In progress - Phase 1 built (cross-origin isolation and the shared snapshot ring); Phase 2 (the agents packed and rigged in a worker) is next.
**Validated:** 370eaae5 (2026-11-18)
**Priority:** 2 - it closes the crisp renderer's last unmet budget (`browser.draw_cpu_p95_ms`, crisp-renderer.md T24) and changes no sim behaviour, so it builds beside the eval lanes
**Depends on:** [crisp-renderer.md](crisp-renderer.md)

The page is cross-origin isolated, the sim worker writes snapshots into a shared ring, and a second worker, the pack worker, blends the agents and fills their instance rows on shared memory. The main thread draws the newest finished pack, one display frame behind the worker. Nothing in the sim, the evolution code or a saved format changes.

## Snapshot ring

`js/worker/snapshot-ring.js` (new, pure) lays out one `SharedArrayBuffer`: an `Int32Array` header and `RING_SLOTS` (6) snapshot slots of `layout.bytes` each. `writeSnapshot` writes into a slot exactly as it writes into a pooled buffer today.

| Header word    | Holds                                                                                                                                                       |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PUBLISHED`    | The sequence number of the newest published slot                                                                                                            |
| `SLOT_SEQ[k]`  | The sequence number slot `k` holds, 0 while it is being written                                                                                             |
| `SLOT_TICK[k]` | The tick slot `k` holds                                                                                                                                     |
| `HELD[r]`      | The oldest sequence number reader `r` may still read (0 the main thread, 1 the pack worker); `RELEASED` (the largest `Int32`) when the reader reads nothing |

| Function                             | Does                                                                                                                                    |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| `ringBytes(slotBytes)`               | The buffer size for the header and `RING_SLOTS` slots                                                                                   |
| `createRingViews(memory, slotBytes)` | The header view and, per slot, `u32` and `f32` views, made once                                                                         |
| `claimSlot(ring)`                    | A slot whose sequence is below every `HELD[r]`; -1 when none is, so every slot at or after a reader's hold is never overwritten         |
| `publishSlot(ring, slot, tick)`      | Stores the next sequence number into `SLOT_SEQ[slot]`, `SLOT_TICK[slot]` and `PUBLISHED` with `Atomics.store`                           |
| `holdFrom(ring, reader, seq)`        | Stores `HELD[reader]`; `seq` `RELEASED` releases the reader                                                                             |
| `slotOfSeq(ring, seq)`               | The slot holding `seq`, -1 when it is gone                                                                                              |
| `releaseAll(ring)`                   | Stores `RELEASED` for every reader (`READER.MAIN` 0, `READER.PACK` 1); a new ring is released, then held for the main thread from seq 1 |

- The sim host (`emitSnapshot` in `js/worker/host-output.js`) claims a slot, writes it and publishes it. With every slot held it logs `SnapshotSkipped` and keeps the effects in its log for the next snapshot, as it does with an empty pool today.
- The `snapshot` message carries `{epoch, seq, slot, tick}` and no buffer. The `ready` message carries a new ring (`SharedArrayBuffer`) and its slot size for every world.
- `onSnapshot` in `js/app/worker-client.js` points `client.latest` at the slot's views, sets `snapshot.seq`, and holds from `client.prev.seq`. A `slotOfSeq` of -1 logs `SnapshotLost` and drops the message.
- The snapshot entry of `POOLS`, `host.snapshotPool` and the snapshot `returnBuffer` path in `sim-host.js` are deleted. The field buffers keep their pool and `returnBuffer`.
- `.dependency-cruiser.cjs` lets `js/app/` import `js/worker/snapshot-ring.js` beside `js/worker/protocol.js`.

> Note: Slot views are reused once a slot is overwritten. A layer that keeps work between frames for one snapshot (the food layer's repack) compares `snapshot.seq`, never object identity. `frame.prevSnapshot` is a held slot and stays valid for the frame.

## Pack worker

`js/app/pack/pack-worker.js` (new) is a module worker that imports only `js/app/pack/`, `js/app/interpolate.js`, `js/app/pursuit.js`, `js/worker/snapshot-ring.js` and the pure packing modules of `js/app/renderer/` (`agents-pack.js`, `agent-rig.js`, `dying-pack.js` and what they import). It never imports `three` or touches the DOM. After `packInit` it takes no messages: everything it reads per frame is shared memory.

### Frame slots

`js/app/pack/frame-slots.js` (new, pure) lays out one `SharedArrayBuffer`: a request block and `FRAME_SLOTS` (3) output slots.

| Part           | Holds                                                                                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Request block  | `REQ_SEQ`, `STOP`, then the frame to pack: `prevSeq`, `latestSeq`, `alpha`, `tick`, `nowMs`, `zoom`, the lens bits, the palette index and the family slot ids (`FAMILY_SLOTS` lineage ids) |
| Slot header    | `SEQ` (the request it answers, 0 while written), `COUNT` (agents), and each spec bucket's row count                                                                                        |
| Slot agents    | The `Interpolated` lanes `x` to `state` over shared memory; `previous` stays worker-only scratch                                                                                           |
| Slot instances | Per spec bucket, the interleaved instance rows in `createInstances` order and stride                                                                                                       |

| Function                         | Does                                                                                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `frameSlotBytes(info)`           | The buffer size for `info.maxAgents` and `info.specs`, every lane at an 8-byte aligned offset                                               |
| `createFrameSlots(memory, info)` | The request view and, per slot, an `Interpolated` over the slot's lanes and the bucket row views, made once                                 |
| `writeRequest(slots, request)`   | Writes the request, bumps `REQ_SEQ` with `Atomics.store`, then `Atomics.notify`                                                             |
| `claimFrameSlot(slots)`          | The slot that is neither the newest published one nor the one the main thread reads                                                         |
| `publishFrame(slots, slot, seq)` | Stores `COUNT` and `SEQ`, then the published slot index, with `Atomics.store`                                                               |
| `takeFrame(slots)`               | The newest published slot's `Interpolated`, with `count` set from `COUNT`, marked as read until the next `takeFrame`; null before the first |

`createInterpolated` in `js/app/interpolate.js` takes an optional lane allocator, so the same blend (`interpolateInto`) writes into a slot's `Interpolated`.

### The frame

1. The main thread's frame callback (`frame` in `createFrameLoop`, `js/app/frame-loop.js`) runs `stepPlayhead` on a clock shifted one frame ahead (`nowMs` plus the callback's measured `interval`, the same shift for every call, so arrival times and the pause check stay on one clock) and writes the request.
2. The pack worker loops on `Atomics.wait` on `REQ_SEQ`, exits when `STOP` is set, and per request: holds the ring from `prevSeq` (`holdFrom(ring, 1, prevSeq)`), checks both slots with `slotOfSeq`, blends them, runs `findPursuits` on its own blend for the fleeing marks, then `packAgents`, `packDying` and `rigBucket` per bucket, interleaves each bucket's rows into the slot (`interleaveRows`, the copy loop of `uploadInstances` split out of `js/app/renderer/instances.js`), checks `SLOT_SEQ` of both snapshot slots again, and publishes. A slot gone at either check skips the request. It then releases the ring (`RELEASED`).
3. The same callback calls `takeFrame`. Its `Interpolated` is `loop.agents` and `frame.agents` for every main-thread reader: `moveCamera` and `findAgent`, picking (`agentAt`), the effects player (`trackDying`, `playEffects`, `playEdges`, `playBumps`), and the chase, vision, trail and refuge layers. Each agent mesh copies its bucket's rows into its own non-shared `data` (`TypedArray.prototype.set`), sets its instance count and marks the rows for upload.
4. When no new slot is published, the main thread draws the previous slot again and counts a late frame.

### State

| State                               | Owner                            | Where                                                                                                                                                                                                                                                      |
| ----------------------------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dents, body tweens, dying bodies    | Main thread writes, worker reads | One `SharedArrayBuffer` per world; `createDents`, `createBodyTweens` and `createDying` take an optional allocator; the dying pool's `frame` and `next` move into an `Int32Array` header, and its `seen` and `pose` lane arrays get one allocated lane each |
| Fleeing marks (`store.fleeing`)     | Worker                           | Its own `findPursuits` on the agents it blends, so the marks index the same blend `packTween` reads                                                                                                                                                        |
| Jaw openness (`store.jaw`)          | Worker                           | Worker memory; `easeJaw` integrates the gap between the requests the worker packs, not the main thread's frame time                                                                                                                                        |
| Family colour slots                 | Main thread writes               | The request block's family slot ids and palette index, written each frame                                                                                                                                                                                  |
| Playhead, camera, selection, lenses | Main thread                      | Copied into each request                                                                                                                                                                                                                                   |

The effects player on the main thread runs on the drawn slot, one pack behind the worker. A bite dents, and a death starts its clip, one display frame later than today. A read that races a write (for example `beginDeath` setting a body playing before its start time) shows a dying body one frame early or at its last pose, or a live body and its dying body together, for one frame. Every index the packing reads from a raced value is bounds-checked, so a race never crashes.

### Lifecycle

- `js/app/pack/pack-client.js` (new) starts the worker from `main.js` with `packInit` for each world: `info`, `layout` (flags and state bits), the ring, the frame slots, the effect stores and `causeNames`.
- A new world or a page hide sets `STOP`, terminates the worker and releases its hold (`holdFrom(ring, 1, RELEASED)`); the next world starts a new one.
- `packError` (`message`, `stack`) from the worker logs `PackWorkerFailed`; the client releases the hold, restarts the worker with backoff (as `restartDelay` in `js/app/supervisor.js` does for the sim worker) and logs `PackWorkerRestarted`.
- `js/app/pack/pack-protocol.js` (new) validates `packInit`, `packReady` and `packError`, as `validateMessage` does for the sim worker.
