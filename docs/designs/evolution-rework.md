# Evolution rework

**Status:** In progress - Phases 1 and 2 are built and judged: the genome, mutation, crossover, `fitnessV1`, `natural-v1`, the MAP-Elites archive and the live policy `map-elites-v1q`. Phase 3, the trainer, is built after `predator-prey.md`, the renderer and the world gate in Phase 3.
**Validated:** 23eaea3 (2026-10-17)
**Priority:** 6 - its Phase 3, the trainer, bakes the world into champions, so it waits for the world gate below: predator-prey.md, the renderer and world-balance.md
**Depends on:** [headless-sim-core.md](headless-sim-core.md), [evolution-evals.md](evolution-evals.md)

`js/evo/` decides which brains get born. The headless sim core runs bodies and brains; evolution supplies the
policy that writes new brains, scores agents at death, keeps an archive of diverse elites and feeds immigrants from
it.

- A genome is versioned and layout-checked. A genome that does not fit the running layout is rejected with an error,
  never randomised.
- Fitness is counted in ticks and built from events: energy gained, offspring and capped survival, plus one capped
  term per specialisation that pays only after eating.
- A MAP-Elites archive per specialisation keeps the best-tested genome for each kind of behaviour and re-tests both
  elites and challengers.
- The live policy keeps natural births. The archive seeds the initial agents and every immigrant, so archived
  behaviours keep re-entering the world as new lineages.
- It replaces the legacy defects recorded in [legacy-audit.md](legacy-audit.md) under NN-5, NN-9, FIT-1 to FIT-8 and SEL-1 to SEL-5.

## Genome

| Field             | Holds                                                                 |
| ----------------- | --------------------------------------------------------------------- |
| `version`         | `1`                                                                   |
| `id`, `lineageId` | The agent's `genomeId` and `lineageId`                                |
| `parents`         | `[parentA, parentB]`, `[0, 0]` for a random genome                    |
| `specialisation`  | One of the five specialisation names                                  |
| `layout`          | `inputCount`, `brainHidden`, `outputCount` from `brainLayout(config)` |
| `sigma`           | The agent's own mutation step size                                    |
| `weights`         | `Float32Array` of the layout's `weightCount`                          |

`assertGenomeFits(genome, layout)` throws naming the field, the genome's value and the layout's. The archive copies a
genome out of the slot's `weights` row in `onDeath`, before the core frees the slot, into its own preallocated rows;
a genome entering the world is checked, then copied into the slot's row.

## Mutation and crossover

- **Step size.** A child's `sigma` is the parent mean times `detExp(tau x N(0, 1))` with `tau = 1 / sqrt(weightCount)`
  (single step size), clamped to `0.002..0.5`. Random genomes start at `0.05`. Splits mutate `sigma` the same way.
- **Weights.** Each weight gains `sigma x N(0, 1)` and is clamped to `-4..4`. Every child is mutated.
- **Crossover.** For `cause` `mate`, each hidden neuron's block (its row of `wIn` and `wRec`, its `bHidden` entry and
  its column of `wOut`) comes from the mother or the father with probability 0.5; `bOut` comes from the mother. The
  parent mean `sigma` uses `fatherSigma`. For `split`, the child copies the parent.
- **Random genomes.** Weights into hidden units draw `N(0, 1 / sqrt(inputCount + brainHidden))`, weights into
  outputs `N(0, 1 / sqrt(brainHidden))` (standard deviations); biases start at 0.

All draws come from the stream the core passes: `brain-init` for `initBrain`, `mutation` for `childBrain`.

### Mutation v2 (Phase 3)

`map-elites-v1m` (and the trainer, when it runs that policy) replaces the absolute step with a per-block relative
one, keeps weights from drifting and starts random brains quiet. The built policies keep the rules above.

| Part                | Rule                                                                                                                                                                                                                                                                                                                              |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Relative step       | `mutateWeightsRelative(row, sigmaRel, layout, rng)` adds `sigmaRel x blockInitSd(layout, block) x N(0, 1)`, clamped to `-4..4`. `blockInitSd` is the random-init sd of the block: `1 / sqrt(inputCount + brainHidden)` (about 0.069) for `wIn` and `wRec`, `1 / sqrt(brainHidden)` (about 0.177) for `wOut`, `bHidden` and `bOut` |
| `sigma` gene        | Holds `sigmaRel`: `SIGMA_REL_START` 0.15 (a step of about 0.010 in `wIn` and `wRec`, 0.027 in `wOut` and the biases); `mutateSigma` is unchanged, with `tau` 1 / sqrt(weightCount) and the clamp `0.002..0.5`                                                                                                                     |
| Weight decay        | `decayWeights(row, WEIGHT_DECAY)` multiplies every weight by `WEIGHT_DECAY` (0.999) before each mutation step                                                                                                                                                                                                                     |
| Quiet output biases | `randomWeights(row, layout, rng, { quiet: true })` sets `bOut` to `SPRINT`, `ALARM`, `HUNT`, `BITE` -1, `SMOKE` -2, `THRUST` +0.3, `TURN` and `MATE` 0 (`OUTPUT_INDEX`); it draws nothing for biases, so the draw order is unchanged                                                                                              |
| Archive files       | `encodeArchive` records `mutation` (`abs` or `rel`); `--resume` and `decodeArchive` reject a file whose `mutation` differs from the policy's, because `sigma` means a different thing in each                                                                                                                                     |
| Heritability        | `eval.heritability_food` (watch): the slope of a regression of an offspring's lifetime food energy per 1000 ticks on its parents' mean, over agents born after burn-in whose parent also completed a life; the evals observer's death log gains the parent genome ids                                                             |

No world rule changes, so `rulesHash` and the golden hashes are untouched.

## Life counters

`life-counters.js` adds, per slot, beside the evals observer, updated in the policy's `afterStep`:

| Counter            | Source                                                                                                                                      |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `cells300`         | Distinct 300 px cells entered (48 x 27 bitset), sampled every 10 ticks                                                                      |
| `kinBitesAbsorbed` | Energy lost to bites (`bittenTimer` reset this tick) while a kin agent is within 300 px, found by scanning alive agents only on those ticks |
| `speedMean`        | The motion grid's speed mean (`speedSum / samples`, clamped to 1)                                                                           |
| `crowdingMean`     | Every 100 ticks, from `inputs` after `step`: the highest ray proximity whose class is an agent, averaged                                    |

## Archive

One 10 x 10 grid per specialisation. Descriptor x is `speedMean`, y is `crowdingMean`, each binned over 0..1. Each
cell holds an **elite** and a **challenger**: a genome row, its `sigma`, and Welford statistics of its fitnesses.

- **Uncertainty.** A genome's lower bound is `mean - 1.96 x sd / sqrt(n)`, where `sd` is its own once `n >= 2` and
  otherwise `mean x cv`. `cv` is the median of `sd / mean` over the archive's genomes with `n >= 2`, and `0.3` until
  five such genomes exist.
- **Offer.** In `onDeath` the policy copies the dying agent's row and `sigma` into a preallocated offer buffer; in
  `onEvent` for its `AgentDied`, an agent that reached `maturityTicks` is scored and offered to its specialisation's cell. A clone
  (`isClone`) adds its fitness to the genome its `archiveRef` and `refId` name, wherever in that cell it now sits. Otherwise an empty cell takes it as the elite;
  a fitness at or above the elite's mean takes the challenger place when the challenger is empty or has `n = 1` and a
  lower fitness.
- **Replace.** A challenger with `n >= 2` whose lower bound exceeds the elite's replaces it, keeping its statistics;
  the challenger place empties.
- **Clones.** `nextClone` cycles over cells in order and returns the first challenger with `n < 3`, otherwise the
  elite with the smallest `n`.
- **Select.** `selectParent` takes a cell tournament size: the occupied cell whose elite has the best mean among that
  many uniform cell draws (one draw is a uniform cell), then the best mean of 3 elites drawn with replacement from that
  cell and its occupied neighbours. `map-elites-v1` draws one cell; `map-elites-v1q` draws `QUALITY_CELL_DRAWS` (4).
- **Seed.** `seedArchive(archive, champion)` places a champion as the elite of its `cell` with its fitness unknown.
  Today it adds a sample of 0 to the elite's statistics, so a seeded champion keeps a false 0 in its mean and sd after
  real clone evaluations; Phase 3 fixes this (below).
- **Statistics cap (Phase 3).** `createArchive` takes `nCap` (default 0, off). With `nCap` above 0 each Welford update
  counts at most `nCap` samples, so the mean follows the latest samples with weight `1 / nCap` and an elite scored
  against old opponents lets challengers in. The trainer sets `nCap` to `TRAINER_N_CAP` (8); the live policy leaves it off.
- Rows are preallocated: 5 x 100 x 2 genome rows of `weightCount` floats.

## Live policy

`createMapElitesV1({ config, log, observer })` is `natural-v1` plus the archive (`map-elites-seed.js` for the initial
agents and immigrants, `map-elites-offer.js` for scoring deaths, `natural-birth.js` shared with `natural-v1`). It
scores a death from the evals observer's death log, so eval, replay and bench all drive it through
`scripts/lib/feed-policy.mjs`; without an observer it never offers:

- **Initial agents and immigrants** (`initBrain`): while the archive has fewer than 10 occupied cells, random. After
  that: 0.5 a mutated child of `selectParent`, 0.3 an unmutated clone from `nextClone` (`isClone` set, `archiveRef`
  recorded), 0.2 random.
- **Specialisation** (`initSpec`): the specialisation with the fewest alive agents, ties to the lowest index.
- **Births** follow `natural-v1`; a child of a clone is not a clone.
- `immigrationInterval` (600 ticks) brings one immigrant every 10 s at 60 ticks per second, so the archive reaches
  the world whether or not the population floor fires.
- `ImmigrantSeeded` (debug: spec, source `archive`, `clone` or `random`, archiveRef) records each choice.
- `map-elites-v1q` is `map-elites-v1` with the four-draw cell tournament. `LIVE_POLICY` in `js/evo/policies/index.js` is
  `map-elites-v1q`.

## Trainer (Phase 3)

`npm run train -- --generations <g> [--episodes <e>] [--workers <n>] [--resume <archive.json>] --out <dir>`
(`scripts/train.mjs`):

- Episode `k` of generation `g` runs on `evals/train-seeds.json` entry `(g x e + k) mod 256` (256 seeds disjoint
  from `evals/seeds.json`), with the default config and `initialAgents` 100, for `EPISODE_TICKS` (60000) ticks. Its
  initial agents and immigrants come from a frozen copy of the archive. The trainer starts from random brains; no
  scripted controller seeds the archive (user, 2026-10-17).
- **Offers.** An agent is offered when it dies and, at the episode's last tick, when it is still alive. Only agents
  born after tick `OFFER_AFTER_TICK` (10000) that reached `maturityTicks` are offered, so the longest-lived genomes are
  scored too. The alive agents are scored with `fitnessV1`'s rule for alive agents and offered in slot order after the
  last death.
- **Statistics.** The archive runs with `nCap` `TRAINER_N_CAP` (8), and a seeded champion's statistics start empty.
- Episodes run on the shared `scripts/lib/worker-pool.mjs` from [evolution-evals.md](evolution-evals.md) (Using every core),
  with its default worker count. `--episodes` defaults to 32, a fixed number so the archive never depends on the
  machine; 32 episodes keep all 32 threads busy for a whole generation. The pool returns episodes in index order,
  so `--workers 1` and `--workers 32` produce byte-identical archives.
- `train.mjs` prints the CPU use for each generation. Each episode returns its offers in death order, each tagged with its `archiveRef` and
  `isClone`; `mergeEpisode` applies them offer by offer in episode-index order.
- A failed episode stops the run with exit 1 and `TrainEpisodeFailed`.
- `--resume` checks the archive's `layout` and `rulesHash` against the config.
- After each generation it writes `<dir>/archive-<g>.json` and logs `TrainGeneration`.
- `npm run train:export -- --archive <file> --out public/champions/v1/` writes one champion file per specialisation
  (the elite with the highest lower bound, with its `cell`) in the [evolution-evals.md](evolution-evals.md) format, and `index.json`
  listing them.
- `createChampionsV1` mutates a champion of the immigrant's specialisation for each immigrant.

### Learning curve

Headless training is cheap (about 7000 ticks a second across 32 workers), so a run is sized from its learning curve,
not guessed.

- `--checkpoint-every <n>` (default 10 generations): at each checkpoint the trainer picks the champions as
  `train:export` would, without writing them, and plays `champions-v1` built from them on 4 seeds of
  `evals/seeds.json` (entries 33 to 36, the tuning-night screen seeds 29 to 32 stay out of it) for 50000 ticks each, on the same pool.
- `curvePoint` makes one row per checkpoint, appended to `<dir>/curve.jsonl`: `generation`, `trainTicks` (cumulative
  episode ticks), `wallSeconds`, the archive's `coverage` and `qdScore`, each specialisation's best lower bound, and
  the checkpoint eval's `eval.food_energy_per_1k`, `eval.births_per_1k`, `eval.fed_median_lifespan` and, when the
  report carries them, `eval.catch_rate` and `eval.escape_rate` from [predator-prey.md](predator-prey.md).
- Checkpoints only read the archive: a run writes byte-identical archives with or without them.
- `npm run train:curve -- <dir>` prints the curve as a table and the plateau generation from `findPlateau`: the first
  checkpoint after which `qdScore` and `eval.food_energy_per_1k` each rise by less than 5% (the `eval:compare`
  minimum effect) over the next 3 checkpoints, or "no plateau yet".
- A checkpoint row is 4 seeds, too few for a verdict; the curve sizes runs, and `eval:compare` at 16 seeds still
  judges the champions (T17).

## Phases

### Phase 1 - Genome, mutation, crossover and fitness (built)

**Targets:** none - its Targets (eval.food_energy_per_1k, eval.fed_median_lifespan) are judged with Phase 2

`genome.js`, `mutation.js`, `crossover.js`, `life-counters.js`, `fitness.js` and `natural-v1`, with the anti-exploit
suite passing for `fitnessV1` with no expected failures. Experiment `E1` (`natural-v1` against `baseline-v5`) was
`worse` on `eval.food_energy_per_1k` and `better` on `eval.median_lifespan`: on the default world neither arm breeds
(about 0.005 births per 1000 agent-ticks, the population on the `minAgents` floor), so nothing is selected and a
genome or fitness change cannot show. Selection first happens in Phase 2, where the archive seeds floor agents and
immigrants, so the user moved Phase 1's Targets there (2026-10-16).

### Phase 2 - MAP-Elites archive and live policy (built)

**Targets:** eval.food_energy_per_1k, eval.diversity, eval.lineage_turnover

`welford.js`, `archive.js`, `archive-codec.js`, `map-elites-v1` and `map-elites-v1q`. Done when the live policy against
`baseline-v5` is `better` on `eval.food_energy_per_1k` (`E10`) and `map-elites-v1` against `natural-v1` is `better` on
`eval.diversity` and `eval.lineage_turnover` (`E8`), under the rules of `reachable-births.md`. `eval.fed_median_lifespan`
(the lifespan of agents that ate at least one item) is recorded with its verdict and does not block: active foragers
live shorter than `baseline-v5`'s agents, which barely move, and the survival weights that close the gap also pay
agents that never eat (the FIT-8 exploits). `eval.lineages_alive` is recorded with no verdict, since families mean
fewer lineages. `eval.qd_score` and `eval.coverage` are recorded with no verdict.

Recorded: `E3` and `E4` on the old rules, where almost nothing bred; `E7` (`map-elites-v1`: food +84%, fed lifespan
-26%) and `E8` (diversity +33%, turnover +105%); `E9` (`map-elites-v1q` with survival capped at food eaten: food +103%,
fed lifespan -28%); `E10` (the live policy and fitness).

### Phase 3 - Headless trainer and champions

**Targets:** eval.food_energy_per_1k, eval.food_energy_per_1k@20k, eval.heritability_food

Phase 3 is built after [predator-prey.md](predator-prey.md) is `Implemented`: champions are trained on its brain layout.
[world-balance.md](world-balance.md) Phase 2 (honest senses) lands before predator-prey Phase 3, so the layout and the
ray classes the trainer bakes in are the honest ones.

The trainer bakes the world's rules into its champions, so a later rules change means retraining and resetting the
league. Phase 3 therefore also waits for the world gate (user, 2026-10-16): [worker-and-renderer.md](worker-and-renderer.md)
is built so runs can be watched, and tuning nights continue until the live policy's world shows all of these:

- Self-sustaining: `eval.born_share` above 0.7 and `eval.floor_episodes` a small fraction of today's.
- A real arms race, as a time-shift assay (`scripts/time-shift.mjs`, `npm run time-shift`, new). A run of the live
  policy saves its living genomes at ticks 50000, 100000, 150000 and 200000. Predators of time `t_i` play prey of time
  `t_j` for every pair, in `evals/predator-world.json` (new) on 16 seeds, through the league runner. The gate passes when
  the catch rate rises with predator time at fixed prey time, falls with prey time at fixed predator time, and both slopes'
  BCa intervals exclude 0.
- Families: `eval.kin_within_call_radius` (mean living kin within `callRadius` of a caller at alarm time, defined in
  [world-balance.md](world-balance.md)) at or above 1, and `eval.alarm_response` above 0 with an interval excluding 0.
- Selection agrees with fitness: `eval.fitness_lrs_corr` above 0 with an interval excluding 0, and
  `eval.archive_lineage_share` read first (both from [world-balance.md](world-balance.md) Phase 1). A share below 0.2
  means the archive barely reaches the world and a fitness change cannot move what is watched.
- A smooth climb: on the skill ladder (random brains, a sloppy forager, `foodSeeker`, a forager that flees, no floor),
  each rung outlives and out-breeds the rung below.
- Skill beats chance: the deliberate-behaviour metrics (D1 to D7 in [world-balance.md](world-balance.md)) show deliberate
  foraging, hunting, evasion and signalling clearly ahead of their chance-or-waste controllers.
- The user has watched it in the renderer and signed it off.

The phase also fixes the trainer's transfer problems and the mutation climb:

- `seedArchive` stops adding a false 0 sample (a bug, fixed with a failing test first).
- Episodes last 60000 ticks and offer living agents at the end; the archive caps a genome's sample count at 8.
- Mutation v2 and quiet output biases run as the arm `map-elites-v1m` against `map-elites-v1q` (16 seeds, prediction:
  `eval.floor_episodes` better, `eval.heritability_food` higher). `LIVE_POLICY` moves to it only when the verdict is
  `better` on `eval.floor_episodes` with no target `worse`.
- `eval.food_energy_per_1k@20k` is `eval.food_energy_per_1k` over ticks 0 to 20000, before burn-in, so a champion-seeded
  start is measured as well as the steady state (new; computed from the observer's checkpoints).
- The checkpoint seeds are entries 33 to 36 of `evals/seeds.json`, which grows by those four entries.

`trainer.js`, `npm run train`, `npm run train:export`, `public/champions/v1/` and `champions-v1`. Done when
`champions-v1` is `better` than the live policy (`LIVE_POLICY` at that time, not `baseline-v5`) on
`eval.food_energy_per_1k` and `eval.food_energy_per_1k@20k`; each champion is admitted to the league in
specialisation order with `--admit`, and its `eval.champion_elo` is recorded.
