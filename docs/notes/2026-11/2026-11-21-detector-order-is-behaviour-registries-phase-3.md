### 2026-11-21 - Detector order is behaviour (registries Phase 3)

Moving the scene detectors behind one loop showed that the order they run in is part of the report: the sprint detector reads `approach.phase`, which the approach detector's per-tick tracking rewrites, so running it before the approach moved `eval.chase_sprint_lift` (a 2-seed 20000-tick eval caught it on the first detector). `DETECTORS` therefore keeps the old per-tick order (approach, stillness, sprint, kinematics), and a death still runs every handler before any slot reset, because the stillness and approach scenes read each other's per-slot state at the moment of death. A birth resets the slot first. `metrics-stats.js` imports the metric registry, which imports `entry.js`, so `SOURCE_BY_MODULE` cannot be generated from the detectors (an import cycle); a contract test keeps the two equal instead.
