# Flora T33: 4K rendering and default-world clip

The matched perf runs used the same build (`7674558`), seed 1, quality 0, 500 starting agents, 3840x2160 viewport and 60-second measurement on Windows Chrome 156. Chrome reported an NVIDIA GeForce RTX 4090 using D3D11. Its monitor refresh was 58.1 Hz, below the perf script's 120 Hz guard, so both runs used `--allow-low-refresh`.

Control command (all look items except Flora):

```sh
flock /tmp/claude-1000/cpu.lock npm run perf:browser -- --cdp=http://127.0.0.1:9222 --look=rocks,aurora,terrain,motion,threads,decay,finish --seconds=60 --viewport=3840x2160 --agents=500 --allow-low-refresh --out=evals/screens/results/flora/T33-before.json
```

Full-look treatment:

```sh
flock /tmp/claude-1000/cpu.lock npm run perf:browser -- --cdp=http://127.0.0.1:9222 --look=all --seconds=60 --viewport=3840x2160 --agents=500 --allow-low-refresh --out=evals/screens/results/flora/T33-after.json
```

The standard collector discards frame intervals above 250 ms, leaving no accepted frame sample for either run. The supplemental raw RAF observer retained every interval and found 225 of 229 above that cutoff in each arm. In this single pair, raw p95 differed by 0.2 ms; this does not establish statistical equivalence. It shows no observed Flora look regression while exposing severe absolute frame stalls in both arms. The 4K browser budget is not claimed as passed; carry the absolute performance shortfall to balancing. The small GPU p95 difference is not evidence of an improvement.

The app's `Shift+P` recorder captured the full-look default world at seed 1, quality 0 and a 3840x2160 viewport. The 15-second WebM is [T33-default-world.webm](T33-default-world.webm), 1,147,658 bytes; 368 agents remained at stop.
